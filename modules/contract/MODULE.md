# M0 问题合同

由主作者在进入问题或用途发生实质变化时读取，供后续模块共用。它确定本次回答什么，不预定结论，也不是用户必须先填写的问卷。

## 用途与输入

适用于 R2—R6；R1 只需识别所问概念与语境，R7 另须全书覆盖。输入为用户原问、已有文件、任务用途、现实约束和已有授权。已明确的内容直接采用；只对会实质改变问题的歧义澄清，同时推进独立工作。

## 步骤与判断

1. 保留原问，分出对象、待解释差异、目标、时间窗、观察位置与预期成果。用户希望成立的结论单列为期待，不当作事实。根据 §1.5、§4.17 形成问题边界。
2. 按 §1.1、§12.1 区分解释、推演、条件前瞻、有限选择。概念问答走 R1，理论评价走 R7，规则与计划起草走 R6。混合请求拆成有依赖的路由，不让后续选择改变前面的事实判断。
3. 明确资料截止与输入模式：公开取材，或只用给定材料。确定材料保护、协作可见范围和成果形式；已有授权不重复索取，也不由工具可用推定授权。
4. 对未来请求按 §12.2 检查目标能否到期判定、对象范围能否冻结、期限能否与机制相接。只问“如果……会怎样”或无法确定可判目标时走 R3；条件齐备才交 M6 登记为 R4。不能偷偷补一个会改变原问的期限。
5. 声明本次阅读模式，按[阅读规则](../../references/full-source-study.md)读取。默认 `full`；只有明确授权的阅读实验才能用 `layered`。R7、跨全书一致性、体系迁移、未知路由均全读。

## 交接物

问题合同交 M1、M2 与最终成文使用。简单任务可在对话中保留；跨作者或跨轮次时，可将下列实质内容保存为任务目录的 `contract.md`，不创建空模板。

```markdown
# 问题合同
原问：
对象、观察位置与边界：
输出类型与路由：
目标与期限；可判定规则（仅 R4 必需）：
用途与完整成果：
资料截止与输入模式：
已知约束、价值前提与已有授权：
阅读模式与原文版本：
会改变问题的未决：
```

## 停止与降级

目标不可判定时降为 R3，不以“将会”发布。关键对象或用途无法确定时暂停依赖它的判断；独立可答部分继续。阅读实验不覆盖某条新依赖时补读完整小节；依赖范围不能确定时改为全读。

## 教学例，不作经验证据

输入：“项目未来会好起来吗？”已有材料只有流程说明，没有“好”的指标或期限。先分开“当前为什么阻塞”与“改变流程后可能怎样”，得到 R2 接 R3；输出是阻塞机制与条件路径。若后来明确“未来两周内完成 20 个已定义验收项”，才补入判定来源、冻结窗口与基线，转 R4。不能把最初的模糊问题登记为日后任意解释的成功。

## 常见误用

把用户期待写成事实；把路线当结论；用“缺信息”回避所有可做工作；把方案推荐当执行许可；为每个短问强制创建文件。
