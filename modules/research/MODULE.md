# 研究与解释边界报告

按需组合 M0—M10 的任务入口，不是第九条判断路由。用户要求研究一项内容、把成果写充分，或想知道目前哪些地方解释不了、有争议、有问题时使用；只说“研究一下”“调查一下”也按这里交付。先按所求判断选 R1—R8，再组织实际研究。短概念问答和有确定答案的计算直接回答，不展开成研究项目。材料只有用户的几句话时，能做的研究主要是把问题分开、列出能区分各种解释的查证，完整稿也随之简短；篇幅跟着已有材料和实际做过的工作走，不为写满各部分而扩写。

## 交付什么

一份手写的完整稿，两项内容都在里面：

- **主体**：让读者沿问题、材料、方法、结果、竞争解释和反方读到判断。各部分先有局部判断，再说明彼此是支持、制约还是独立。
- **解释边界与问题**：末章，集中写出目前解释不了、判断受限或有实质争议的地方。用户要求问题单独流转时才另存一份文件。

开头的中心判断同时交代三件事：结论是什么；其中哪些由材料直接算得出或由条文直接规定，哪些只是现有材料倾向支持；足以改变中心判断的缺口有哪几处。后文相应结论处再展开这些缺口，末章不能是唯一写着重大限制的地方。

理解本身可以是终点。用户没有问怎么办时不硬给方案；研究指向一项尚未作出的决定时，说明研究对这项决定意味着什么，把决定留给有权限的一方。

## 实际工作

1. **明确争点与范围。** 从需要解释的差异出发，把一个大问题里的不同问题分开，例如数字为什么变、事情实际怎样、他人的说法能否成立。问题较大时自主选出有意义的部分展开，不把规划交还用户；不先猜答案再找支持它的材料。
2. **交代材料的来路。** 承担关键判断的每份材料说明怎么产生、能支持什么、不能支持什么。抽取办法不明的样本和摘录只证明有这种情况，不推比例；由结论的受益方整理的材料照用，同时写明这一点。
3. **核对词义与口径。** 同一个词指不同东西、定义中途改过、分子分母或计数单位不同时，先在正文里分开再比较。按需调用[领域映射](../domain-mapping/MODULE.md)；有对得上的领域卡先读卡。
4. **完成可开展的研究。** 实际读取、比较、计算或细读，按[研究工作](../../references/research-work.md)处理来源形成、反向材料、时间和识别条件。能用同一口径重算的就重算；只能在假设下推算的，写出假设并给范围，不挑一个值当估计。缺失不补零；未知机制不取消独立成立的描述，相关变化也不自行成为因果效果。
5. **形成论证。** 每个主要判断说明材料怎样支持、方法能回答到哪里、最强的替代解释是什么、什么观察能把它们分开。保留可并存的机制和真实的规范分歧。评价他人的说法时，先分开数字是否属实与推论是否成立，再给出材料能支持的替代表述；转述按原文的强度和已经写明的限定保留，批评时写明所用的标准出自对方自己的前提、评价者另行采用的前提，还是对方主张所涉的事实材料（§2.7.1）。
6. **从实际工作中提取问题。** 研究中遇到的断点才进末章：算不出来的量、分不开的解释、对不上的材料、没照章执行的迹象、定不下来的规范选择。不为填满类别制造问题；确实命中理论承诺时，也不一律归到材料不足。
7. **核对两项内容一致。** 末章每一项都能在前文找到它限制的那条结论，前文那条结论处也写着这项限制。

## 问题怎样写

按对中心判断的影响从大到小排列。每一项写明：

- **影响哪些结论，不影响哪些结论。** 后者写出它们另有什么依据，读者才知道哪些话现在就能用。
- **已经做了什么。** 实际做过的计算、比较或推断；没做的不算。
- **为什么仍未解决。** 缺的是哪份记录、哪个比较、哪项规定，或哪两种解释在现有观察下分不开。
- **它把判断改成了什么。** 例如从“质量下降”降为“没有改善的证据”。
- **下一步。** 能把问题分开的那份材料、那种方法或那项决定，最好写到拿到什么结果会支持哪一种解释。

问题少时用几段话写清即可。条目只写对读者有用的：不逐类声明“本次未发现”，不拿“材料只是节选”这类泛泛之词凑数。没有发现命中理论承诺的问题时，在章末用一句话交代本次实际评估的范围，不据此宣布理论无误。已回复、已归档、已讨论都不等于已解决。

问题的身份帮助想清楚下一步该做什么，允许一项多类；它是工程分工，不是新的理论分类。正文用读者看得懂的说法，不必逐项贴标签。

| 身份 | 要定位的内容 | 后续工作 |
| --- | --- | --- |
| 材料不足 | 缺什么记录、影响哪个范围 | 取得相称材料，保留独立结论 |
| 方法与识别限度 | 哪些解释仍兼容同一观察 | 改比较或测量，或保留并列解释 |
| 领域方法需求 | 哪个专业问题超出当前方法 | 由相应专业方法接管 |
| 映射或概念不足 | 丢了哪个区别、混了哪种义项 | 修订对应、原词或表达 |
| 理论问题候选 | 实际原命题、前提、范围与反例命中位置 | 走 R7；修订构想另保留候选身份 |
| 规范分歧 | 冲突的价值、权利、目标或责任理由 | 展开论证，把选择留给有权限的一方 |
| Skill 实现缺口 | 已有要求与实际漏做、错做的环节 | 修复流程、工具或成果 |

## 语言与出处

正文用领域自己的话说清谁、做了什么、在什么条件下、得到什么结果。原文小节号、理论编号和规则卡名不进正文，集中列在末尾的方法附注，写明用到了原文的哪些区别；领域事实和专业方法的出处跟在所支持的内容旁边。理论提供的区别、领域来源提供的事实与本次提出的新连接分别交代，不用一句“理论支持”覆盖全文。被读的著作、领域方法或细读本来就能得到的区分，不记为本框架的贡献；判断只是变了而没有变好的，也不算（§4.17.4）。公开材料、计算和推导，不输出私有内部思维链。

## 新材料与更正

来源、数据、前提或词义被更正时，按[持续对话](../../references/continuation.md)中“来源或数据更正”的顺序办：先分清更正改了什么、没改什么、没交代什么，重算受影响的量，顺依赖检查用到它们的解释和判断，把更正自己带来的新问题写进末章，最后告诉用户哪些结论变了、哪些没变。数值变了而结论不变的照实写明；独立成立的结论保留。修订稿另存，旧稿留作回查。目标重开按 §2.14 保留原问题与旧结果。

## 长期研究与完成

单次研究不建台账。多轮、多人或主张很多的长期研究需要记录时，用已有的[材料目录](../../references/evidence-work.md)、[主张台账](../../references/claim-ledger.md)和[任务状态](../../references/task-state.md)；它们是工作材料，成稿始终是手写的正文，不由记录排版生成。未安排的后台研究不许诺。

完成标准是当前可做的研究已实际完成、正文充分、问题定位准确且两项内容一致，不以文件数量或条目数量判断。更简单的领域方法或细读已足以解决、本框架的术语不改变判断时，按 §1.9 改用领域方法，本框架至多保留来源与边界的核对。需要专门作品时选[成果模式](../../references/output-modes.md)；用户要把一个领域做深、做成研究室水平的理论研究时，按其中的[领域专论](../../references/output-modes/domain-study.md)组织：先立领域自己的问题和文献，再逐条映射并用公认的案例检验。有限模型计算见[有限工具](../../references/finite-tools.md)，具体操作见[能力操作](../../references/capability-operations.md)。写法可参照[合成示例](../../assets/examples/research-answer.md)；实际任务的结论由自己的材料决定。
