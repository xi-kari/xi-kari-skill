# 领域映射与方法适配

按需连接 M1 的领域材料、M2 的对象与关系、M4 的变换和 M9 的成文。用户要求把理论用于一个具体领域、核对词义或使输出保持专业细节时调用；研究和设计过程中出现新歧义也可局部进入。它不增加判断路由，不把一切专业知识统一翻译成结构标签。

## 先保留领域的问题

说明具体领域、任务、材料范围、地区或机构以及规则或技术版本。优先取得用户原件、适用规则、公开专业文献或技术接口。一个机构的“完成”可能指提交，另一个可能指批准或实际服务；没有语境时保留多义，不用词面命中替用户选义。

首次任务只建立真正需要的局部对应。可复用包先核适用范围与版本，再补本题材料。现成[领域包](../../references/domains/README.md)覆盖有限任务，不能代替实际岗位、课程或系统资料。

## 必要的八类对应

| 内容 | 实际工作与输出 |
| --- | --- |
| 词义与对象 | 原词、当地定义、来源、同名异义、实体与记录边界 |
| 动作与关系 | 谁对谁做什么、方向、条件、过程和结果；“收到”与“改变处理”分别表述 |
| 角色与责任 | 联络、决定、执行、实际承接和承担代价者；权限另据适用材料 |
| 任务与终点 | 解释、比较或完成什么；提交、批准、落实与目标后果各用自己的证据 |
| 字段、单位与时间 | 观察单位、分母、存量/流量、事件与记录时点、窗口和缺失 |
| 证据与专业方法 | 什么材料支持哪项判断；统计、史料、规则解释或技术验证保留自身条件 |
| 不对应与例外 | 部分、多对多、类比、不对应、不适用和未知分开；保留必要原词 |
| 输出与修订 | 用对应关系写成具体段落、表格或方案；列版本、反例和改义影响 |

不要求每题填满八张表。相关区别用最少且充分的记录保留；没有资料时不编造定义、单位、角色或事实。

## 对应身份与证据

区分定义对应、角色/对象实例化、部分对应、观察接口、类比候选、不对应、不适用和未知。这些是工程组织名称，不能当作原文新定义。一个领域词可以对应多个理论问题，也可以没有理论对应。

分别回答三件事：在此任务中语义是否对齐；现实关系是否有相称证据；若申请某项正式强主张，是否满足该合同。语义相近不能补现实证据，正式资格未申请也不取消独立成立的专业知识。自然技术对象不强套人格、意愿、同意或责任。

申请 §3.4.1 的正式表述转义时，另明确源语境、目标任务、转换规则及版本、保持、允许改变、折叠、遗漏、新增、歧义误差、父记录与回返路径、目标侧复核、有效期和撤回条件。没有目标侧独立复核时标为待检验转义。普通适配包的字段完整不自动满足这份合同。

## 映射检验与成文

先从领域材料建立关系，再检验理论中哪些区别有用。用同义换说法、同词换场景、关键证据改变、缺失记录和反例检查：结论是否仍依赖正确条件，已知与未知是否保留。换一种措辞应保持同一用法，换了实际证据则允许改变判断。

需要检查有限状态表示时可调用[有限工具](../../references/finite-tools.md)，但有限划分不证明自然语言最优。按 §5.10.2 分开表示丢失与规则使用错误；任务相关区别仍在而处置错误时，不能把全部失败归为转译损失。往返文字相似也不是语义保持的充分证明。

输出必须包含一段真正使用对应关系的领域说明：具体主体、动作、条件、结果和依据。不得只列“输入、结构、输出、反馈”而删掉专业细节。主体可用领域原词，理论连接放方法说明。单独调用时交付必要对应、来源、未对齐项及具体成果；接研究时直接供主报告使用，不另复制抽象报告。

## 更新与工具

新来源改变词义、技术版本、分母或权限后，核对受影响条目、结果与下游判断。保留仍适用的对应及未映射部分，不全表机械替换。工具的 `impact` 只定位依赖，实际更正仍由作者读材料并修订完整成果。

多义查询、关系记录、引用和变更影响可用 `domain_mapping.py`，格式见[领域映射格式](../../references/domain-mapping-format.md)。单次小问题可直接自然语言完成，不强制建立长期库。包不适用时改用相称专业方法，不能为了复用而删掉现实区别。
