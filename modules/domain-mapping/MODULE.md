# 领域映射与方法适配

按需连接 M1 的领域材料、M2 的对象与关系、M4 的变换和 M9 的成文。用户要求把理论用于一个具体领域、核对词义和口径，或要输出保留专业细节时调用；研究和设计中途出现新歧义也可局部进入。它不增加判断路由，不把专业知识统一翻译成结构标签。

## 先保留领域的问题

说明具体领域、任务、材料范围、地区或机构以及规则或技术版本。优先用用户原件、适用规则、公开专业文献或技术接口。一个机构的“完成”可能指提交，另一个可能指批准或实际服务；没有语境时保留多义，不用词面命中替用户选义。

用户或宿主指明了领域库时，先看其中有没有范围对得上的[领域卡](../../references/domains/README.md)。卡片记的是以前核实过的本地用法，不是本题证据：范围对得上才用，与本题材料冲突时以本题材料为准并写明冲突。没有卡片就按本题材料建立局部对应，只建真正影响判断的那几条，不等行业词典建成。

## 要分开的八类内容

| 内容 | 实际工作与输出 |
| --- | --- |
| 词义与对象 | 原词、当地定义、来源、同名异义、实体与记录边界 |
| 动作与关系 | 谁对谁做什么、方向、条件、过程和结果；“收到”与“改变处理”分别表述 |
| 角色与责任 | 联络、决定、执行、实际承接和承担代价者；权限另据适用材料 |
| 任务与终点 | 解释、比较或完成什么；提交、批准、落实与目标后果各用自己的证据 |
| 字段、单位与时间 | 观察单位、分母、存量与流量、事件与记录时点、窗口和缺失 |
| 证据与专业方法 | 什么材料支持哪项判断；统计、史料、规则解释或技术验证保留自身条件 |
| 不对应与例外 | 部分、多对多、类比、不对应、不适用和未知分开；保留必要原词 |
| 输出与修订 | 用对应关系写成具体段落、表格或方案；列版本、反例和改义影响 |

不要求每题填满八类。相关区别用最少且充分的文字保留；没有资料时不编造定义、单位、角色或事实。三处最容易漏：

- **同一个词是不是同一个意思。** 定义改过、不同文件各有规定、说话人各有所指时，逐处写明所指；有本地规定确认同义的，前后用法保持一致。
- **几句话说的是不是同一个对象。** 被资助的项目、被观察的流程和被表决的提案可能不是一件事，核对后才放进同一个论证。
- **字段到底记了什么。** “已读”是有人读过还是打开即标记，检测时刻不是发生时刻，受理时间不能顶替完成时间；缺失不记零，也不当作没发生。

## 语义、事实与正式资格分开

对应关系有不同身份：定义对应、角色或对象实例化、部分对应、观察接口、类比候选、不对应、不适用和未知。这些是工程组织名称，不是原文新定义。一个领域词可以对应多个理论问题，也可以没有理论对应。

分别回答三件事：在此任务中语义是否对齐；现实关系是否有相称证据；若申请某项正式强主张，是否满足该合同。语义相近不能补现实证据，正式资格未申请也不取消独立成立的专业知识：一个字段的定义可以成立，而它记录的事情是否构成传导、反馈或学习仍需另取证。自然和技术对象不强套人格、意愿、同意或责任。

申请 §3.4.1 的正式表述转义时，另明确源语境、目标任务、转换规则及版本、保持、允许改变、折叠、遗漏、新增、歧义误差、父记录与回返路径、目标侧复核、有效期和撤回条件。没有目标侧独立复核时标为待检验转义。普通对应写得再齐全，也不自动满足这份合同。

## 检验与成文

先从领域材料建立关系，再看理论中哪些区别有用。用同义换说法、同词换场景、关键证据改变、缺失记录和反例检查：换一种措辞应保持同一用法，换了实际证据才允许改变判断。按 §5.10.2 分开表示丢失与规则使用错误：一个说法把任务必须区分的情况合并了，是表示不足；区别还在而处置错了，是规则或执行的问题。往返文字相似不是语义保持的充分证明。需要检查有限状态表示时可调用[有限工具](../../references/finite-tools.md)，有限划分不证明自然语言最优。

输出必须有一段真正使用对应关系的领域说明：具体主体、动作、条件、结果和依据，不能只列“输入、结构、输出、反馈”而删掉专业细节。主体用领域原词，理论连接放在方法附注。两个以上的说法纠缠在一起时，在正文给一张本题对照表：每个说法在这里指什么、依据哪条规定或哪份材料、现有哪项记录对得上、不能据此推出什么；比率写全分子、分母、口径版本和时期。对照表帮助回查，不代替论证。

单独调用时交付必要对应、来源、未对齐项和这段具体说明；接研究时直接供主体使用，不另写一份抽象报告。新来源改变词义、技术版本、分母或权限后，只修订受影响的对应和依赖它的判断，仍适用的保留，不全表机械替换。

## 与概念重构的分工

核对已有用法、让输出用对词，是本入口。用户要为一个混用的词提出一套新说法并据此改写文本时，用[概念重构](../../references/output-modes/concept-reconstruction.md)：它先按本入口把现有用法分清，再比较几种改法，给出定义与边缘例，写出改写后的文本。

## 把核实过的用法留下来

本题核实了以后还会用到的本地定义、口径、易混点或“不能推出什么”时，交付之后在对话里用一两句提出可以存成或补进领域卡的条目，不写进成果正文。用户同意并指明领域库位置后才写入，写法与修订记录见[领域卡](../../references/domains/README.md)；不同意就不写，也不存入宿主全局记忆。一次性的概念问答不提这件事。卡片不适用时改用相称的专业方法，不为复用而删掉现实区别。
