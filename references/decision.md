# 判断与决策

用户要明确结论、方案取舍、计划、规则或制度草案时，使用本模块。承接用户目标与约束、已有事实和机制解释、可用资源、真实备选方案，以及必要的条件推演或预测。无需等所有事实都查明才开始比较；已知条件能够支持的判断和成果应当完成。

## 从问题走到取舍

### 1. 确定要作的决定及其理由

说明规则、系统或行为试图改变谁的什么处境，以及用户真正要解决的冲突。把事实是否成立、解释是否有力、安排是否正当、行动是否合适分别判断。按第十四部分导言，分析推荐承担论证原则，现实采用另须实质保障，框架内部的“获准”状态另有记录格式；不同格式不能自称同等保护，更不能删去决定谁受保护、承担、决定、停止或纠错的实质要求。规范目标、权利底线和利益取舍来自哪些公开前提，也要说清；不能从“更可能发生”直接推到“更值得选择”。

已有分析指出主导约束时直接承接；尚未解释清楚且会改变方案时，交给[结构与机制分析](analysis.md)解决具体争点。补充解释可以改善范围、代价与实施，即使不改变首选也保留其内容价值。

### 2. 形成真正可以比较的方案

从实际断点提出可行改动，同时考虑维持现状、主动行动、延迟、可逆试探、退出或转移、明确不行动中适用的选项。不为数量凑方案；请求选择时保留真实的不行动基线。维持现状可能需要持续投入，不行动也可能让现状随其他行动者和时钟继续变化，两者不能自动合并。

现有选项都触不到断点时，使用[批判与构想](critique-and-invention.md)生成新的安排。例如改变入口、资源分配、决策权、承接关系或反馈通道；不要把现成二选一误当全部选择空间。

### 3. 比较每项方案怎样改变处境

在同一问题、时间窗和约束下，说明措施通过什么机制触达哪个断点，局部作用怎样接续到目标。后果不清楚时进行[条件推演](dynamics.md)；确实需要判断未来发生可能性时使用[预测](forecasting.md)。机制、硬约束和稳健性已经足以支持选择时，不额外要求概率或正式预测。

分别分析谁获益、谁执行、谁能承接、谁承担成本、谁有决定与停止的权利。按 §14.4.1 和 [M7](../modules/choice/MODULE.md) 列全直接、已知或被指出的低权力与应用必列位置，对其余影响按风险追踪并记录可质疑的识别界线；现状和不行动同样承担识别责任，事后识别者有同等补救。能力不产生义务；总体收益不能掩盖负荷转给低权力位置或后续时期。展开局部与整体、短期与长期、直接结果与跨圈层溢出的差异，辨明纠错、退出、修复和恢复原状是否实际可行。保护不降级不等于每项结果不得有损，保护/结果有争议时先按保护；结果损失另据明示价值、最小伤害与比例性论证。初次同意和当前拒绝、协商、退出条件分查，继续留下不作持续同意；有限责任的承接另行保留。

不可通约的价值与代价保留多维比较，不用一个随意加权的总分消除冲突。对最强反方及具有不同实质作用的重要异议作回应，接受其有效部分并修改方案，或给出有据的维持理由；没有必要机械接受一条错误意见。

### 4. 把资源、依赖和时间接起来

说明实施需要的人员、容量、预算、材料、权限和起效时间。多个动作单独可行，不表示能共享同一份资源同时完成；把共同资源占用、串行依赖和截止连起来安排。下期新增容量不能补回本期已经错过的任务，首个节点完成也不能当成最后受影响者已经获益。任务要求连续工作、休息或准备退出时，另核整段可用时间的长度与可预期性；待命即使少被调用也可能阻断整段，不与已占用钟表时数重复相加。

等待、调查和试探本身也有时间、隐私与资源成本。确实需要补充信息时说明要区分什么、怎样取得，以及何种结果改变做法，不虚构精确的信息价值。实际采用所需的权限按真实情况处理，不让模型建议代替决定主体。

### 5. 作出当前明确选择

证据允许时直接说建议采用、应当修改、不应继续、应当保留或优先完成，再展开理由和范围。分别说清首选为何合适、其他方案为何不足，以及哪些条件会使首选改变。不要以“都有利弊”“因情况而异”结束。

关键事实未知时继续判断可决定的部分。某方案在当前可信相容状态中均可行，可以给稳健选择；不同条件下首选不同，给明示前提的条件方案及区分条件；确实无法合理排序时，指出决定性缺口并交付本轮能够完成的方案与分析。“暂缓”不是所有不确定情形的默认选项，也不能为了显得果断而编造事实、概率或必然结论。

全部可行方案（含暂停和不行动）都有不可逆损失或未满足要求时，按 §14.9.1 和 [M7 的有限判断](../modules/choice/MODULE.md#所有方案都有损失) 继续给出供审议推荐。保留决策规则及提出/采用者、受损者要求、后续减轻与补救责任、改判条件及重评时点；规则有争议则并列其下判断。核查真实约束、被删方案及先前决定能否重开，权限不足向有权限主体提交。不得豁免事项不因全有损失失效；即使独立复核认定无法同时保全，框架仍不以“获准”背书，外部主体只能依自身有效权限承担决定。

### 6. 完成用户需要的文本与安排

把当前判断落成具体改动、实施次序、责任位置、资源、触发与停止条件，以及采用所需的实际程序。草案可使用明确标出的设计性阈值、期限和岗位，区分提议值与现有事实。缺少国家、法域或组织背景时，可以先形成适用假设明确的设计稿，不捏造当前法律；实际法域有效性分析需要适用权威材料。

| 请求 | 交付的判断与成果 |
| --- | --- |
| 为什么、如何理解 | 中心解释、主次机制、竞争解释裁定、仍未知的具体范围和改判证据 |
| 评价某观点、法律或制度 | 总判断、关键成立或不成立处、最强反方回应及具体调整方向 |
| 怎么办、选哪个 | 首选、落选或暂缓项、真实代价、实施顺序、触发与停止条件 |
| 制定法律、章程或规则 | 可审议的完整条款，包含适用范围、权利义务、执行能力、程序、救济、例外、过渡与修订，并解释关键取舍 |
| 制定制度体系 | 总体架构、模块和层级、权限与冲突规则、模块间接口、核心条文及完整覆盖安排，按任务规模持续完成 |
| 制定计划 | 目标、主导约束、资源、依赖、次序、责任安排、实际验收与替代路径，使安排与机制判断相连 |

草案形成与合法生效分别成立，尚未生效不妨碍完成草案。用户要求完整成果时，不用原则清单或一句“建议进一步研究”替代正文。

## 制度与流程草案核对表

起草者和成文者逐项核对下表，适用项落实到具体条款；确实不适用时说明理由。面向组织使用的简明草案，条文正文不超过 12 条，相关事项可合并，解释置于条款之后。按 §14.5 将否决提案、提出替代、修改议程与更换审理或终审者的能力分别落实；有回应不等于规则层可改，高影响或利益冲突且终审不可挑战又无外部独立复核时，不称充分纠错。用户要求更大范围的制度体系时按其规模展开。

| 核对项 | 草案应明确的内容 |
| --- | --- |
| 个案暂停 | 谁申请、谁决定、临时保护、决定期限及恢复条件；紧急情形的临时处理权限 |
| 制度暂停 | 身份泄露、保护失效、授权到期、纠错无法执行等触发条件；决定主体、存量事项承接和恢复程序 |
| 恢复原状与补救 | 错误改判后的决定撤回、记录更正、权益恢复与损失补救；责任人和完成期限 |
| 泄露处置 | 身份或数据泄露后的止损、访问限制、通知受影响者、安全复核及补救安排 |
| 计时与排队 | 从收件开始计时，公开排队时间、办理期限和超期处理；保护身份的同时让当事人查询进度 |
| 相对方回应 | 向被申诉者说明指控与可披露证据，给予回应机会，处理利益冲突并保护双方 |
| 三类代理 | 区分协助表达、代为提交、代为决定；分别说明同意、授权范围和撤回方式 |
| 全流程能力 | 给定处理能力覆盖初审、调查、回应、裁决、复核中的哪些环节；核算共享人员与总容量，未核清处保留待定 |

## 形成判断以后

完成当前取舍及其完整解释即可交付，无需另作自我评分或让其他模块批准结论。已经存在的事实矛盾、计算错误、重要反例与条款冲突属于具体问题，应当解决；没有新的实质问题时，不为再检查一次重复整条流程。

持续对话中，把反驳、补证、偏好和目标改变分别接到具体命题。可以有理由地维持、限缩、修订、撤回或保留未决；用户坚持不自动证明其主张，机械反驳也不表示独立。改变判断时同步真正依赖它的解释、方案和完整成果，未受影响的工作直接保留。
