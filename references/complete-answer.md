# 完整答案与成果

## 完整论证是默认交付

呈现问题的完整分析与可审查论证，使读者能看清：为什么这样理解问题，怎样判断材料，哪些解释成立或被排除，作用如何接续，反方造成什么挑战，什么条件改变结果，最终为何作出这项判断与选择。表达可以充分深入，不能只留下结论和几条理由。

这里的“完整”指与本题有关的实质分析及其理由，不是公开私有内部思维链、逐token推理、自我对话或工具工作日志。用可核查的证据、推导、比较、案例、反例和明确前提支撑文章。

默认呈现所有已经开展的实质分析：事实辨认与材料评价、结构关系、机制比较、竞争和混合解释、案例与反例、适用的多阶路径、局部裁决、方案比较、建设性构想及各自的条件、代价、限制和停止原因。被排除的解释也需要说明为什么被排除；尚未区分的解释保留具体分歧。

不得仅因“没有改变主结论”“不是最强理由”“属于次要分支”“用户可能不想读长文”而删除这些内容。可以重排、去重、合并同义表达，须保留全部实质区别。材料受到隐私或保护限制时保留非敏感的理由与边界，不为完整性公开不应披露的原值。

## 文章怎样展开

先让读者知道中心判断，再依据本题真实关系组织章节。每个主要部分有自己的局部判断，随后展开事实、机制、竞争解释、反例与限定，并说明它怎样承接前后问题。不要照抄XK阶段名作标题，也不要机械填“输入—输出—通过”表格。

资料不是脚注装饰。重要材料要讲清其产生方式、直接支持和不能支持的主张，与其他材料的冲突，以及为什么采用或保留它。真实案例要进入论证，不能在结尾附故事代替比较。

机制不是名词组合。写出具体的人或对象、动作、载体、通道、条件、时钟与变化；不同尺度和圈层之间说明桥接，反例说明会动摇哪项判断。涉及计算、约束和证明时展示足够复算的公式、步骤与前提，而不以“已经验证”替代它们。

反方要强到足以挑战自己的方案；回应必须落在它提出的问题上。允许坚定维持原判断，允许局部修正，也允许部分未决；不能把反思写成一段无关紧要的免责声明。

## 成果类型

| 用户要求 | 必须完成的成果 |
| --- | --- |
| 深入解释 | 完整文章，包含材料评价、关系与机制、竞争解释、案例、局部与总判断及边界 |
| 批评与评论 | 重建被批评论证、明确立场、逐项理由、强反方及回应、可成立部分与具体改法 |
| 决策与计划 | 真实方案比较、明确取舍、成本承担、资源与依赖、实施安排、触发和停止条件 |
| 法律、规则与章程 | 完整可审议条文及制定理由，涵盖权责、程序、资源、证据、例外、救济、监督、过渡、生效和修订 |
| 制度体系 | 共同目标、规则层级、权限分配、模块条文、接口与冲突解决、实施和救济架构；不能用目录冒充完整体系 |
| 新构想与研究 | 新主张或设计、提出依据、机制、替代解释、反例、可行性、检验路径与推进安排 |

法律与制度草案提出设计值不需要假装已有经验成效，也不需要先拥有使其生效的权限。对当前法域或真实专业事实作判断时另取得权威依据；虚构案例和规范设计明确自身身份。

## 篇幅与连续交付

不设置默认字数上限、固定节数或预先设定“几千字足够”。复杂问题需要上万字才能完整展开时充分写出；不以篇幅证明深度，不为了字数添加重复、无关概念或虚构证据。只有用户明确要求简答或限制篇幅时才压缩可见答案；全文学习和必要的实质分析仍须完成。

初次完整交付及用户要求完整合稿时，较长任务以`xi-kari-answer.md`保存完整正文，并在聊天按连续章节交付。文件是完整成果，消息也是读者界面；单次容纳不下时明确已经交付和后续部分，不得用一个摘要或链接宣称完整正文已在聊天全部呈现。遵守宿主实际输出限制，无法继续时如实说明限制及未显示范围，不静默删减。

同一任务的聚焦续问完整回答本轮问题，给足背景、材料与新增论证，不必重发未变化的全文。当前成品已获授权打磨时，将成熟修订合入完整稿，保留全部仍有效的实质内容，并同步受影响的图表与阅读版。探索分支保持其身份；用户要求“只讨论不改稿”时不修改。详见[持续对话与深化](continuation.md)。

第一段结论和视觉总览只承担导航作用，不限制后文展开。读者可以先把握总体，再进入充分论证；不能把关键内容藏进默认不可达的附件、弹层或折叠区。

## 总装

把材料、解释、路径、反方、裁决和构想组织为互相连接的部分：每部分回答一个明确问题，继承共同事实和定义，产生可供后续使用的判断。检查具体矛盾：同一数据是否换了口径、一个条款是否否定另一条、一个方案是否重复占用资源、一条结论是否用未决前提冒充已知。

这类一致性工作以具体问题与修改为内容，不能输出“全覆盖”“已完成全部思考”“质量通过”作为自我认证。最终文章由实际论证承担说服力。
