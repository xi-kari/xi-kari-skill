# 现实使用与反馈

分析、采用和实际效果分别成立。用户请求把方案投入具体用途时，沿已经取得的授权完成能完成的工作；不能以草案尚未生效为由拒绝起草，也不能因工具可用就扩大真实处置权限。

## 按用途形成采用材料

完整论证仍是内容基础，再按用途生成可以直接使用的材料，而非每题制作相同附件。

| 用途 | 可交付的采用材料 |
| --- | --- |
| 法律、章程、内部规则 | 可编辑条文、条文理由、相关规则接口、普通案件示例、过渡及救济安排 |
| 组织与项目调整 | 承担岗位与权限、实际工作顺序、资源排程、交接内容、既有任务如何继续 |
| 研究与新构想 | 可区分问题、资料采集说明、分析文件、试验安排及适用边界 |
| 评论、历史或思想研究 | 完整论证、关键材料定位、相反解释、重要争议和后续研究入口 |
| 软件、流程或配置改变 | 可检查的具体修改、使用说明、现有数据承接及用户指定的运行结果 |

用户需要完整DOCX、PDF或表格时，按[领域与宿主接入](domain-and-host.md)使用实际可用的文档能力。格式转换须保留有实质作用的内容，不用展示稿替代完整正文。

实施安排要处理从现在到目标状态的过渡：谁因改变而失去原有承接、旧承诺怎样履行、新岗位何时真正可用、哪些决定依赖尚未成立的条件。不要把制度名称、岗位成立或通知送达当成能力与效果已经发生。

## 决定怎样观察，而非承诺自动监控

对用户确实要采用的方案，选择与其作用机制相连、且能够取得的观察：直接变化、不同位置的代价、实际承接、效果到达和意外后果。明确资料截止、观察窗口、比较基线与重新考虑的条件。必要的事前判断可以保存原稿，不要求每项建议编概率或制作记录表。

用户没有安排后续跟踪时，交付观察办法与可接续材料，不许诺后台运行。用户要求提醒、持续监测或定时回访时，用宿主实际支持的调度能力；调度是否创建成功和方案是否有效是不同结果。不能用技能文本伪造不存在的常驻能力。

## 现实结果回来以后

先辨材料是谁取得、何时发生、观察了什么、是否改变口径。用户报告是一类有意义的材料，仍保留其来源身份。不要让自信的叙述取代事实，也不要因为没有完整统计就取消已被具体记录的损失。

分别检查可能的改变来源：原事实或表示有误、机制解释失效、环境或目标改变、措施没有按设想实施、执行已发生但缺少后续承接、局部目标达到却带来额外代价。它们可以并存，不能把所有失败归给执行者，也不能用目标单项增长替所有后果结案。

例如，“决定已更正”与资源到账、服务恢复、损失得到补救可能处在不同位置。判断实际到达哪个结果，再修改相应安排。若结果反驳先前判断，保留原判断和真实失败；新稿说明当前结论，制作差异与旧稿放在工作材料，不让正文堆积修订日志。

按[持续对话](continuation.md)把新结果传到实际受影响的解释、条款、资源安排和图表。可以保留方向而改变实现，也可以撤回原建议并提出新的取舍。明确现在能够完成什么，以及哪项判断仍需要现实材料；不生成“已反馈所以正确”的自证。
