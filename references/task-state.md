# 跨轮次任务状态

用于长任务跨轮、跨上下文或换人接手的场合：一个中心问题讨论了多轮，需要记住**哪些已经决定、哪些仍然悬着、哪些被新证据动摇、哪些已经撤回**。

注意它与[主张台账](claim-ledger.md)的分工：主张台账管的是**一项主张靠什么成立**；本文件管的是**这轮讨论走到哪里了**。两者可以同时使用，但不要拿其中一份冒充另一份。

几轮之内能记住的任务不必建立台账。建立它的理由是不让「上次已经排除的解释」在下次讨论中悄悄回来，也不让「还没实施的方案」被当成已经验证过。

## 四种身份必须分开

使用状态工具保存条目时，按以下四种身份区分：

| 身份 | 含义 |
| --- | --- |
| `decided` | 已经作出的决定 |
| `open` | 仍未决的分歧 |
| `revisit` | 受新证据影响、需要重新复核的既有判断 |
| `withdrawn` | 已经撤回的判断 |

`decided` 条目还要声明 `kind`；`kind=fact` 或 `kind=observation` 需要填写来源位置。工具检查来源字段是否存在，不判断来源真伪或内容含义。作者仍按实际材料区分用户报告、观察和计划：用户说「这个办法有效」不自动成为独立实测，尚未实施的方案没有已观察结果。

这条限制的意义在于：长任务最容易发生的失真不是忘记结论，而是把**同意**记成**证实**，把**计划**记成**结果**。

## 命令

工具需要Python 3.10以上，只用标准库。以下PowerShell命令使用`$skillRoot`表示当前`SKILL.md`所在安装目录，`$taskRoot`表示安装外的用户任务目录，可从任意当前目录调用；路径设置见[宿主接入](host-setup.md)。台账放在任务文件旁，不写技能安装目录，也不写宿主全局记忆。

```powershell
python "$skillRoot/scripts/task_state.py" --state "$taskRoot/状态.json" init --task '申诉等待是复核容量造成的吗'
python "$skillRoot/scripts/task_state.py" --state "$taskRoot/状态.json" record --record "$taskRoot/round-2.json"
python "$skillRoot/scripts/task_state.py" --state "$taskRoot/状态.json" list
python "$skillRoot/scripts/task_state.py" --state "$taskRoot/状态.json" brief
python "$skillRoot/scripts/task_state.py" --state "$taskRoot/状态.json" check
```

`init` 建立新台账，已存在即拒绝。`record` 追加一轮并原子提交——每轮记录轮次号、本轮问题、新增材料或条件、已作出的决定、仍未决的分歧、因新证据需要复核的既有判断，以及当前完整稿位置。`list`、`brief`、`check` 都是只读。

`brief` 生成供新接手作者使用的接续摘要：当前中心判断、仍然有效的结论、明面上的未决分歧、下一步真正的实质缺口。换人接手时先读 `brief` 与实际材料，再决定深入哪里——它帮助快速恢复状态，不替代对新材料的阅读和前一位作者的完整学习。

`check` 核对内部一致性与引用可解析性：轮次号是否重复、是否指向不存在的轮次、四种身份是否被混用、`kind=fact` 的条目是否真的给了来源。它检查的是**登记是否自洽**，不判断内容真伪，也不证明任务已经完成。

## 写入与并发

同一台账同时由一位作者负责写入。工具用同目录独占写锁保护最后的重读、比较和原子提交，拒绝重复轮次号、不可识别的台账文件、已经变化的旧内容，以及指向不存在轮次的引用。遇到写锁或版本冲突，重读后重新处理，不静默重放旧台账。异常遗留的写锁须确认没有写入者后再处理，工具不自动清除。

## 接续时怎样用

接续不是重讲一遍已经讲过的话。带着台账回来时先辨明：用户这轮的新输入改变了什么，受影响的最早工作是哪一步，哪些既有判断仍然有效。`revisit` 与 `withdrawn` 的条目要实际处理——前者补齐复核，后者说明撤回理由，不能只在台账里改个状态而正文保持原样。

结论改变时，把影响传到真正依赖它的解释、方案、条款与图表，保留未受影响的有效部分。台账是工作材料，不是正文；最终成果仍完整写出论证，读者不需要看到这些管理字段。
