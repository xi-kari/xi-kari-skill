# governance_procedure@V90-B01212

## 原文层

来源：`V90-P02514`

SEL-GOV 还必须建立 governance_procedure 记录。议程形成检查谁能提出问题、谁能排除方案以及紧急程序何时终止；代表检查授权来源、代表范围、可撤回性和未被代表者；参与检查安全、可达、信息和实际影响能力；少数保护检查多数决定不能取消的权利、局部排除区和暂停条件；利益冲突检查决定者、执行者、评估者与受益者是否重合；执行问责检查责任人能否被复核、停止和更换。

来源：`V90-P02515`

形式参与不等于真实参与。一次公开会议、一个投诉入口或一张多数票，都不能单独证明低权力位置能够安全表达并改变决定。异议必须保留自己的 ID、主张、位置、状态、回应期限和安全提交渠道；少数异议仍为 open、protected_and_pending 或 unresolved_action_paused 时不得进入 authorized，只能缩小方案或暂停，不能把“人数少”写成“影响小”。

来源：`V90-P02516`

这一严格状态规则首先约束框架自身签发的authorized记录以及其高影响使用，不是对所有外部课堂、组织、法律或公共决策设置每人无条件否决权。一般程序中的有理由拒绝可以有参与和尊重价值，却不能因此被登记为已满足本框架更强的应用合同。需要修改强门时，应明确作为规则修订提出，不通过释义删除原条件；合法事实、规范评价和本框架的状态资格继续分开。〔研究14.06、19.02、21.04、25.02〕

## 解释层

允许边界：SEL-GOV 还必须建立 governance_procedure 记录。议程形成检查谁能提出问题、谁能排除方案以及紧急程序何时终止；代表检查授权来源、代表范围、可撤回性和未被代表者；参与检查安全、可达、信息和实际影响能力；少数保护检查多数决定不能取消的权利、局部排除区和暂停条件；利益冲突检查决定者、执行者、评估者与受益者是否重合；执行问责检查责任人能否被复核、停止和更换。

禁止边界：SEL-GOV程序记录含真实异议；框架强状态不外推社会无限否决
