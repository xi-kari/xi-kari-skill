# 按完整成果调用工作流

用户要比较专论、过程史、安排草案、作品阐释、概念方案、理论模型或共同问题书时，从本页选择对应工作流。它们组织现有路由和方法，不是新的底层模块、理论分类或七个必经阶段。先确定所求作品，再实际取得材料、分析和成文；不把选定工作流当作完成任务。

| 用户要得到什么 | 调用 | 主要承接 |
|---|---|---|
| 两套理论究竟冲突在哪里、怎样取舍 | [跨理论对话](output-modes/theory-dialogue.md) | R7；按争点用材料、变换、机制比较和反方 |
| 某种安排如何形成、维持并走到今天 | [机制史与过程重建](output-modes/process-history.md) | R2；条件反事实另接 R3 |
| 可以讨论和试行的完整制度或生活安排 | [制度与生活安排设计](output-modes/arrangement-design.md) | R6；需要推荐时承接 R5 |
| 一段经验、作品或叙事表达了什么 | [经验、意义与作品阐释](output-modes/meaning-interpretation.md) | R2 的解释性任务；按材料选择方法，M9 成文 |
| 一个词被混着用，要一套新说法并改写文本 | [概念重构](output-modes/concept-reconstruction.md) | 先用领域映射分清现有用法，再接 R8；写成用语条文时接 R6。已有词义问答继续 R1 |
| 有范围、关系、推导和检验入口的新模型 | [中层理论构造](output-modes/middle-range-theory.md) | R8；要求体系评价时接 R7 |
| 争点尚未对齐时，可以继续研究或协商的问题 | [共同问题与议程重开](output-modes/problem-reframing.md) | M0 与 R8；方案选择或制度修改草案再接 R5/R6 |

可以直接请求“用机制史工作流研究这些材料”，也可以只说“它怎么走到今天”；依实际所求识别，不要求用户记编号。同一任务需要两种作品时按依赖组合，例如先过程史再设计安排，并复用材料和已成立判断。明确的计算、定义或局部解释继续原路由，不扩大成完整研究。

## 共同工作与交付

1. 阅读责任遵循现行 Skill；同任务接续使用仍可靠的学习，工作流不替代所需原文。以具体任务、材料与用途确定范围，不为填满所有栏目扩大收集。
2. [研究入口](../modules/research/MODULE.md)可调用这些模式完成实际研究并汇总解释范围；模式也可单独使用。长任务交接现行稿、来源与真实未决，短任务直接交付正文，不强制建立多份台账。
3. [领域映射与方法适配](../modules/domain-mapping/MODULE.md)按需提供对象、词义、关系、单位、时钟及专业方法。领域知识保持自身依据；不要求每个普通概念都转写为正式实例。意义阐释可以不用无关的结构建模。
4. 主体作品应有中心判断、实际分析、关键材料、竞争解释或读法、理由与边界。来源表、事件表、比较表和检查项辅助回查，不替代连贯论述。复杂任务的重要分支先形成局部判断，再综合；不能只交提纲或后续计划。
5. 需要限定模型计算时用[有限工具](finite-tools.md)；其他专门操作见[能力操作](capability-operations.md)。工具只承担所声明的计算或记录任务，不验证事实真伪、文本解释、规范正当或实际授权。
6. 未决只限制依赖它的部分。新材料回来时同步相关论证、结论和图表，保留其他成立结果；用户要求行动时才继续到相应选择或执行终点。

## 示例的用途

各工作流链接一个自包含示例，包含明确标为 `synthetic` 的材料、用户请求和完整短作品。它们展示工作怎样从材料走到成果，不是现实案例、用户数据、执行记录或能力成绩。实际任务应由自己的材料决定答案，不能复制示例结论。

本页及各工作流中的检查要点用于核对具体遗漏，不产生学习认证、自评分或运行证书。格式与链接检查只能证明相应工程事实；成果还须检查材料、推理与任务是否吻合。若专业方法已经充分，直接使用该方法；若工作流只增加篇幅和维护负担，就缩减或停用受影响部分。
