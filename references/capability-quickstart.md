# 研究与领域工作的调用方式

以下请求在已启用 Xikari Skill 后按需选用。默认完整理论学习仍适用；同一问题的续问承接已有工作。只想快速得到一个判断时，在请求里写“用十句话”：技能只按[十句话](ten-sentences.md)核对后直接回答，并在开头写明没有读原文。

## 从自然语言开始

| 所需成果 | 可直接使用的请求 | 接入位置 |
| --- | --- | --- |
| 完整研究，并知道哪里还解释不了 | 研究一下这些材料。 | [研究入口](../modules/research/MODULE.md)：末章自动单列解释边界与问题 |
| 领域对应与具体表达 | 这些词在这里各指什么？保留当地定义、数据口径和专业方法，用它们写一段可以直接用的说明。 | [领域映射](../modules/domain-mapping/MODULE.md) |
| 一个混用的词要一套新说法 | 这个词大家各说各的，给一套更准确又能用的说法，并把这段文字按新说法重写。 | [概念重构](output-modes/concept-reconstruction.md) |
| 比较两套理论 | 准确重建双方主张，判断真冲突、异题与互补，给出比较专论及未决争点。 | [成果模式](output-modes.md) |
| 重建形成过程 | 用这些有日期的材料解释形成和转折，分开当时已知与事后取得的资料。 | [成果模式](output-modes.md) |
| 可审议安排 | 在真实人员、资源和时段内给出不同安排与取舍，并写完整约定及过渡。 | [成果模式](output-modes.md) |
| 经验或作品解释 | 细读这份完整材料，解释语境与不同声音，比较读法；理解本身可以是终点。 | [成果模式](output-modes.md) |
| 中层模型或议程 | 构造有边界的模型；或保留旧问题并提出可以继续研究的新问法。 | [成果模式](output-modes.md) |
| 把一个领域做深 | 对这个领域做一项研究：它自己的核心问题和已有答案是什么，理论怎样一条条接上去，用公认的案例检验，哪里领域自己的方法更强。 | [领域专论](output-modes/domain-study.md)，从[领域入口索引](domain-index.md)进入 |
| 材料查得全、每条都能回到原件 | 这个问题请分方向取材，留下原件，告诉我哪些没查到；成稿后再请一位没参与取材的协作者把引用逐条核一遍。 | [取材的组织](collection.md) |
| 更正后的局部修订 | 这份来源已更正，只改真正受影响的部分，告诉我哪些结论变了、哪些没变。 | [持续对话](continuation.md)中“来源或数据更正”的五步 |

研究成稿由作者手写：主体在前，解释边界与问题为末章，重大限制同时出现在开头和相关结论处。写法见[合成示例](../assets/examples/research-answer.md)。

## 让领域里的用法留下来

在一个领域里反复工作时，告诉技能你的领域库放在哪个目录（安装目录之外）。任务开始它先读范围对得上的[领域卡](domains/README.md)，任务结束提出值得存下来的本地定义和口径，你同意后才写入。

```powershell
python "$skillRoot/scripts/domain_cards.py" --library "$taskRoot/领域卡" list
python "$skillRoot/scripts/domain_cards.py" --library "$taskRoot/领域卡" check
```

两个命令都只读。卡片记的是以前核实过的用法，不代替本题的材料；定义对得上，不表示本题的能力、权限、效果或恢复已经发生。

## 需要记录和计算时

单次研究不建台账。只有工作确实需要时才用下面的记录，已有的直接引用，不重复建账。

| 眼前需要 | 用什么 |
| --- | --- |
| 找回多份材料、版本和原文片段 | `evidence` 材料目录 |
| 长期维护独立主张、反方和历史 | `claims` 主张台账 |
| 跨作者或跨轮恢复实际工作 | `task_state` 任务状态 |
| 需要他人继续采集可区分的材料 | `study_design` 研究设计 |
| 状态、动作、时段或关系能够明确列举的计算 | [有限工具](finite-tools.md)的六种模型 |

有限工具的分组、排程和组合搜索只在输入的模型内成立；搜索未完成与已证明无解分开。其余专门操作见[能力操作](capability-operations.md)，只选与任务有关的部分。
