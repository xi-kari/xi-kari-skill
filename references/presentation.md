# 完整成果的呈现设计

## 用完整图景组织内容

先完成可读正文，再根据问题设计表达。可以在写作中同步画图辅助分析，但最终图、表和正文必须共同回答同一问题。总览是进入全文的入口，不能成为缩略答案的替身。

复杂任务可以组织为下列内容分区；按本题关系命名，不必照抄分区名或强制每区一个文件：

| 分区 | 所回答的问题 | 合适载体 |
| --- | --- | --- |
| 问题与中心判断 | 我们到底在判断什么，当前结论是什么 | 清楚的开场、问题地图、全文导航 |
| 材料与案例 | 我们知道什么，为什么信，哪些地方有争议 | 来源附近的引用、案例叙述、证据比较表 |
| 条件与机制 | 事情怎样发生，关系在哪里接通或断开 | 完整散文论证、因果或关系图、条件链 |
| 路径与反方 | 还有哪些可能，什么会反转判断 | 分叉图、时间线、反例与敏感性比较 |
| 裁决与构想 | 应当支持或反对什么，能设计什么新办法 | 完整判断、方案比较、条文和设计说明 |
| 实施与未来 | 谁在什么条件下怎样做，什么信号要求调整 | 资源排程、角色与流程图、检查点与停止条件 |

分区像相互衔接的拼图。材料区不能只堆引用，机制区不能只画箭头，裁决区不能脱离前文重新提出无据结论。保留定义、对象、时间、数值和来源的一致性，解释部分之间如何接续。

## 图表的证据纪律

箭头区分真实支持的因果、条件推演、相关关系与拟议干预。不同线型或文字说明承担区别，不能只靠颜色。图中没有材料支持的边不得因画得漂亮而成为事实。

表格用于同口径比较、事实映射或资源安排；机制和取舍仍用完整段落解释。时间图注明时钟、单位与假设，数量图只用真实或明确标注的示例数据。对复杂关系分图展开，另给全局入口，避免用密集大图形成新的知识壁垒。

## 长文阅读页面

篇幅和内容关系适合时，主动生成完整Markdown的HTML阅读版。保留全部正文、表格、引文、代码、链接与图片说明，提供章节导航、搜索、字号与主题切换、打印布局及原文入口。普通本地阅读无需部署网站或启动服务器。

可使用随包的`python scripts/render_answer.py --help`查看离线生成工具，在技能目录中执行`python scripts/render_answer.py <完整正文路径> --output <阅读版路径.html>`，或使用脚本绝对路径。生成器支持的Markdown语法和图形能力以实际实现为准；不支持的语法保留可见原文与原稿入口，不悄悄丢失。需要其他文档格式、复杂图形或交互模型时，使用宿主实际可用的相应工具，缺少能力时提供完整静态版本。

代码或Mermaid源码不等于图已渲染。不能可靠离线渲染时提供清楚的文字、比较表或实际生成的SVG/图片，并说明源码的身份。真实图像与外部素材须有适当来源，涉及数据的视觉结论仍需正文解释。

## 视觉和可访问性

采用适合长文的阅读宽度、中文行距与字阶；颜色克制，对比清楚。桌面目录可以并列，窄屏改成可收起导航；正文始终完整。表格在窄屏允许横向查看，不能截掉列。

交互有键盘操作和可见焦点，图有替代说明，搜索只定位高亮而不隐藏未命中的正文。静态无脚本环境仍能阅读主体，打印时保留内容并减少装饰。不同主题、字号和布局只改变阅读方式，不改变内容。

呈现质量靠实际内容和可用性判断。生成后查看文件是否可打开、文字是否保留、图表是否真实显示；不以截图、文件大小或“生成成功”替代理论与论证质量。
