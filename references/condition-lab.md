# 条件推演

当几种方案的选择取决于明确数量、资源上限、布尔条件或不同外部情景时，将可计算部分做成用户能够复算和比较的模型。不为了图表而量化一切。价值冲突、史料解释、行为机制以及不能合理赋值的关系，继续由实质论证承担。

工具帮助辨认“在这些假设、条件和计算关系下，哪些约束满足、哪些仍受阻”。它不从理论自动推出比例，不把满足显式约束称为现实有效、最优、合法、公正或具有某种成功概率。

## 从问题建立模型

先把可控制的选择与外部条件分开，并确定单位、数量边界和数据来源。未知保留为未知；研究者提出的数字标为假设，不因已填进表格就成为事实。候选方案不能靠偷偷改变外部事实获得优势，外部情景也不能暗中替用户更换方案。

将关系写成具体公式与约束。例如“总投入不超过40工时”和“每个案件都有无冲突且时间可用的复核者”是不同约束；两名复核者不能直接换算成前者，也不能证明后者成立。需要排程或逐案资格资料时，指出缺少的材料，不把总量表解释成完整现实模拟。

每项模型应当明确：它帮助比较的决策、输入的来源和日期、哪些关系暂作假设、实际未覆盖的条件、哪些结果将改变判断。单位由作者声明，工具不做自动量纲证明；将金额、人数、工时和日历天数混用仍是作者需要纠正的错误。

## 直接运行

`scripts/condition_lab.py`使用Python 3.10以上版本和标准库。它读取用户提供的JSON，只向明确的输出目录写入固定产物，不修改输入模型。

以下PowerShell命令使用`$skillRoot`表示当前`SKILL.md`所在安装目录，`$taskRoot`表示安装外的用户任务目录，可从任意当前目录调用；路径设置见[宿主接入](host-setup.md)。随包教学模型只读，输出保存在任务目录：

```powershell
python "$skillRoot/scripts/condition_lab.py" "$skillRoot/assets/examples/condition-university.json" --output "$taskRoot/高校容量推演"
python "$skillRoot/scripts/condition_lab.py" "$skillRoot/assets/examples/condition-project.json" --output "$taskRoot/项目容量推演"
python "$skillRoot/scripts/condition_lab.py" "$taskRoot/我的模型.json" --output "$taskRoot/推演结果" --format all
```

默认产生三个文件：

- `condition-results.json`：原始模型、全部离散组合、每项输入、派生结果、约束状态及输入文件身份。
- `condition-results.csv`：每个组合中每项输入、计算量和约束各占一行，可在表格软件中继续比较；可能触发单元格公式的文本添加前置单引号，保持为数据。
- `condition-results.html`：内嵌数据、样式和脚本的离线页面。选择外部情景、离散条件组合和具体方案后，页面列出所选情景下全部已计算组合的状态一览、同组条件下每个方案逐条约束的结果、每项离散条件单独变化时模型状态是否改变，并展开公式、来源与边界；无需联网。

`--format json`、`csv`或`html`可只生成一种产物。默认拒绝覆盖已有文件；明确需要更新已生成结果时，使用：

```powershell
python "$skillRoot/scripts/condition_lab.py" "$taskRoot/我的模型.json" --output "$taskRoot/推演结果" --force
```

`--force`只覆盖这些固定文件名且能识别为本工具产物的已有文件，不能覆盖输入，即使输入使用相同文件名。已有任意用户文件、符号链接或写入锁有冲突时，应选择新输出目录或先了解冲突原因。不要把覆盖授权扩展到其他文件。

## 模型格式

完整可运行输入见[高校容量教学模型](../assets/examples/condition-university.json)和[项目容量教学模型](../assets/examples/condition-project.json)。二者都明确虚构，不能当成真实机构的情况或模型效果证据。

顶层字段如下：

| 字段 | 格式与用途 |
|---|---|
| `schema_version` | 数字`1`。 |
| `title`、`purpose` | 模型标题及它要帮助处理的具体问题。 |
| `fictional` | 明确布尔值；教学设定用`true`，实际任务仍需逐个输入区分观察、假设和未知。 |
| `assumptions`、`boundaries` | 非空文本列表，明确简化关系和不可越过的解释边界。 |
| `inputs` | 变量名到输入对象的映射。每个输入有`label`、`value`、`unit`、`basis`、`role`、`note`、`source`。值为有限数字、布尔或`null`；文本标签不参与运算。 |
| `derived` | 按依赖顺序排列的公式对象列表：`id`、`label`、`formula`、`unit`、`note`。只引用输入或前面已经定义的计算量。 |
| `constraints` | 约束对象列表：`id`、布尔`formula`、`description`。没有约束时明确显示“未定义约束”，不宣称可行。 |
| `plans` | 方案列表：`id`、`label`、`overrides`、`note`。只能覆盖`role=decision`的输入。 |
| `scenarios` | 外部情景列表，结构同方案；只能覆盖`role=condition`的输入。 |
| `explore` | 条件变量名到离散值列表的映射，例如`{"total_hours": [30, 40, 50]}`；不允许改变决策变量。 |

变量和ID使用英文字母开头的字母、数字、下划线；人可读名称放在`label`。`baseline`为系统保留的方案/情景ID。输入的`basis`含义：

- `observed`：作者声明有相应来源，必须填写`source`。工具不验证来源是否真实、当前或适当；填来源不是对事实的认证。
- `assumed`：假设、估计或方案设定。理论不能独立确定的参数不要写成理论结论。
- `unknown`：实际尚不知道；`value`必须是`null`。反过来，`null`也必须声明为未知。

`role=condition`表示外部条件，`role=decision`表示本次比较允许选择的量。若选择事实上不可控制，不能只改角色就让它成为可行决策。`source`可写材料目录中的源ID及精确位置，或可回查的文件、页面、日期和位置；必要时使用[材料与证据工具](evidence-work.md)回到原文。

### 公式范围

公式使用有限的Python表达式写法，由脚本自行解释AST，不调用`eval`或`exec`：

```text
protected_hours + exploration_hours + administration + risk_reserve
max(0, existing_need - protected_hours)
remaining_hours >= 0
reviewers >= 2 and all_cases_eligible == True
```

支持`+ - * / // % **`、括号、一元正负号、数字比较、`and/or/not`、布尔等号，以及`min/max/abs`。幂指数绝对值最多12。`min/max`接受1—16个数字参数，`abs`一个。禁止任意函数调用、属性读取、索引、集合、字符串计算、导入及条件表达式。数字与布尔不互当作0/1。

未知向依赖它的计算传播，不当作0。已知不满足的约束不会因为别处存在未知而被隐藏。布尔逻辑中`未知 and False`可确定为假，`未知 or True`可确定为真；但表达式各部分若有除零等计算错误，会明确保留错误，不用逻辑短路将模型错误藏起来。除零、复数、数值越界、类型错误显示为“计算错误”，与“尚不清楚输入”的未知分开。

链式比较按相邻比较共同成立处理，例如`a <= b <= c`与`a <= b and b <= c`保持一致。任一可确定的比较为假时，不会因其他比较尚未知而隐藏不满足；计算错误和已知类型错误仍优先报告。

约束必须返回布尔值。整个组合可能是“满足所列模型约束”“不满足所列模型约束”“尚不能确定”“存在计算错误”或“未定义约束”。仍需逐项查看结果：总量约束成立，不能清除资格、执行或其他未表示条件的未知。

### 离散比较与资源边界

工具自动加入“输入中的条件值”情景和“输入中的决策值”方案，然后计算全部`情景 × explore组合 × 方案`。`explore`中列出的条件值始终覆盖输入基准值；如果希望比较原值，请把它列进网格。情景与`explore`禁止同时覆盖同一个条件，避免网格悄悄抹去情景含义。

情景、网格或方案覆盖的值明确标为假设或未知。即使原输入标为观察值，改成新数值后也不会沿用它的事实身份；界面保留原来源以供回查，同时注明原来源不为覆盖值作证。

最多64个输入、64个派生量、64项约束，最多16个用户情景、16个用户方案、8个网格条件且每条件最多16个值。组合总数上限512，超过会明确拒绝，不自动抽样或截断。模型文件上限2MiB，单项输出上限32MiB；这些限制约束计算规模，不限制用户问题的分析深度。

HTML只切换已预计算的结果，不用JavaScript重新解释公式或产生新预测。离散点上“从不满足变成满足”只能支持所列点的比较；不能自行声称所有中间值、任意变化方向或真实世界均有同样阈值。需要更精细比较时，作者明确调整网格并重新计算。

## 把计算接回判断

高校教学例中，40工时下分配25给既有需求、5给探索，加上10事务与2预留，总量为42，超出2；探索降到3后总量恰好40。但两名复核者的逐案资格与实际时段仍未知，因此模型不宣布该方案在现实中已经可执行。既有需求增加到28时，原先的25也仍有3工时缺口；总工时增到50不会自动把“只分配25”的方案变成覆盖全部需求。

项目例中，24工时可覆盖3项各6工时的功能，再加4工时集成和2工时预留；外部依赖延期时，即使工时增加仍不能通过依赖约束。计算帮助说明条件之间的区别，不能代替对方案价值、执行者和实际工作关系的分析。

实际回答给出当前首选、成立条件、相对备选的理由、尚需取得的材料和切换条件。不要只交一个绿色状态表。若量化模型与材料或理论分析矛盾，应重新检查输入、单位、遗漏关系和模型适用范围；不能以“程序算出来了”为由压过现实材料。

多轮讨论中，用户改变的是事实、选择、假设还是目标，决定改哪一处。保留仍适用的模型与备选，读取实际当前输入后更新；新结果进入受影响的正文、图表和决断。对方只要求讨论时先解释，不擅自覆盖主稿或模型文件。
