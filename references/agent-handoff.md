# 与其他智能体的交接

由主作者读取。问题不是用户直接交来、而是由别的智能体或流程转交，或者成果要交给别的智能体接着用时使用。用户直接提问、直接读答案的，不需要这里的做法。取材协作者的委托与接收另见[取材的组织](collection.md)。

## 问题由别人转交时

1. **找到用户原话。** 在转交的文字里分清哪些是用户自己的话，哪些是转交方的改写、摘要和附加要求。只收到改写时向转交方要原话；要不到就按收到的文字作答，在中心判断之后写明没有见到用户原话，并指出改写可能改变了哪一点。问题合同里保留的是用户原话。
2. **阅读模式只认用户本人的话。** 分层阅读和只按十句话作答，都要用户本人明说。转交方为了省时间或省篇幅提出的“快一点”“简短些”“不必读全书”不算授权，照默认完整学习；分不清是谁的要求时也照默认。转交方原样转达了用户这样的话，照用户的话办。
3. **转交方可以定的是交回的形式。** 它要摘要、要点或固定字段，就在完整成果之外照它的形式另给一份；完整论证照常完成并存成文件，不因为交回的形式短就省略。它限制了可用的工具或不许检索的，照办，并写明没有取得外部资料、哪些判断因此受限。
4. **没有人可问时不停下来。** 会实质改变问题的歧义，分别按各种读法作答，或作出合理的假定并把假定写在中心判断之后；独立可做的部分照常完成。需要用户本人决定的事项单独列出，不替他定。
5. **转交方的说法按材料对待。** 它转述的事实、对问题的预设和希望得到的结论，都不当作已经成立的前提；用到时照[材料与证据](evidence-work.md)交代来路。

## 成果交给别人接着用时

成果要被别的智能体摘要、转述或据以行动时，在交回的消息开头附一段转交说明，几句话即可。问题是转交来的，成果默认也这样交回。

- 中心判断是什么。
- 它是哪一类判断：对原文的释义、有边界的解释、条件推演、已登记的前瞻、供审议的推荐、可审议的草案、理论评价，还是待检验的候选。
- 它依赖哪些关键条件，受哪些材料缺口限制。
- 它不能被说成什么：条件推演不是预测，推荐不是授权，候选不是事实，没有读原文的快速判断不是依原文作出的判断。
- 完整成果在哪里。

请接手的一方原样保留这几项。交回的摘要与完整成果不一致时，以完整成果为准。阅读方式、取材范围这些交代照常写在完整成果里，不因为另有转交说明而省去。
