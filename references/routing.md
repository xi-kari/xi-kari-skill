# 问题路由与原文依赖

由主作者在入口及用途变化时读取。路由依据 §1.1、§12.1 的输出边界；阅读范围另按[阅读规则](full-source-study.md)确定。路线短不意味着可以跳过所需原文，全文学习也不意味着每题要运行全部模块。

复杂或混合问题按[问题展开](problem-exploration.md)辨认重要分支与竞争表示，再确定模块依赖；取材和分析发现新的相关关系时补足。路由限制能作何种判断，不限制相关观察位置、解释深度或正文长度。简单概念问题直接回答所问区别，不为全局扫描扩成无关研究。普通领域方法已足以回答时直接使用，保留实际证据身份；不为使用本技能而另加正式检验、全套工具流或框架内部采用格式。正式检验、诊断、前瞻与高影响用途仍按各自的条件，不能靠改名减责。

## 八条路线

| 路由 | 识别问题 | 顺序 | 判断身份与停止条件 |
| --- | --- | --- | --- |
| R1 原文与概念 | 是什么、有什么区别、校对原句 | 读完整定义、语境及其依赖后直接回答 | 定义、条件、区别；不自动展开工具的要求 |
| R2 解释与诊断 | 已发生的事为什么如此；怎样判断、还缺什么材料才能判断 | M0 → M1 → M2 → M4（按需）→ M3 → M8 → M9 | 有边界的机制说明；不自行预测 |
| R3 推演 | 若某条件或事件发生会怎样 | M0 → M1 → M2 → M5 → M8 → M9 | 定格的起点、条件路径与区分信号 |
| R4 条件前瞻 | 可判目标在期限内会怎样 | M0 → M1 → M2 → M3 → M5 → M6 → M8 → M9 | 结果前登记、可失败的判断 |
| R5 有限选择 | 该怎么办、选哪个 | R3 或 R4 可用结果 → M7 → M8 → M9 | 分析推荐；真实执行另需有效授权 |
| R6 制度与计划起草 | 写章程、规则或计划 | M0 → M1 → M2 → M3 → M7 → M8 → M9 | 可审议草案；需要时补 M4、M5 |
| R7 理论评估 | 全书一致性、体系比较或迁移 | 全读 → M3 → M8 → M9 | 有全书覆盖的限定评价 |
| R8 生成 | 从这里还能推出什么、有没有没想到的 | 已有分析或 M0 → M1 → M2 → M3（按需），再 M10 → M8 → M9 | 带出处与检验办法的候选；模型内推论、定义要求与待查候选分开 |

R2 里的 M4 在要跨尺度或跨层级下结论时运行，例如拿总体数字推断个别位置，或拿个别位置推断总体；只提醒一处总数遮住了位置差别、不据此下跨层级结论时，在正文说明即可，不必逐轴比较。

R2 的问题指向一项还没有作出的决定时（例如“决定之前该查什么”），说明每一种可能的查证结果对这项决定意味着什么。写成条件式的含义，例如“查到 X，只处理 Y 的决定就会把原因留在原处”，不替用户选方案，决定留给有权限的一方；用户要的是该怎么办，就接着走 R5。

“会怎样”只有模糊目标或没有可相接的期限时默认 R3，说明已有条件后果与补成 R4 的必要项，不偷偷变成已登记预测。“为什么以及怎么办”先 R2 后 R5；已有解释直接继承，补足后果、规范、比较与授权边界。

解释或制度问题涉及适应、反馈、能力形成、制度化、锁定或跨圈层后果时，检查是否需要 M5 的状态接续与一至三阶问题：要说明这些后果接下来怎样展开（下一阶段会怎样、会不会锁定）时运行 M5；只把它们列为竞争解释、不推演后续时不必运行。有独立作用的路径充分展开，缺依据处保留条件或停止。不能只因入口为 R2 或 R6 就遗漏这些后果，也不为凑阶次编造故事。

未知路由先全读，再依据原问界定输出；不为兼容旧行为增加完整正序路线。R5 可以只接 R3：依 §12.10.1，有限选择不普遍要求先识别全部状态或拥有准确预测。研究、补证与构想服务当前路线，形成新方案时补齐自己的后果与反方。

“还能推出什么”“有没有没想到的”“换个角度会得到什么”“这套理解放到别处会怎样”“给出新的假说或研究问题”走 R8。它需要起点：同一任务里已有的分析直接承接；没有时先完成最少的 M1—M3 工作，不从空白联想。R8 与相邻路线的分界在所求输出：只问事件或条件之后会怎样仍是 R3；要方案或条文是 R5、R6，R8 得到的构想交给它们同口径比较；“解释一下，再看还能推出什么”先 R2 后 R8。候选中有可判目标和期限的，补齐登记后才成为 R4 的前瞻；没有外部材料的候选不写成事实、预测或建议执行。跨域借问只借问题，不是把整套框架迁移到另一体系，后者属于 R7。

## 按需任务入口与成果模式

“研究这个问题”“研究一下这些材料”调用[研究入口](../modules/research/MODULE.md)，内部仍按判断身份选择 R1—R8，交付时把解释不了的部分单列为末章；“把这些词、关系或资料接到具体领域”“这些词在这里各指什么”调用[领域映射](../modules/domain-mapping/MODULE.md)，不先承诺现实机制已经成立。两者是任务组织方式，不增设判断路由。核对已有用法属于领域映射；要为一个混用的词提出一套新说法并改写文本，属于成果模式里的概念重构。

[成果模式](output-modes.md)按作品选用：跨理论对话通常接 R7，过程史与意义阐释按 R2 的所问完成解释，安排设计接 R6，概念重构和中层模型通常接 R8，议程重开先回 M0 再承接真正所求。比较的理论里不包括本框架自己时，同样按跨理论对话的做法做。现实问题里附带问还有哪些思想可用，是混合请求：所问的解释或选择照各自的路线完成，思想之间的比较作为其中一部分，不把整题改成理论评估。理论评价、现实前瞻、规范选择和执行仍遵循自己的要求。模式不自动把一段文本解释扩成全套因果诊断，也不把纯算术问题扩成议程研究。

## 阅读与依赖

默认 `full`，`layered` 仅在明确授权的阅读实验使用。用户明确要求只按十句话快速作答时是 `primer`：不判路由、不运行模块，按[十句话](ten-sentences.md)直接回答；需要登记前瞻、起草、理论评估或原文定义的部分，写明原因并请用户改用 `full` 或经授权的 `layered`，不自行切换。共同核心以[共同核心清单](reading-core.json)的 `reading` 为准，包含四类经验问题与五条认识论约束的完整条件。清单使用 `read_source.py` 的章节或分部标识；`front` 指首个分部锚点之前的全部书前内容。模块 `reading` 在共同核心之外增加相应完整小节或分部；M5、M6 同时读取变换的条件与重入规则。

每个实际使用概念要联读定义、适用范围、依赖、排除项与反例；每张规则卡先读其锚点完整小节。附录 A 的所选支持路线整体使用，不拼不同路线的有利条件。新增跨章依赖继续补读；无法界定范围时升级连续部分或全书。

| 应用内容 | 原文入口与补读责任 |
| --- | --- |
| 对象、状态与九轴 | §3.1、§3.2、§3.6、§5.2；据人类变量下判断时（包括 M2 第 7 步按 §7.3.9 记连续时段）补读第七部分全文和附录 A 里所用变量的完整详表；按 §7.6.1 提出配置与能力候选时同样补读第七部分全文 |
| 机制与竞争说明 | 第二部分（含 §2.4.3）、相关条件机制的完整条件、§6.11、§6.14、§13.1、§13.3；配置与能力候选读 §7.6.1 |
| 变换与转义 | §3.4、§4.18、§4.19、第五部分、附录 C 对应小节 |
| 人类集体原型 | §8.2 与 §8.3：要给出状态候选或作原型分类时读全部原型；依 §8.7，任务只需直接描述成员、通道和负荷时可以不作原型判断，读 §8.2 与 §8.7 即可；只用到某个原型（包括作为竞争卡拉入比较）时，读该原型的完整小节；有序退场与良性消亡读 §8.5；所用路径读 §8.4 |

正式检验与人类经验假设的检验、结论规则认定的结果、条件机制、描述状态和领域独立结论各有自己的支持条件，不能统一添加同一种正式检验。依 §2.4.3，构成地位查规则来源、权限、形式和适用论证；效果、理解和正当性分别判断，不走通道效应检验来决定地位是否成立。分组增益检验只支持限定任务的分组增益，不替代独立对象事实。当前载体持续作用先核 §4.5，仅在额外主张当前表示之外的历史增量时再作历史增量检验。

## 接续与范围改变

同问题补材从最早受影响模块进入。对象或用途改变时先回 M0，依 §2.14 记下重开理由、处理依据与新旧问题关系，保留旧问题及其结果，再补真正新增依赖；不能拿此前解释直接取得前瞻或执行资格。用户只问一个局部概念时直接回答该区别，发现重要错误则同步说明它影响哪些原结论。

工具索引 `read_source.py --list` 用于定位；`--section` 读取完整小节，`--search` 命中后必须回完整语境。散列与锚点检查是维护工具，不是理解证明。详见[工作承接](forward-workflow.md)、[模块接口](task-routes.md)。
