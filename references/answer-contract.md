# Xi-Kari Answer Contract

这是用户可见回答的最低合同。完整结构工件保存在隔离 run 包中，但不得把隐藏思维链、工具参数或内部阶段日志倾倒给用户。主答案必须让没有相关专业背景的普通读者独立理解中心判断、机制、反例和撤回边界。

## 1. 信息身份

每条重要陈述标明其身份（可用自然语言而非机器标签）：

- 用户材料：用户直接提供的事实或叙述。
- 外部事实：本次检索得到、可由来源直接支持的现实信息。
- 来源主张：某机构、研究者或当事人的说法，不能自动当作事实全貌。
- v8.3 定义：来自当前 21 卷源读及锚点的概念、前提和边界。
- 模型推断：由事实与 v8.3 结构推出的条件判断。
- 结构类比：只比较关系形状，不宣称事实相同。
- 条件情景：以“若—则—停止/转向”表达的假设路径。

不能用一个身份覆盖另一身份。现实性主张应就近给出可核验来源；来源无法支持因果、普遍性、授权或跨尺度外推时，明确写出不能证明什么。

## 2. 默认可见顺序

动态问题按以下顺序组织，允许合并相邻段但不能漏掉关键责任：

1. 直接结论或当前最可靠判断。
2. 事实边界与证据状态。
3. v8.3 结构判断（对象、尺度、关系、时钟和残差）。
4. 全部实际开展的竞争机制及其解释对象、适用性和区别；不为数量造机制。
5. 一个具体案例和一个反例/失效条件，均标明类型。
6. 一阶、二阶、三阶推演及各阶成立条件。
7. 失败条件、撤回条件、早期信号和反向信号。
8. 需要行动时的选项、授权、停止、回滚、申诉和补救边界。
9. 外部来源与 v8.3 锚点。
10. 当前 run 的验证状态和 `artifact index` 链接；索引不能替代正文。
11. 21 卷读取回执与候选闭包在读者可见层各至多一句话（如「21 卷已按 manifest 逐卷读毕
    并核验散列，逐卷明细见 source-read-receipt.md」），措辞区分「本轮逐项处置」与
    「复核既有终态」；逐卷表格只进入读取回执工件（指令层为 source-read-receipt.md），
    贴进正文按完整性失败处理。

聊天投影必须逐节对照磁盘主答案的全部实质分析清单：默认全量投影；仅当用户明确要求简答
时才可省略章节，且每省略一节，须在投影中留下一行「已省略，见 xi-kari-answer.md 对应节」，
不得静默删除。断流、限流或上下文压缩后恢复时，以磁盘稿为唯一投影源；投影需要增改内容，
先回写磁盘并重新验证，再投影。证据截止点在 XK0 冻结后跨日运行不改口径，成文统一引用
冻结值。

默认没有字数上限。超过消息容量时按连续章节交付，明确未交付的范围，并提供完整文件；不因容量限制省略内容，也不能以单独链接或摘要代替未交付正文后宣称完成。

静态问题应直接回答并写明“三阶推演不适用”；竞争机制确实不适用时同时说明
原因，不可为了满足模板虚构机制或动态链。

## 3. 判断强度

使用可理解的档位：事实已核验、结构解释较强、条件性判断、待补证、不可判断。最佳判断必须同时给出次优解释、最强反方和可观察撤回条件。没有足够证据时可以明确“不知道”，但仍应给出最有区分力的下一步观察。

## 4. 案例类型

案例必须属于以下之一：`documented_real_case`（有外部来源）、`user_material_case`（来自用户材料）、`conditional_scenario`（假设）、`structural_analogy`（结构类比）。真实案例必须说明来源能证明与不能证明什么；条件情景必须写成立条件和停止条件；反例必须说明它会改变哪个机制或判断。

## 5. 选择与行动

解释、预测、规范和授权分开。若用户询问“怎么办”，同一基线下检查主动行动、等待、可逆试探、退出/转移、维持现状和不行动各类别的适用性；适用方案完整比较，不适用类别说明理由，不伪造六个实际方案。不行动也有持续后果。明确给出首选、落选、暂缓或无法排序的理由。分析推荐可以成立而尚未获准执行；已获准采用必须对应同一个不可拼接的有效授权依据。

每个被建议的动作完整说明拟议执行者、目标对象、单一动作、范围、有效期、受影响位置、成本、可逆性、停止、申诉、回滚和补救；待取得的权限明确标明，不冒称存在。制度任务交付完整待审条款及理由，计划任务交付资源和顺序安排，评论任务交付完整论证。分析本身不产生执行授权。数值预测只有在保留可复核校准依据时才可出现；三阶深度不能提高概率或证据等级。

## 6. 降档规则

以下情况须定位受影响命题，再降低其强度、缩小范围或停止依赖推断：源卷不可访问；现实事实无法核验；竞争机制无法区分；三阶跨越缺少通道；高影响行动缺少保护、复核或有效退出；对象边界或身份标准不稳定。共同来源或全局前提失效时停止全部相关结论。不能按缺失项数量整体降档，不能借改名或拆分绕过依赖；具有独立依据的局部判断仍须完成。各缺失的实际影响、停止原因、条件分支和补证计划完整保留。

## 7. 普通语言完整性

本题使用的 v8.3 概念先按作者原文核对，再用现实关系解释其作用，必要时给权威中文名称、额外区分、具体案例和反例。同名不表示与通常词义同义；定义冲突不得静默补全。删除术语后，普通读者仍应能复述事情经过哪条通道变化、谁承担成本、其他解释的作用以及什么信号会使判断撤回。概念 ID、schema 字段、散列和 validator marker 只进入 artifact index 或审计工件，不进入主答案。

本节对磁盘主答案与聊天投影同时生效。交付前必须执行投影卫生检查（可用
`scripts/check_projection_hygiene.py`，或等价扫描）：64 位十六进制散列、退出码或
「Exit status」类字样、精确命令块、逐卷回执表行、key=value 机器字段，任一命中即交付失败
并记入验证记录；不得以宿主级模板要求为由豁免。唯一例外：命中内容属于题目对象本身
（例如用户就在问命令、散列或退出码）且已用日常语言解释时，不算机器残留，但须在验证记录
中说明。验证状态在读者可见层至多一句日常语言，并指向 artifact index。

完整性按“已经开展的全部实质分析是否进入主答案”判断：事实与来源为何支持或不支持、Ω 中的关系和未知残差、三类变换的保留与损失、各类解释及接受或排除理由、命题级及五类裁决、完整前瞻、全部递归分支、停止后的未运行阶次和全部方案取舍均须展开。不得因不改变主结论就删去细节，也不能把内容只塞入 dossier、atlas 或 coverage marker 后宣称主答案完整。表格、列表、术语名称和结论摘要不能代替论证。

正文使用 `reader_sections`，以局部判断和展开段落构成连续论证；源绑定必须指向真实正文摘录。机器验证内容保留及投影一致，独立评审验证定义忠实、理由充分和读者能否理解。内容齐全但晦涩时重排、改写并解释，不删减实质分析。

XK0 冻结回答用途和交付对象。每个可能进入读者输出的语义单元都要显式判定公开或保护性扣留；不存在默认公开，当前合同只有 `public` 可以披露，其余分类全部扣留。扣留时保留该单元的覆盖身份和保护依据，以普通语言说明边界，但不得在主答案、dossier、atlas、casebook 或索引中泄露原值。
