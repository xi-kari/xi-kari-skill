# 模块接口与交接物

由主作者和协作者读取。[routing.md](routing.md) 是路由的唯一主表，十个 `modules/*/MODULE.md` 是步骤入口；本文件说明怎样承接内容，不另建同名流程。

## 交接的是实质工作

| 内容 | 产生者 → 使用者 | 何时保存独立文件 |
| --- | --- | --- |
| 原问、对象、用途、截止、路线与约束 | M0 → 后续全部模块 | 长任务或跨作者需要共同合同，使用 `contract.md` |
| 来源、片段、支持范围、反向材料与争议 | M1 → M2/M3/M5/M7 | 多来源回查时用现有材料目录或 `evidence.json` |
| D0/K、九轴、行动者圈层、变量与未知 | M2 → M3/M4/M5/M7 | 状态需接续时用 `state.md` |
| 机制比较、使能依据、竞争与区分观察 | M3 → M5/M6/M7/M9 | 可直接在分析稿或路径文件中保留 |
| 转换规则、保持损失与适用域 | M4 → 所有依赖目标表示者 | 与所在状态或路径记录合并，避免重复 |
| 冻结输入、事件、时钟与传播政策 | M5 → M6/M7/审查者 | 需要冻结或复用时用 `snapshot.md` |
| 路径、父子节点、条件、信号与停止 | M5 → M6/M7/M8/M9 | 多路径或协作时用 `paths.md` |
| 结果前目标、基线、表达与回写合同 | M6 → M7/M8/M9/到期评价 | R4 必须保留，优先 `forecasts.json` |
| 同基线方案、代价、首选与改判条件 | M7 → M8/M9 | 多维复用时用 `comparison.json`，短比较可在正文 |
| 具体异议、证据、影响与修正 | M8 → 受影响模块/M9 | 仅在多人或跨轮有用时保存问题记录 |
| 完整答案或用户所求成品 | M9 → 用户/持续工作 | 长文、合稿、导出与持续编辑用 `xi-kari-answer.md` |

名称不要求每题创建十套工件。除 R4 登记外，文件只在下一步确实使用、需要恢复或用户指定时生成。短概念问答直接答；简单解释可以在一份答案中完成全部相关内容。文件存在不证明工作质量。

## 共同接口

传给下一模块的内容应使接收者知道：共同问题、对象与版本、当前事实、来源、判断、假设、未知、主要反方以及下一项真正要解决的事。已有文件引用原位置即可，不复制同义台账，不转交私有内部思维链。

事实、报告、模拟、推断、规范与授权分开。获取旧材料是认识更新，模拟后继仍是模拟，实际新事件才改变现实状态。对象、期限、单位、规则版本不同先处理差异，不能无缝拼接。

模块完成后直接使用其结果；没有新事实或具体矛盾不固定回头验一遍。问题扩展时补新增输出的责任：解释不能代替登记，预测不能代替规范，推荐不能代替执行授权。

## 一个教学接续，不作经验证据

用户问“项目月底能否交付，怎样调整”。M0 明确交付物、期限和判定来源，M1 取得实际完成项与剩余依赖，M2 建立容量与依赖，M3 比较瓶颈机制，M5 展开按期与延误条件；条件齐全时 M6 冻结 R4，M7 再比较缩范围、增容量、延期及不行动，M8 处理共享资源与质量反方，M9 给当前判断和完整理由。

若交付标准尚未定义，先保留 R3 路径，不能登记模糊成功；若硬约束已证明某条件下不可能按期，仍明确给出这项局部结论。只为回答概念则走 R1，不复制这条长链。

独立部分可按[协作](collaboration.md)并行，继续同一问题按[持续对话](continuation.md)从最早受影响内容进入。
