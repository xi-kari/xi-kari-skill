# 任务路线与模块承接

在完成理论学习后，按用户真正要得到的结果组织工作。先明确问题和材料，再展开解释、后果或方案，形成判断并完成成果。XK0—XK11保留这个先后关系；模块说明其中每一类工作怎样做，不另加一条验证流程。

## 先选择本题的工作路线

| 用户主要在问 | 依次开展的工作 | 最后交付什么 |
| --- | --- | --- |
| 某个概念、文本或观点是什么意思 | 回查完整定义与语境 → 解释关键区别 → 用例子和反例说明 | 直接释义、成立范围及争议判断 |
| 发生了什么，为什么会这样 | 材料与观察 → 对象和机制 → 竞争解释 → 裁定 | 中心解释、各机制的作用及具体未决 |
| 条件改变后会怎样 | 当前状态 → 作用通道与时钟 → 条件分叉 → 后果比较 | 路径、承接关系、主要后果与边界 |
| 未来会不会发生，何时发生 | 当前状态与简单基线 → 机制和竞争路径 → 适用的计算 → 预测判断 | 当前预期、期限、关键条件、替代路径和反向信号 |
| 怎么办、选哪一个 | 目标与约束 → 可用解释及后果 → 真实方案比较 → 选择 | 当前首选、落选理由、代价及实施次序 |
| 能不能设计另一种办法 | 定位实际断点 → 形成新的规则或安排 → 推演后果与承接 → 比较取舍 | 具体构想、运行方式、代价和采用条件 |
| 还需要研究什么，或怎样区分解释 | 已有判断与未决 → 区分性观察 → 能开展的资料工作或计算 → 更新判断 | 实际研究结果；尚不能完成的部分给可用采集安排 |

一个问题可以同时包含几种要求。例如“改革为什么失灵、继续这样会怎样、应该怎么改”，按解释、预测、方案依次展开；前面取得的材料与机制直接沿用。用户只问其中一段时，完成必要背景和该段工作，不顺势扩成无关任务。

路线决定工作重点，不提前决定答案。发现材料口径改变，就先处理口径；发现一个新方案，补足它自身的后果与比较；已经能判断的部分仍可继续交付。

## 模块实际承担什么

| 模块与入口 | 承接的内容 | 要做出的实质结果 | 后续怎样使用 |
| --- | --- | --- | --- |
| [材料与证据](evidence-work.md) | 原问、已有文件、待了解的现实情况 | 可回查观察、冲突、时间与支持范围 | 为解释、预测或选择提供同一事实基础 |
| [结构解释](analysis.md) | 事实、争议及对象范围 | 作用通道、关键条件、主次与兼容机制、反例判断 | 供推演采用，或直接回答为什么 |
| [条件推演](dynamics.md) | 当前状态、机制、条件与时钟 | 各路径如何改变对象、行动与后续条件 | 供预测比较或方案分析使用 |
| [预测判断](forecasting.md) | 未来目标、窗口、当前材料及可用路径 | 有依据的预期、相对基线的理由、关键变化与未知 | 回答未来问题，或向选择模块提供后果判断 |
| [方案选择](decision.md) | 目标、价值前提、约束、解释与后果 | 首选、落选、条件分支和具体安排 | 形成计划、条文或按已有授权继续执行 |
| [批判与构想](critique-and-invention.md) | 待评价观点、断点、真实反对理由 | 对具体主张的裁定、可用的新构想与替代方案 | 更新相应解释或加入方案比较 |
| [实际研究](research-work.md) | 当前最有意义的实质分歧 | 新材料、计算、试验结果或具体采集办法 | 改变有依赖的机制、预测或选择 |

批判随实际争点进入，不在每个模块后再附一次相同审核。研究只围绕尚未解决的问题展开，不能把所有能回答的内容退回资料清单。预测和选择分开：更可能发生的结果，不直接决定更值得采取的行动。

## 接续的是内容

向下一模块说明共同问题、已经知道什么、当前判断、相关依据、仍在使用的假设，以及接下来真正需要回答的问题。已有材料可以直接引用任务文件或前文，不复制一套同义台账，不要求固定JSON和独立报告。

事实、推断、假设情景与未知在论证中保持各自身份。拿到一份旧记录改变的是当前认识；模拟得到的后继状态仍是模拟状态；新观察到的实际变化才更新现实状态。不同模块使用相同的对象、期限、单位和版本，发现具体不一致就修正那一处。

模块完成自己的工作后，下一步直接使用其结果。没有现实新材料、具体矛盾或用户新要求时，不因“还可以再检查一遍”退回上游。最终由主作者把各段论证连成一个正面回答，而不是交付模块列表。

## 选择协作方式

- 共同材料较少、前后依赖紧密时，由同一作者顺序使用各模块。
- 不同领域、地区、对象或证据方向可以独立展开时，并行分工，先约定共同问题和边界。
- 某个承重判断确有争议时，分配这项具体争议，要求提出反对理由、反例或替代解释；不能只要求另一作者判定整篇是否合格。
- 计算、来源定位、制图和排版可以交给相应工具或辅助者。真实采用与外部操作按原有授权完成。

模块数量与智能体数量无须一一对应，不按人头投票形成事实或概率。协作者各完成有用内容，主作者负责取舍和总装，详见[完整学习基础上的协作](collaboration.md)。

## 一个顺序工作的例子

用户问“项目能否月底交付，应该怎样调整”。先取得已完成验收项、剩余依赖、可用人员和截止时间；解释模块判断当前限制来自关键依赖、返工还是容量。推演与预测模块据此比较继续现状、依赖按期和依赖延迟的后果，给出月底交付的当前判断。方案模块再比较缩减范围、增加资源或调整期限，说明首选及代价。

若依赖日期不确定，但另一项必需工作已经无法在期限内完成，仍可据已知约束判断当前方案不能按期；若未知条件确实会改变结果，就分别说明条件下的判断和应取得的具体信息。分析结束便交付，不生成“已使用模块”证明，也不等待结果发生后才作当前判断。
