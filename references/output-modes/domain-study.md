# 领域专论

用户要求把一个领域或一类问题做深、做成研究室水平的理论研究，或要一份严格的“理论怎样接到这个领域”的映射时调用。它由[研究入口](../../modules/research/MODULE.md)组织，按所问判断接 R2、R7 或 R8，映射部分用[领域映射](../../modules/domain-mapping/MODULE.md)。几条路线都用到时按这个顺序做：M0 立题，M1 取领域来源，领域映射做对应，M3 在案例上比较领域的解释与理论的区别（需要时用 M2、M4），评价贡献与限度，要推出新命题时接 M10，最后 M8 反方、M9 成文。只问一个现实案例时用研究入口即可；只比较两套理论时用[跨理论对话](theory-dialogue.md)。返回[成果模式索引](../output-modes.md)。

## 输入与实际工作

取得领域范围、要回答的问题、用户已有的材料和用途。默认主动取得领域的一手来源和权威综述；用户限定材料时遵守，并写明因此核对不了什么。范围没有说全而用户不在场时，取一个本次做得完的范围直接开始，在成果开头写明替用户假定了什么。先在[领域入口索引](../domain-index.md)找到相应的附录 D 小节，读完整小节及其正文连接。专论要评价理论在这个领域的适用，属于体系迁移；明确授权的分层实验中也完整阅读原文。

1. **先立领域自己的问题和已有答案。** 写出这个领域公认的核心问题、主要解释传统、关键经验发现和仍在争论的地方，各自回到原作或可靠的专业综述，取原作的办法见[实际研究](../research-work.md)的“追到原作”。每条来源写明实际读到的范围；只读了摘要、工具转述或书目的照实标明，不当作已核。写出检索范围和日期，“没有找到”只相对这个范围。
2. **读理论对这个领域的定位。** 附录 D 的小节说明这个领域里哪些区别必须保留、哪些说法不能互相顶替。它是定位，不是操作手册；领域的定义、数据和方法以领域来源为准。
3. **逐条映射。** 把领域的概念、关系、测量和方法，与理论中用得上的区别一条条对起来。每条落笔前用 `read_source.py --section` 复读所引的小节，转述以复读为准，不凭通读时的印象。每条写明身份（定义对应、角色或对象实例化、部分对应、观察接口、类比候选、不对应、不适用或未知）、两侧各自的出处、保持了什么、丢了什么，以及什么情形会使对应不成立。类比按 §2.6 写清共享结构、关键差异和不可迁移的条件；申请正式转义按 §3.4.1。对不上的领域概念保留原词。
4. **用公认的案例或发现检验。** 选两三个领域内公认的案例、已发表的发现或长期争论，分别说明领域自己的解释怎样说，用理论的区别又多看见或少看见什么：它防住了哪种已知的错误推论，哪里领域方法更强，哪里两者会给出不同而可以检验的后果。引用已发表的数字时给出处和口径，不编造数据；没有可核材料的检验写成研究设计。
5. **写清贡献和限度。** 按 §16.15 分开三种情形：两边在估计不同的结果，对同一结果提出竞争机制，或者采用不同的价值前提。说明理论对这个领域新增了什么可辨别的内容，哪些地方只用领域方法就够（§4.17.4），哪里命中了理论自身的命题、应作为理论问题候选。
6. **核对与审读。** 定稿前逐条核对两件事，每篇都做：每处对原文的转述与所引小节是否一致；每个引用的数字、页码和结论与实际读到的来源是否一致。成果要外传、要据以决策，或用户要求时，宿主支持的话再请一位按[审查者职责](../../agents/reviewer.md)独立阅读的作者挑映射和实质论证的错。这位审读者要自己读完原文，耗费与主作者的阅读相当，按成果的用途决定值不值得。同一模型的另一个实例能帮助发现错误，其意见不算独立的经验支持。

## 交付与接续

交付一篇专论：开头的中心判断，领域的问题与已有答案，理论的定位，映射，案例检验，贡献与限度，末章是解释边界与问题；最后列参考来源，每条注明读到的范围；正文只在一个判断依赖没有读到原文的来源时就地说明，不逐处重复。正文用白话写，映射在正文里讲关键的几条；完整对照表放在正文之后，原文小节号和两侧出处写在对照表与方法附注里。推出的新命题单列一节，按[生成指南](../generation.md)保留候选身份：写明来路、最强的竞争项、检验办法和否决条件，以及新在哪一层；就这条陈述专门查过领域已有说法的才写“所查范围内未见”，没查的照实写没查。需要继续取证的检验写成研究设计放在专论里；要交给别人实际采集时，再按[研究设计](../study-design.md)生成可交接的说明。方法附注用一句话写明是否做过独立审读、由谁做。

映射结果同时整理成一张[领域卡](../domains/README.md)的草稿，附在成果之后，或放在任务目录里并标明是草稿。用户同意并指明领域库位置后才存入；用户不在场时不写入任何领域库。

篇幅大、要分几次做时，先交付已完成的部分和明确的后续范围，不把提纲当成果。长期进行的专题用已有的材料目录、主张台账和任务状态接续。

## 边界与验收

不把领域知识改写成理论的同义词，不预定理论胜出，也不因为专业方法没有理论编号就取消它的知识地位。理论材料不代替案例证据，AI 摘要不代替可追踪的来源，同一原作被多处转引仍是一条证据。没有做过先例检索，不称原创。临床、法律、金融、工程安全等高风险的专业判断交给相应的专业方法和有权主体，专论只提供分析。

实际核对：领域自己的问题是否先被准确写出；每条来源是否写了读到的范围；每条对应是否有身份、出处和失效情形；案例检验里的数字是否有出处；是否指出了领域方法更强的地方；末章的问题是否对得上正文里的结论。

[完整合成示例：社区工具共享站的一篇有限专论](../../assets/examples/output-modes/domain-study.md)。材料里加入一批登记了损坏却不处理的站点后，应重做柳岸站的检验和依赖它的贡献判断；押金与流失的结论不受影响。
