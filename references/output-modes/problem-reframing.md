# 共同问题与议程重开

用户对目标、成员、损失或给定约束有实质争议，或尚不清楚究竟应研究什么时调用。承接 M0 的问题工作，以 R8 形成候选问题；要求方案比较或制度草案时再接 R5/R6。明确、恰当的局部问题直接回答，不为显示深入而强行重开。返回[成果模式索引](../output-modes.md)。

## 输入与实际工作

取得原问题与已有结果、争议及提出者、不同位置的实际材料、适用决定程序。没有当事人材料时只列分析者提出的候选问题或待询问位置，不能虚构访谈、代表意见或共识。

1. 先回答原问中已经能回答的部分，保留其口径、来源和范围。结果不利不是换题理由；新题完成也不使旧任务自动完成。
2. 分开事实争议、解释争议、目标冲突、对象边界和程序争议。明确是谁以什么理由质疑，避免把未被记录的人直接当作赞同者。
3. 提出若干完整问题表述，说明它们与原问是并列、替代还是细化，各自保留和遗漏什么，需要什么材料与方法。可以建议维持原问；不以多造问题数量为成果。
4. 比较不同问法会改变哪些方案、损失、权限或研究结论，形成有理由的建议。日常讨论可以直接重述；制度内目标、资格和资源配置的修改由适用程序决定，讨论本身不生成决定权。
5. 写共同问题书，明确已经能够继续的研究与尚需本人或制度决定的事项。存在真正价值分歧时保留分歧，不假造经验理由消除它，也不把争议自动当成永久否决。

## 交付与接续

主体交付原问题的限定答案、实质分歧、建议的新问题及理由、可马上开展的工作。按需要附议程草案，标明哪些是材料中的真实主张、哪些是分析者建议；不得只交泛泛的“利益相关者清单”。

实际研究交给[研究入口](../../modules/research/MODULE.md)，概念混淆可调用[概念重构](concept-reconstruction.md)，具体安排交给[制度与生活安排设计](arrangement-design.md)。复用已有来源和主张记录，不因重开而删除原失败或旧边界。

## 边界与验收

帮助表达不等代人同意，整理意见不等取得代表权。公众或法定程序不一定以逐人私人同意为基础，也不能被写成人人已同意。相关人的保护性不公开保持相应未知，不为追求完整强迫披露。

实际核对：原问是否得到相称回答；每个新问题是否有实质理由；旧证据在新目标下是否仍适用；是否误把改名当作结果改善；是否伪造一致意见。时间紧迫时先交付有用的局部判断，不用无尽重开拖延必要保护。
