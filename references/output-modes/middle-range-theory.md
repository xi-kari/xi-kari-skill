# 中层理论与模型构造

用户要把已有材料、机制或残差发展为有明确范围的理论草案时调用，默认承接 R8 与 M8；要求体系评价时再用 R7。普通候选生成不必写成论文，单纯复算一个公式也不必扩成新理论。返回[成果模式索引](../output-modes.md)。

## 输入与实际工作

取得待解释的具体差异、已知案例与反例、领域已有模型、允许使用的假设及目标。资料可以不足以支持经验机制，此时仍可构造明确标示的模型；不能把构造轨迹填成现实观察。

1. 说明新模型要比已有解释多回答什么。查相称的既有模型与简单解释；先例未查明时限定新颖性范围，不把本次首次想到当作学术首创。
2. 选择必要概念、对象、关系和状态，逐项区分定义、经验依据、形式假设与规范设定。关系图中的箭头须有相应论证，不能靠连线使机制成立。
3. 明示边界、初始条件、作用规则和任务。用可核推导、手算或[有限工具](../finite-tools.md)求出模型内后果；先说明前提，再论证结果。非形式解释也须把关键连接完整写出，不强造数字。
4. 给有实力的竞争模型或简化版本，比较它们允许的结果与区别。局部平均效应不能无条件相乘；同一时刻可拟合，不等于干预后预测一致。
5. 尝试困难反例与条件变化，定位结论何时减弱、反转或失效。新增的事后解释只成为下一轮候选，不改写旧检验成功。
6. 写完整模型说明：问题、先例、关系与前提、推导、比较、反例、适用域和下一项可区分研究。已有相称设计识别的总效应不必等待所有中介识别，但未识别的因果关系不能由模型填补。

## 交付与接续

交付小型理论论文或模型说明，并把模型内结果、经验候选与规范建议分别标示。正文应能让读者复核为什么会出现所述后果，而不是只列候选命题或丢一个计算脚本。

候选谱系沿用[候选账本](../candidate-ledger.md)，只在有用时保存；实际材料检验交给[研究入口](../../modules/research/MODULE.md)，具体比较操作见[能力操作](../capability-operations.md)。要形成安排建议时另公开价值取舍和现实可行条件，不从模型自动授予执行权。

## 边界与验收

模型完整、内部一致、合成数据复算成功都不证明现实机制成立。不能用同一材料反复自证，也不能无限补条件维护无法失败的解释。专业或精简模型同样完成任务时，允许简化或交接。

实际核对：每个结论能否返回前提或证据；推导和数值是否正确；竞争模型是否被公平保留；规范建议是否额外说明目标；正文是否交代没有回答的现实问题。
