# 选择与执行

## 完成选择

沿[判断与决策责任](decision.md)给出首选、拒绝或暂缓项及其理由。规范目标、约束和受影响位置公开说明，不从事实直接推出唯一价值排序。用户已明确的价值选择应保留；必要假设应标明，不能冒称所有人同意。

比较实际可行选项，包含真正的不行动基线；按相关性考虑等待、试探、退出和主动维持。它们不是必须凑齐的固定数量。不行动仍可能有持续代价，也不免除既有责任。

每个重要方案须连接主导问题、作用机制、承接者、资源、时限与后果。共同资源要检查联合可行性；不能把各自可行的方案叠在一起就算完整计划。对未知状态可考察共同合格动作，不要求先识别全部世界；交集为空时寻找最有区分力的观察或公开的条件选择，不能擅自消除未知。

## 法律与制度设计

先形成总体裁断，再落实保留、废止、替换或新增的规定。重要诊断必须能指向具体规则或程序变化；一条条款要有明确对象、触发、责任主体和后果，例外有边界，救济能改变错误结果。

按实际请求覆盖：目的与适用、术语、权利义务、权限分配、申请或启动条件、证据与理由、期限、执行能力、利益冲突、例外、复核救济、监督、过渡、生效与修订。大体系还须处理上下位规则、横向冲突、管辖、共同定义、资源接口和规则缺口。不能只给一张目录便称完成法律体系。

资源不足时调整实施范围、次序和过渡安排，保留最低保护；不要写出无人、无时限或无效力的“独立复核”。提出的期限、岗位和额度是设计建议，明确与现有事实区分。对具体法域适法性与现行法作判断时核对权威文本；虚构或规范设计题不伪造法源。

条款形成后，选对任务最有区分力的普通案件与反例沿条文走一遍：谁受理、凭什么决定、何时通知、何处救济、谁承担资源。发现冲突就定点修改。这里核对的是制度能否工作，不是模型是否遵循技能。

## 使用既有授权

分析推荐、采用决定和工具执行分开。用户授权起草即可起草；授权具体可逆编辑即可在该范围内编辑，不要求重复批准。涉及真实他者处置、权利、资源或组织化采用时，核对适用的规范、保护、责任与有效权限；不能从工具可调用、自己给的评分或输出合同生成许可。

正式框架干涉依其合同核对N/PF、结构化选择、C12、同一条有效J授权与O1—O4；这些要求不能用来虚构所有普通本地编辑都需要机构审批，也不能替代外部制度的有效授权。

## 工具工作的结果

按任务所要求的终点确认结果：

| 用户终点 | 需要看见的结果 |
| --- | --- |
| 回答或草案 | 内容完整、理由可理解；文件任务正确保存并可读 |
| 更改配置、文件或外部记录 | 正确目标已发生要求的改变；必要时核对实际消费该状态的系统 |
| 指定补救 | 对应资源、权利、服务或机会确实到达；尚余问题单列 |

建议、请求送达、应用接收、实际变更和指定后果不是同一个状态。无需为每次操作额外产出五份日志；从实际工具与对象取得足够结果即可。

共享对象的修改按版本或顺序协调；独立读取和独立对象任务可并行。超时表示结果未知，先查看目标状态或请求身份，再决定是否重试，尤其不要盲目重复外部写入。发出停止、执行器确认、在途终止和已发生后果的补救分别成立；需要时报告已到哪一步。

原文入口：§12.8—12.15、§13.11.1—13.11.2、第十四至十五部分及附录D.19—D.21。
