# 条件前瞻与结果回写

由预测者和主作者读取。完整操作统一使用 [M6 条件前瞻](../modules/forecast/MODULE.md) 的 F0—F12；本指南说明表达、登记和能力边界。

## 何时进入 R4

未来问题具备可判定目标、冻结对象与圈层范围、与机制相接的期限、输入截止及结果来源时，可进入 R4。仅问假设后果或这些条件尚不具备时走 R3，给出有依据的条件路径与所缺内容，不把模糊“会变好”留到事后任意解释。

已有 M0—M5 材料和机制直接使用，F1—F7 只补缺口。前瞻先比较最近状态、趋势、历史频率、行动者单焦点、主圈层单焦点或领域已有方法等适配基线，再判断新增机制是否提供有支持的偏离。基线与模型使用同目标、期限、截止及评价规则；没有改判依据可以保留基线。

## 表达由证据决定

概率须有模型或经验生成依据和适用范围，数值区间须有单位、方法与误差含义。路径排序、主观信念、决策权重、计算优先级与现实概率不互代。多个模型赞同或内部抽样出现较多，不直接提供现实频率。

数值 `interval` 还须登记严格介于 0 与 1 的 `nominal_coverage`，同一记录内模型与基线使用相同单位和名义覆盖率。预登记 `interval_score` 后，令 α = 1 − 名义覆盖率，评分为区间宽度，加上结果低于下界或高于上界的距离乘以 2/α；越低越好。例如名义覆盖率 0.8、结果为 5 时，区间 [3,4] 得 11，区间 [0,1000] 得 1000。`interval_width` 仅描述宽度；`interval_coverage` 只用于核对实际覆盖比例是否接近名义覆盖率，不计算覆盖率增益或据此判模型更好。有限输入产生超出数值表示范围的宽度或评分时，值保存为 `null`，相应的 `interval_width_infinite` 或 `interval_score_infinite` 明示溢出。

预测事件时间时使用 `time_window`，在共同评价窗 `window` 内另行冻结表达的 `start`、`end` 和 `basis`；各基线区间可以不同。`window_coverage` 只比较事件是否进入各自预测区间，并同时报告 `window_length_days`，不能把共同评价窗当成各自的预测。评价窗内未发生事件时覆盖为 0；未知不记 0。live 无事件结果的时间表示测量完成时间，不能早于评价窗终点。可选 `nominal_coverage` 严格介于 0 与 1，预登记 `interval_score` 时按天计算区间评分；事件未发生时没有可计算的事件时点评分。

概率不足时，可以在有依据范围给等级或排序；方向也无识别依据时保持未知，并指出有区分力的观察。部分未知不取消其他可成立的局部判断。例如明示生产与串行检验需要 8 天时，可以说明 7 天目标在这些条件下不可达，不必捏造延期概率。

条件与时间窗放在正文中，说明简单基线、主路径、竞争路径、早期与反向信号、暂停条件及当前未知。早期信号是机制先产生的变化，不是把结局缩小重说。信号触发复核，不产生行动权限。

## 结果前登记是 R4 的组成部分

依据 §2.12、§12.2，所有 R4 在结果出现前保存最低登记；不因“普通回答”或未要求跟踪而免除。优先用 `forecast.py` 在技能目录外保存 `forecasts.json`；没有命令行时可保留同字段、不可覆盖的等价记录。无法保存或缺最低项时，输出退回 R3。

记录包含版本、目标、判定规则、期限、范围、输入截止、基线时点、简单基线、机制、路径、表达与依据、校准、适用决策阈值、信号、暂停退役、回写与证据引用。每阶独立记录和评价，二三阶另与不递归延续、直接远期判断、浅阶加延续比较。开发验收阈值尚待确定，与本案行动阈值不是同一字段。

新登记的二、三阶还须给记录级 `parent: {"forecast_id": "父前瞻ID", "path_id": "父路径ID"}`：父记录须已存在、恰好低一阶、采用相同理论散列，子资料截止不得早于父资料截止。本记录内部的顶层 `path.parent` 可为 null，不与记录级父路径混用。`pooled_by_parent_match` 对二、三阶另列父最新结果中的路径匹配／不匹配／未决；旧无谱系数据另列 `unknown_legacy`，不能补造父运行。

新 `live` 登记的评价窗起点不得早于工具实际生成的 `registered_at`；为录入留出时间，起点应设置在预期提交之后，失败时按报错给出的实际登记时间修正。新 live 回写只要 `observed.value` 或 `observed.category` 非空，就必须填写晚于登记时刻的 `observed.event_time`，表示事件发生或测量完成的时间；零值也不能省略。旧冻结记录只读保留原校验与评分版本，不能借兼容规则为新登记或新回写倒填已知结果。

`register` 冻结新记录；`list` 与 `show` 回查；`resolve` 追加真实结果；`report` 统计适用指标；`check` 检查结构一致性。命令和字段示例见 M6。工具不证明定义用对、材料真实、模型有效或选择正当。

`check` 只能核对注册表中已有的内容，不能看见未登记就发布的 R4 答案。登记覆盖率由外部评测将 R4 答案与登记逐条对应后统计：有对应有效登记的 R4 答案数除以全部 R4 答案数；没有 R4 答案时记为不适用，不填成 100%。

新写入使用 `schema_version: 2` 的顺序哈希链，关联每条前瞻及结果；v1 只读不迁移，第一次写入时按旧前瞻数组、旧结果数组顺序补链，并以 `legacy_prefix` 标明这一前缀不是可恢复的原始交错写入历史。旧冻结记录内容保持不变。CLI 每次成功写入输出 `chain_head`，应立即保存在注册表之外，例如把注册表及该链头另行提交到版本库。之后用 `check --expect-head <散列>` 核对；仅有文件内部链不能发现自洽删掉尾部或整体重建，不能充当外部时间戳、签名或预测认证。

评测资料包每次登记或结算后运行 `check`，把其 `chain_head` 连同注册表相对路径、核对时间写入资料包 README，并保留各次历史链头。审查时使用 README 中对应版本的链头执行 `check --expect-head <散列>`，核对原件散列及命令退出码。结果追加后的当前链头应与当前注册表配对；旧链头继续保留作历史记录。

形成表达前读取已有注册表的报告。`by_contract` 保留逐题合同明细（`groups` 为兼容别名）；`pooled` 按阶次、证据类型、表达类型、理论散列、技能版本和宿主模型汇总，并将不同的预登记降级政策分开。先在每条记录内与基线配对，再按 `type` 对齐；不以基线 id 或问题文字相同为跨题条件。每条新登记的基线类型不可重复，一阶采用 `recent_state`、`trend`、`historical_frequency`、`actor_only`、`primary_circle_only`、`domain_model`，二三阶另有 `state_continuation`、`direct_long_term`、`shallower_continuation`；其他类型保留逐题结果但不进入汇总对比。

汇总的均值、配对差、较好／较差／持平条数及校准分箱都是描述统计，不能自动消除任务选择偏差或证明可迁移性。按 M6 的 F8 将降级决定限定到相同汇总组、政策和基线类型，在各月达到预登记样本数后核对持续性。受影响复杂模型保留推演用途；独立成立的简单基线和其他任务分别判断。顶层 `scenario_only` 只摘要提示存在降级组，不代表所有用途共同失效。

`disagreement` 报告登记中的分歧率：模型预测与本条登记全部基线预测都不同的记录数，除以全部基线均可比较的登记数；尚未结算的登记也计入，分母为零时为 `null`。同时列出合格数、排除数及原因，并按与 `pooled` 相同的版本、宿主、阶次、表达、证据类型和降级政策分组。未知表达、未知或重复基线类型、缺少类别空间、单位或名义覆盖率不一致的记录均排除，避免把不可比当成分歧。旧单基线记录仍可报告，评测协议所需基线数量另行核对。

比较只使用冻结的预测内容，忽略 `basis` 等说明文字：概率比数值；方向比选定类别；排序比完整有序列表；数值区间比上下界；事件时间区间统一时区后比起止时刻。类别集合顺序变化不产生分歧，区间须先满足相同单位和名义覆盖率，旧数值区间缺少名义覆盖率时保留不可比。`pooled_on_disagreement` 只对这些分歧登记已有的最新结果作逐基线配对汇总，沿用原有指标与兼容规则，并列出所含登记 id。完整排序不同而第一名相同时，`rank_top_hit` 仍可能持平；有分歧不保证现有指标能区分表现。总体与分歧子集都应报告，分歧率长期为零如实保留，分歧子集的成绩也不足以单独证明总体增益。

数值区间的 `pooled` 比较使用每条记录“模型区间评分 ÷ 基线区间评分”的几何平均，小于 1 表示模型评分较低；不混合不同单位计算原始评分均值、宽度均值或平均差。比值以对数差汇总，逐条较好、较差、持平另行保留。双方评分都是零时约定比值为 1，作为中性比较并单独计数；零除以正数为 0，正数除以零为无穷，组内同时出现这两种比值时几何平均未定义。任一评分带溢出标志时不推定精确比值；双方均溢出也不记作持平。报告用 `ratio_status` 区分有限、零、无穷、未定义及最终数值表示的上溢或下溢，不能表示的比值为 `null`。覆盖率在 `interval_calibration` 中按名义覆盖率分层报告 `observed_coverage`，仅用于校准。

旧冻结记录继续按原登记与各次回写的评分版本读取；新追加结果也保留旧表达的评分语义，不为旧记录补填名义覆盖率或重算历史评分。新回写的时间校验与旧评分版本分开记录，兼容评分不免除新 live 回写的时间要求。需要新指标时另行登记符合当前合同的新前瞻。

新 `time_window` 若预登记 `interval_score`，模型与全部基线也须提供同一 `nominal_coverage`；只登记窗口覆盖时仍可省略。既有名义覆盖率不一致的时间区间保持冻结分数，但报告将其区间评分列为 `incomparable_metrics`，不计算配对增益、几何比值或优劣票数。

## 结果到来后

F12 在真实结果可得时追加，当前回答不等到结果出现。保留支持、未支持、未决、目标失效、无法评价五种状态。目标或同一性转换不能计命中；监测离线或缺失标签不能填零；事后移动目标、期限、群体或合并路径不能救回旧成功资格。

报告的状态、评分与汇总仍采用每条前瞻的最后一次回写；`status_revisions` 另列状态曾被后续回写改变的前瞻数量、id 和转变时的 `state_history`。未决转为支持也计入；支持转为未支持再转回支持不会因首尾相同而隐藏。连续同状态回写折叠，不算改判；历史只作追踪，不改写冻结记录或重新计分。

数值概率可用预登记的 Brier 与对数损失，数值区间用区间评分并保留覆盖校准，事件时间用窗口覆盖及有名义覆盖率时的区间评分；不适用的指标保持不适用。方向型前瞻可预登记 `direction_hit`：模型和各基线使用文字与顺序完全相同、至少两个互斥类别的 `options`，各自 `value` 选其中一项。已判定结果必须给 `observed.category`；只有它与模型 `value` 相同时才记 `supported`，否则记 `not_supported`，各基线按自己的选择分别计 1 或 0。未登记类别与指标的方向记录保留定性结果，不补造分数。逐案损失不等于长期校准。

前瞻在现行响应制度下的表现、响应改变了多少结果、是否应采用响应是不同问题。没有观察到损害既不能自动判保护成功，也不能一律取消原可评价目标；因果效果另取相称证据。新结果只改变受影响依赖，保留仍成立内容。

排序表达可预登记 `rank_top_hit`，仅评价第一项是否与实际类别相同，不把排序换算成概率。模型与基线须给相同的互斥 `options`，非空排序 `value` 中的条目均取自这些类别且不重复；回写用 `observed.category`，`supported` 当且仅当它等于模型的第一项。各基线独立计算首位命中。未预登记这一指标的旧排序保持未计分。

## 能力与跟踪

教学例、合成测试与公开已知结局演示不计经验能力。前瞻是否增加价值由仓库外固定题集、无泄漏回测与真实持续注册分别检验；尚无结果时只说能力未证实。复杂模型长期不优于基线、校准恶化或群体误差集中时，依 §16.22 缩范围、降表达、优先简单基线或退役相应前瞻用途。

能力评测优先选择组织承接、制度执行、集体动态或技术故障传播等有适用机制的任务。材料须覆盖承担者与职责、容量、期限、依赖关系及近期变化；具体场景由作者确认。每条新评测登记至少使用两种不同类型的基线，先冻结选择规则与计算方法，再形成模型预测；尽可能采用有生成依据的概率或数值区间，依据不足时保留方向或未知。使用相同目标、截止、窗口、资料和评分，保存模型与全部基线一致的记录，不为提高分歧率制造偏离或事后挑题。

盲回测仅接纳结果晚于已核实宿主知识截止的事件，或作者提供且未公开的私有案例。独立组织者冻结输入包、结果包、来源与散列，答题运行只可读取截止前输入包；结果包须在运行账户或执行环境之外保存，单纯换目录不构成访问隔离。无法核实宿主知识截止或实际访问隔离时，记录为待核候选，计分资格为零。首批六案用于发现明显问题；优于基线的判断需要累积到几十条并复核样本选择、隔离、配对成绩与不确定性。流程测试单列用途与排除名单，保留原登记并依原规则结算，外部能力表不将其计入经验增益。

只有用户明确安排后续跟踪才建立相应提醒或持续任务。没有安排时，给可回写的原记录及结果判定条件，不许诺后台自动查看。用户问怎么办时接 [M7](../modules/choice/MODULE.md)，分别完成价值、代价、保护和权限判断。
