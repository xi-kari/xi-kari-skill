# 领域卡

领域卡记下一个具体任务范围里核实过的本地用法：词在这里指什么，谁对谁做什么，数字是什么口径，该用哪种专业方法，原文里哪些区别用得上，哪些话不能推出。它让同一领域的下一次工作不必从头辨认，也让同样的区别每次都被保留。卡片是上次核实的记录，不是本题证据；它不是专业标准原文，也不构成新的理论定义。实际工作入口见[领域映射](../../modules/domain-mapping/MODULE.md)。

## 两种卡片

**你自己的领域库**是主要用法。把在真实任务里核实过的机构定义、系统口径和易混点存成卡片，放在安装目录之外由你选定的目录里，以后同一领域的任务先读它。[合成示例卡](../../assets/examples/domain-card-example.md)演示一张从任务材料整理出来的卡片。

**随包样例**有三张，各自绑定公开来源里的一个小任务，用来示范写法；任务范围相符时也可以直接使用。

| 卡片 | 可以直接处理的任务 | 不能据此宣布覆盖的范围 |
|---|---|---|
| [组织与工作](organization-work.md) | 使用 Scrum 2020 语义的团队，核对职责、完成条件和共享资源安排 | 一般劳动关系、法律授权、全部项目管理或所有组织文化 |
| [教育与学习](education-learning.md) | 短课程成果说明：参与、课程完成、测评、迁移、微证书与认可分别陈述 | 对个人作全面能力诊断，认定职业执照，证明课程因果效果 |
| [技术系统与维护](technical-maintenance.md) | HTTP 服务的观测、任务结果、服务目标和故障恢复核对 | 任意协议、所有云产品、完整安全审计或实际变更许可 |

只有采用相应规则的任务才套用卡片里的词义；同名词在别处可以不同。事实已有充分领域依据而未申请正式理论实例资格时，仍可直接回答该领域问题。

卡片记的是具体机构、规则和系统的用法。理论自己对 32 个领域的定位在原文附录 D，从[领域入口索引](../domain-index.md)进入；把一个领域系统地做深并得出映射时，按[领域专论](../output-modes/domain-study.md)做，结果可以整理成卡片。

## 一次任务里怎样用

1. **开始时查。** 用户或宿主指明了领域库，就列出其中的卡片，读范围对得上的那一张。没有指明就不找，也不自建。
2. **用的时候核对范围。** 卡片的机构、系统版本、规程版本或材料期间与本题不符时，只把它当提问线索。本题材料与卡片冲突时以本题材料为准，在正文写明哪一条变了。用到卡片里与理论的对应时，先读它列出的原文小节；卡片不代读原文。
3. **结束时提出增补。** 本题核实了以后还会用到的本地定义、口径或易混点时，在对话里用一两句列出可以存进或补进卡片的条目。用户同意并给出领域库位置后才写入；不同意就不写，也不写入宿主全局记忆。[领域专论](../output-modes/domain-study.md)另把映射整理成一张卡片草稿随成果交付，同样要等用户同意才存入领域库。
4. **写入后检查。** 新建或修改卡片后运行 `check`。

`$skillRoot` 是当前 `SKILL.md` 所在目录，`$taskRoot` 是安装目录外的用户目录，路径设置见[宿主接入](../host-setup.md)：

```powershell
python "$skillRoot/scripts/domain_cards.py" --library "$taskRoot/领域卡" list
python "$skillRoot/scripts/domain_cards.py" --library "$taskRoot/领域卡" check
python "$skillRoot/scripts/domain_cards.py" list
```

`list` 给出每张卡片的标题、适用范围、更新日期和所据原文版本，供挑选；不带 `--library` 时列随包样例。`check` 核对卡头是否完整、所据原文是否仍是当前版本、引用的小节是否存在、正文提到的小节是否都列进了卡头。两个命令都只读，不写任何文件；卡片由作者用宿主的文件能力编写。检查通过只说明这些工程事实，不说明卡片里的定义正确、来源可信或对应成立。

## 卡片怎样写

文件开头三行是卡头：一行 `---`，一行 JSON，再一行 `---`，然后才是正文。少了前后两行 `---`，`check` 会报没有卡头。

```markdown
---
{"id":"hotline-tickets","title":"热线工单办理：办结口径","scope":"某市便民热线；办理规程 2026 年 4 月修订版；2026 年第一、二季度材料","updated":"2026-11-18","theory_sha256":"所据原文的 SHA-256","anchors":["2.4.3","3.3"]}
---

# 热线工单办理：办结口径
```

`id`、`title`、`scope` 和 `updated` 必填，`updated` 写成 `2026-11-18` 这样的日期。`scope` 写机构或系统、规则或技术版本、材料期间，不能写成无限适用。`anchors` 只列正文实际用到的原文小节；没有用到时留空数组，`theory_sha256` 可以省略。

正文按需取以下小节，不要求填满：

- **适用任务**：能直接处理什么，明确不处理什么。
- **来源与已核范围**：每个来源的版本、位置、查阅日期和它能支持的范围；用户材料写名称与位置。
- **词义与关系**：每条写四件事：这个说法在这里指什么，依据哪条规定或哪份材料，容易和什么混，据此能说到哪一步、不能推出什么。动作、角色和任务终点同样写。
- **口径**：字段、单位、分子分母、时间窗、缺失怎样处理，以及口径变更的日期。
- **专业方法**：这类问题在本领域该怎样核对，哪一步要交给专业方法或有权主体。
- **与理论的对应**：借用了原文的哪个区别（写小节号），对应的身份（定义对应、角色或对象实例化、部分对应、观察接口、类比候选、不对应、不适用或未知），以及对应的边界。
- **例与反例**：一个可以直接照写的输出例，几个容易混淆的反例。
- **变更复核**：什么变了要回来改卡。
- **修订记录**：日期、依据的材料、改了哪一条。改义时保留原来的说法和改的理由，不直接覆盖。

写卡时守三条：

- **语义、事实与正式资格分开。** 卡片只管词义、口径和方法；具体的人、课程、工单或系统此刻怎样，是每个任务自己的证据。未申请正式实例资格不影响专业用法成立；按 §3.4.1 登记正式转义时另列目标侧独立复核，没有复核就写待检验。
- **不替别处定义。** 一个机构的用法不推广到全领域，一份建议的词义不替代具体法规。
- **未知照写未知。** 没有材料的定义、单位、时限留空并写明缺什么，不用常识补齐。

卡片里的小节名、对应身份和这些约束是工作约定，不声称来自原文的新分类。

## 来源维护与缩小范围

卡片列出实际核过的正文位置、版本和查阅日期。在线文档未公开固定版本时如实标记，使用前只复核影响当前判断的段落，不声称锁定了未知版本。书或指南中的参考文献不自动算作已核原作。

出现以下情况时复核卡片：专业来源发布修订；机构采用另一套规则；指标或日志定义改变；同词出现新的义项；原有示例不能解释新材料；卡片所绑定的原文版本变化。新来源不可访问时标记“本次未核”，保留仍有依据的范围，不用搜索摘要补成已核正文。

卡片迫使任务删掉领域关键区别、把测量字段当成实际能力，或把技术通路当成授权时，缩小或停用相应条目。分析和方案输出本身不授权发布、排程、授证、重启、切流或修改真实系统；任务已有相应授权时按其范围继续，不因使用卡片再造一轮许可要求。是否值得保留一张卡，以任务结果和维护负担判断。
