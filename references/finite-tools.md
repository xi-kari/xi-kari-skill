# 有限模型工具

当问题中的状态、动作、任务时段或关系已经能明确列举时，使用 `scripts/finite_tools.py` 计算可复查的分块、冲突、共同动作、排程、条件组合或整链见证。它是按原文已有条件制作的派生工具，不认证理论、资料真实性、模型的现实完备性或实际效果。没有可合理列举的模型时，继续用材料与专业方法分析，不为了运行工具制造数字、状态和关系。

六个算子分别对应任务充分表示、表示损失、共同动作、联合资源条件、有限条件生成和整链共同见证。它们只实现下面明示的有限子问题；不能将一次计算说成已经实现全部修复、预测、干预或领域求解能力。人工复核场景可以使用资源算子核对时段、资格、材料与授权的合取，实际判断质量和停止通道是否有效还需独立材料。

## 直接使用

Python 3.10 以上，只有标准库。`$skillRoot` 是当前 `SKILL.md` 所在目录，`$taskRoot` 是安装目录外的用户任务目录。输入只读，`validate` 不求解、不写文件；`compute` 默认向标准输出给出 JSON，指定 `--output` 后保存为一个新的外部 JSON 文件。

```powershell
python "$skillRoot/scripts/finite_tools.py" --model "$taskRoot/model.json" validate
python "$skillRoot/scripts/finite_tools.py" --model "$taskRoot/model.json" compute --output "$taskRoot/result.json"
python "$skillRoot/scripts/finite_tools.py" --model "$skillRoot/assets/examples/finite-tools.json" --case task-partition-h1 compute
```

教学集合内的每个条目都是完整模型。使用 `--case` 选择，未选择时返回可选 ID；整个集合先作结构检查，仅计算选中条目。自己的单模型文件不需要 `--case`。

| 教学条目 ID | 算子 | 可核对结果 |
| --- | --- | --- |
| `task-partition-h1` | `task_partition` | `{a,b}` 同块，`c`、`d` 各自成块，尚不动力闭合 |
| `task-partition-h2` | `task_partition` | 四个单元素块；区分 `a,b` 的最短动作串长 2 |
| `task-partition-stable` | `task_partition` | 到稳定分块；本例与期限 2 相同 |
| `representation-two-errors` | `representation_audit` | 同纤维冲突和信息足够但规则错误并存 |
| `common-action-triple` | `common_actions` | 三状态整体无共同动作，给定观察分组后每组有共同动作 |
| `schedule-shared-capacity` | `resource_schedule` | 每个任务各自可行，共用同一时段联合无解 |
| `schedule-final-endpoint` | `resource_schedule` | 前序 `[0,1)`，后续 `[1,3)`，共同满足所列限制 |
| `condition-complement` | `condition_search` | 只有同时改变 `x,y` 才进入完整合格表 |
| `relation-local-without-chain` | `relation_chain` | 每段关系非空，中间对象不同，整链没有共同见证 |

以上均为示意资料，不是经验验证记录。

## 通用输入与结果

单模型固定字段如下，不接受拼写不明的额外字段：

```json
{
  "schema_version": 1,
  "title": "所要计算的具体问题",
  "fictional": true,
  "assumptions": ["哪些输入由调用者明确假定，真实资料来自何处"],
  "boundaries": ["这次模型没有覆盖什么"],
  "operator": "common_actions",
  "input": {
    "admissible": {"s1": ["A", "B"], "s2": ["B"]},
    "action_universe": ["A", "B"]
  }
}
```

`fictional=false` 只表示作者声明这不是虚构模型，工具不会因此认定输入已核实。现实输入应在 `assumptions` 中回指源版本、实际抽取方法与仍采用的假设；正文另行说明模型适用性。

计算结果保留完整选中模型、输入文件绝对路径、字节数、SHA-256、集合条目 ID（如有）、限定说明和实际结果。校验通过是 `valid_model`，只指类型、范围、必填项与引用满足合同；计算完成的外层状态为 `computed`，不表示可行。结果内的判断须按相应算子解释。

输入、输出的 ID 不自动注册为主张、候选或任务台账。若已有台账，可以沿用其明确标识，并在主稿中引用本次结果文件；不因运行工具重复建立一套台账。

核心值未知时不补零、不替换为正常类别。任务回答、动作资格、容量、起点、时限和关系字段的未知必须先留在正文问题表，或由作者明确建立不同假设下的模型，再分别计算。工具拒绝这些位置的 `null`；唯一有明定计算含义的 `null` 是 `task_partition` 的 `H`，表示到稳定。可选的解码器或观察不可得时省略整个字段，结果保留未评估状态。

重复 JSON 键、重复 ID/关系对/菜单值、未知引用、非有限数、整数位置的布尔值和浮点数都会拒绝。布尔与数字不互当 `0/1`；数值 `1` 与 `1.0` 作为相等的有限数处理。字符串 `"unknown"` 是一个普通字面符号，不能靠它伪装尚不知道的任务回答。

JSON 小数须能在当前数值接口中保留原十进制数值：普通 `0.1` 可用，超出精度的 `9007199254740993.0` 或下溢的 `1e-400` 会明确拒绝，不先舍入再把不同值判成相同。需要这类精度时，改用精确缩放整数并写明单位，或保留为当前工具无法计算的模型；例如大整数 `9007199254740993` 可直接使用。工具不能恢复进入 JSON 文件以前已经丢失的精度。数学上相等的 `1` 与 `1.0` 在标量回答处等价，整数专用字段仍只接受整数写法。

## 任务族等价划分

依据 §4.19 对有限任务的界定，并联系 §4.18.1、§4.18.2、§2.14。选择 `task_partition`：

- `states`：非空状态 ID 列表，最多 64 个。
- `actions`：动作 ID 列表，最多 16 个；允许空列表。
- `transitions`：每个状态到每个动作的目标状态映射。所有动作必须在所有状态上确定且全定义。
- `queries`：查询 ID 到“每个状态的已知答案”的映射，最多 32 项；允许显式 `{}`。也兼容单个 `query`，两者不能并用。
- `H`：非负整数，表示最多执行多少个动作；`null` 表示精化到稳定。

按全部查询的答案向量生成初始分块，再使用上一轮分块同步精化。输出分块、各轮历史、逐动作闭合性，以及每个已区分状态对的最短动作串、具体目标 ID 和末端不同答案。最短按动作次数计算，不代表真实耗时、费用或信息披露最少。

有限期限充分不自动等于动力闭合。空动作集只保留当前查询；空查询族没有任务区别，全部状态在一组。稳定分块只针对声明的状态域、动作与任务，不是自动发现的现实完整状态空间。随机、部分定义、依状态可用的动作及近似容差均不在工具处理范围内。

## 表示损失与解码错误

依据 §4.18.1、§5.10.2，并联系 §C.6、§C.7、§2.1.2。选择 `representation_audit`：

- `representation`：非空“状态 ID → 表示 ID”映射。
- `query`：相同状态集合的已知答案。
- `actual_decoder`：可选的“每个表示 ID → 实际输出”完整映射；省略表示未提供规则。

输出同一表示下不同答案的冲突对，以及给定规则的逐状态错误。某个纤维不可识别与另一个纤维信息足够但规则错误可以同时存在；不会把它们强制排成互斥类别。模糊纤维上的实际错误仍展示，但不再当成独立于表示损失的新损失相加。

全是有限数字时，输出每个纤维最小、最大、允许任意实数解码时的中心和最坏绝对误差半径，以及全域最大值。对已通过精度检查的十进制输入作精确有理数计算；结果的 `exact` 保留精确值，近似数值超出有限浮点范围时 `value=null`，这不是零。整数或二元输出限制需要不同的优化合同。

这项静态检查不自动判断源记录是否事时可达，也不生成传感器设计、源记录修复或领域参数估计。未提供实际解码器时，其是否正确保持未评估。

## 共同动作与给定观察

依据 §4.18.3，并联系 §12.10.1、§11.3.1、§C.12。选择 `common_actions`：

- `admissible`：非空“可信相容状态 ID → 已知合格动作列表”。各状态允许空列表。
- `action_universe`：非空、无重复的动作全集，固定空状态子族的交集约定。
- `observation`：可选的完整“状态 ID → 观察标签”映射。

计算所有状态的动作交集。交集为空时，返回包含极小的空交集状态子集及删除任一状态后的非空共同动作见证；包含极小不等于状态个数最少，也不要求状态两两已经冲突。

给定观察时，只检查每个观察组的共同动作是否非空。它不优化观察、不判断观察能否实际取得、不估概率价值。共同动作已经存在也不能据此断言所有进一步信息都没有价值：若目标还涉及动作优劣，需要另一个比较合同。给定资格不等于工具授予了现实权限。

## 联合资源与连续时段

依据 §12.10.2、§12.6、§7.3.9、§2.1.2；人工监督用途联系 §16.23、§13.11.2。选择 `resource_schedule`。这是小型离散排程器，完整搜索列出的起点菜单，不提供万能排程或最优解。

| 字段 | 合同 |
| --- | --- |
| `horizon` | 1—256 个相同长度的整数时隙，由作者明确实际单位 |
| `resources` | 最多 16 项，含唯一 `id` 和长度恰为 `horizon` 的非负整数 `capacity` 日历；允许无资源 |
| `tasks` | 最多 20 项，允许空任务集；全部任务都必须完成 |
| `search_budget` | 0—1,000,000 次候选起点尝试；这是计算预算，不是现实资源 |

每个任务必须完整提供：

- `id`、正整数 `duration`、无重复的整数 `start_slots`，以及 `ready_at`、`end_by`。时段为 `[start,start+duration)`，不可拆分、不可抢占；开始不早于就绪，完成不晚于截止。空起点菜单合法，表示此任务在模型中没有允许的起点。
- `demands`：覆盖每一种资源的固定非负整数需求，不使用的资源也明确填 `0`。
- `predecessors`：必须完成后才能开始的任务 ID。不得自引、引用不存在的任务或形成循环；循环不由工具改成别的依赖语义。
- `eligible`、`authorized`、`materials_ready`：分别声明资格、有效授权、所需材料是否就绪，必须为明确布尔值；不是来源认证。

共同容量按每个时隙累加，独立任务可以重叠，输入顺序不暗含串行执行。前序和所有末端任务的截止共同生效。成功返回完整开始/完成时间及资源占用见证；工具不处理人员替代分配、抢占、随机工时、跨单位换算或自动放松限制。

结果分为 `feasible_in_model`、`infeasible_in_model`、`search_incomplete`。前者已有满足全部编码限制的见证；第二种有局部无起点证明、总量证书或完成了穷举；第三种仅表示预算用尽，不能称为无解。`tasks_without_individual_start` 是局部检查结果，不是最小冲突核心。空任务集无需搜索即给空排程。

搜索前先做一项总量检查：每个任务的所有允许起点都落在“最早允许开始到最晚允许完成”的区间内；若某段 `[a,b)` 内必须完成的任务对一种资源的需求总量（需求乘时长）超过该段日历容量之和，就不存在排程。此时返回 `capacity_certificate`，写明资源、区间、所需量、可用量和相关任务，不再搜索。例如 10 个单位任务都须在 9 个单位时段内完成而容量为 1，直接判为无解。这一检查只给出充分的无解证明：没有证书不表示可行，仍由完整搜索判定；证书也不是最小冲突集。

把最终起效环节纳入任务，应来自实际任务合同。首端完成不能自动代表末端完成，工具也不会凭空扩张用户要完成的终点。时间算够不证明复核可靠、材料真实、停止权有效或实际介入已经到达。

## 有限目标条件组合

依据 §2.13、§2.14、§4.18.3、§12.9、§12.10.2、§14.4、§14.8。选择 `condition_search`：

- `variables`：1—16 个条件，每项有 `id`、已知 `current`、1—16 个无重复已知标量组成的 `values` 菜单，以及布尔 `mutable`。当前值必须在菜单中。
- `admissible_assignments`：至多 4096 条完整赋值，每条覆盖所有条件，值来自相应菜单，无重复。
- `admissible_table_complete`：必须显式为 `true`，表示调用者承诺合格表在给定菜单内完整。只有这个合同成立，未列组合才可视为不合格；资料不全不能假装成闭世界模型。
- `search_budget`：0—1,000,000 次完整组合检查；可变条件菜单乘积不得超过 1,000,000。

工具枚举给定菜单，固定条件保持当前值。全部搜索完成后返回全部找到的合格赋值，以及按“发生变化的条件 ID 集合”判定的包含极小候选。已经合格时保留空变化方案。两个改动方向不同的候选可能都极小，即使一个改 1 项、另一个改 2 项；不宣称最低成本、最少改动数或幅度最小。

预算耗尽时，仍展示已找到的有限见证，但 `inclusion_minimal_changes=null`，不凭局部搜索声称全局极小。整个合格表都先验证，未被搜索访问的坏记录也不能潜藏。

这项工具不从目标猜测干预效果，不创造资源或降低保护标准。调用者应把不能改的条件设为固定，并用独立依据建立合格表；缺失的领域因果关系不能由枚举代替。

## 端到端关系链

依据 §2.4.2、§4.18.4、§C.12、§2.3。选择 `relation_chain`：

- `layers`：2—32 个按顺序排列的层，每层有唯一 `id` 和无重复字符串 `members`；允许某层为空。
- `relations`：每两个相邻层恰有一个关系，顺序与层对应，每项含唯一 `id`、`from_layer`、`to_layer` 和最多 4096 对 `[来源成员,目标成员]`。成员必须存在于该关系的明确层中，关系对无重复。

计算相邻二元关系的自然连接。一个中间对象必须在同一个中间层以同一成员 ID 出现，不能将不同人群、版本或情境仅因名字相似就拼接。不同层的同名 ID 仍属于各自层；对象同一性由建模者基于材料建立，工具不替其判断。

成功输出一条从首层到末层的完整见证。无路则输出逐层可达集合与第一次空连接的来源证据。只有每个局部关系都非空、整链却没有共同路径时，`local_existence_counterexample=true`；某关系本身为空不满足这一反例的局部非空前提。

这是对给定有限关系的判断：局部存在不够推出整链存在。它不是现实因果机制证明，也不能否定独立识别的总效应。随机关系、关联强度、跨样本总体推断和未观察的连接不在工具处理范围内。

## 文件边界与使用结果

输入不超过 2 MiB，单项输出不超过 32 MiB；超过明确拒绝，不静默截断。输出限额按包含末尾换行的 UTF-8 字节数在编码过程中检查；冲突对或见证重复展开而超限时停止，不先构造全部巨大 JSON 字符串，不向标准输出留下半份结果，也不创建目标文件。通用 ID 列表最多 256 项，标识最多 256 个字符；`assumptions` 与 `boundaries` 是说明文字，各最多 256 条、每条最多 4000 字符且不重复；各算子有上述更窄上限。可计算规模限制的是机器合同，不限制研究正文深度。

输出先经 `xikari_paths.require_external_output` 核对，拒绝安装目录及指向安装目录的父路径。没有覆盖选项；已有文件、符号链接、同名写锁均拒绝。新输出使用独占锁、同目录临时文件、刷新和不覆盖的原子创建；竞争写入者的内容保留。文件系统不支持硬链接时安全失败，不退回可能覆盖的写法。锁不自动当成过期锁删除。

将计算接回成果时，正文先说明解决了哪个具体问题、结果及限定，再链接模型与见证。保留模型外的不确定性、独立有效的领域结果与需要进一步材料的问题。程序成功只证明这次在声明合同内完成计算；测试反例和教学例通过也不代表现实增益。
