# 公开离职：从冻结输入到到期回写

读取者：第一次组合 M0—M9、使用规则卡和 `forecast.py` 的使用者，以及核对交接物的反方审查者。本例展开原文 §10.11、§11.11、§12.13 的示范结构。公司、人员、日期、工时、人数、来源、输入和到期结果全部虚构；它们只用于展示如何完成和失败，不是作者的私有经验，也不进入外部能力评价。

以下顺序把“结果前可得输入”与“到期结果”分开。同行 JSON 是可运行的教学数据，不能用同一实例同时充当盲测材料和答案。真实回测应在仓库外隔离结果包。

## F0：适格检查与问题合同

原问：“员工公开离职后，团队还会有人走吗，公司应该怎么做？”请求含条件前瞻 R4 与有限选择 R5。为使判断可失败，拆成三个独立登记：O1 是高负荷的直接后果，O2 是负荷和外部机会改变行动集合后的退出，O3 是局部适应能否完成制度化接续。阶次是推演责任，不是三个自然阶段，O2 与 O3 可以有相同截止日。

冻结输入截止为 2024-09-01 10:00 UTC，登记时点为同日 12:00 UTC。基线时点为 2024-08-25 10:00 UTC。对象为虚构 TEAM-A 的原 20 人队列；这是触发事件员工离开后冻结的名册，不含该已离职员工。K 是“共同项目交付、明确排班与可追踪职责接口”。后续员工退出不自动改变队列分母；如公司对象实质转换，应判断原目标是否失效，不能换成剩下员工继续报成功。

| 登记 | 可判定目标 | 窗口终点 | 登记方向 |
| --- | --- | --- | --- |
| O1 | 完整原队列的两周周均实际工时是否仍高于 48 小时 | 2024-09-15 | 条件方向为仍高于 48 小时 |
| O2 | 原队列自愿离职是否至少 4 人 | 2024-11-30 | 条件方向为达到至少 4 人 |
| O3 | 是否完成两个复核周期且覆盖全体的排班、申诉责任和可用退出制度写回 | 2024-11-30 | 条件方向为未完成全部条件 |

这些阈值是本教学任务的事前定义，不是理论给出的普遍标准。真实任务若只有“关系改善”而没有可判定目标，停在 R3；本例因已给出目标、范围、期限和完整虚构标签，可继续展示 R4。

| TEACH-IN-03 | 管理层公开否认部分指控，宣布两周后考虑试点；截止前无已执行新预算、排班或申诉规则 | 支持“计划中”和尚未见执行；不证明永远不执行 |

新增未知：平台推荐规则、管理者私下决策、未来岗位是否撤回、照护支持期限。资料冲突与缺失分别保留；后续任何真实中间观察只能用于新冻结版本，不能倒灌本快照。

九轴尺度同时冻结：A 为 20 名员工的固定队列、逐人记录及其分布，均值不替代个别负担；X 为团队工作边界、家庭照护接口和指定平台；T 为四周输入观察、两周直接后果及三个月后续窗口；O 为员工角色、团队、公司管理层与制度安排；C 为发布事件、互动与负荷机制及制度接续，尚不提出系统总效应；R 为逐人排班与匿名表达，聚合时保留 5 人未答和来源限制；I 为员工、照护依赖者、交接承担者与未覆盖者，外部公众只记录可见传播；N 为团队嵌套、跨圈层成员重叠、社群与平台桥接；J 为教学分析、无现实执行权限，扩大观察范围不扩大处置权。

## F3：对象、行动者与状态

员工同时属于团队、家庭照护关系和职业社群；团队嵌套于公司；平台桥接外部公众。管理层与团队在资源分配上可能冲突，在声誉维护上又有共同约束。只保留这些确实回答问题的圈层，不另加没有独立通道的对象。

行动者慢变量包括岗位技能与照护责任，中变量包括合同和信任，快变量包括注意与即时情绪。M 通道记录工资、工时、岗位和照护资源；Ψ 通道记录尊严、信任、身份和公开评价。12 人的信任报告只支持相应位置。

团队已有 S3 候选迹象：工时负荷、申诉执行和交接可能连通。但输入没有两类约束相互强化的充分通道证据，正式原型保持 `unknown`。不能把这改叫 `mixed`。若确需正式 S3 分类，应补齐原文 §8.2.1 运行记录；本例直接使用已知变量继续，不让原型成为强制前置门。

## F6：三阶路径、谱系与停止

第一阶从冻结现实教学输入展开：P1-load 为未减载导致高工时持续；竞争路径 P1-relief 为实际补位和减载；平台舆论消退与放大作为并行外部情景，不能代替工时结果。

第二阶以“第一阶高负荷持续”的模拟状态再入，继承信任来源、机会撤回和容量未知。P2-exits 为真实外部桥接扩大退出集合并出现连续离职；竞争路径为实际试点降低退出动力，或照护与岗位条件使机会不能转化。父运行、父路径分别为本教学运行和 P1-load；模拟再入不说明 P1 已经发生。

第三阶以第二阶的适应过程为模拟起点：P3-local 为局部试点停在组织层，没有完成全体覆盖的制度接续；竞争路径为规则、责任、执行和可用退出实际闭合。保留高后果支路“表达受压、无法退出者负担增加”，只作为保护与复核候选，不赋予编造概率。第三阶后停止；其未解决未知不因叙事完整而消失。

四种分叉分开处理：管理指控真假属于事实不确定，沉默来自恐惧还是策略属于机制不确定，是否接受外部岗位属于选择不确定，招聘冻结属于扰动。分别采取核验、区分性观察、保留行动集合和压力情景，不合成一个百分比。

合并规则在展开前固定：同一 K、同一目标口径、关键状态等价且后续行动与约束相同才合并；家庭支持与制度修复即使都降低离职，也因接续不同不合并。剪枝只移除不适用对象域或完全重复的分支，保留理由；低概率或概率未知不能单独删除高后果路径。没有区分信号、K 失效、敏感性全面翻转或深一阶无独立问题时，停止相关支路。

## F7：早期、反向与否决信号

| 路径 | 早期信号 | 反向信号 | 复核与否决 |
| --- | --- | --- | --- |
| P1-load | 排班未减、交接无人补位、等待和恢复被推迟 | 实际补位并降低完整队列工时 | 达到两周窗即核标签；工时记录口径变化则暂停 |
| P2-exits | 实际面试或录用桥接、工时不降、申诉未执行 | 可验证减载、申诉试点、机会撤回 | 桥接条件改变即开新冻结；原登记保持 |
| P3-local | 局部执行存在但全体责任与退出条件未落实 | 两个周期、全体覆盖和可用申诉均得到独立确认 | 保护被突破、退出受阻或来源失真触发否决复核 |

离职人数本身是 O2 结果，不被当作唯一早期信号。发现、核验、触达、理解、筹集资源及起效的总时间须早于拟保护对象的损害窗口；提前看见信号不能代替实际保护。观察触发复核，不自动授权动作。

## F8：基线与表达

O1 使用最近状态和工时趋势，均指向仍高于 48 小时。O2 分别比较不继续递归的历史状态延续、直接远期判断和一阶加简单延续：前两者按历史与同类 1/20 指向未达 4 人，浅阶延续指向达到 4 人。O3 的三种基线均指向未完成全部制度条件。这些基线使用同一输入截止、队列与目标，不能在结果后调换。

本例没有真实概率估计、先验或校准依据，不给百分比，不计算 Brier 或对数损失。方向只是教学设定的可失败表达：O2 即使有负荷和桥接理由，达到 4 人也未获统计可靠性保证；真实任务若这些材料不足以识别方向，须返回 R3。本例不将路径研究优先级称为概率排序。

## F9：登记与冻结

同行目录 `forecast-public-resignation/` 提供三份 `order-N.json` 和三份 `outcome-N.json`。每阶有自己的 ID、目标、期限、范围、表达、信号和基线。工具创建实际 `registered_at`，历史教学 `created_at` 不冒充真实事前登记；`evidence_kind=teaching` 使其不可进入真实能力结论。

在技能根目录运行以下 PowerShell 命令，注册表路径须位于技能目录之外，并使用一个新文件名：

```powershell
$registry = Join-Path $env:TEMP ('xikari-resignation-teaching-' + [guid]::NewGuid().ToString('N') + '.json')
1..3 | ForEach-Object {
  python scripts/forecast.py --registry $registry register --record "cases/forecast-public-resignation/order-$_.json"
}
python scripts/forecast.py --registry $registry check
```

register 完成后不能修改目标、窗口、范围或基线。变化只能新建 ID 再冻结，不能以更有解释力的结果后故事代替旧登记。

## F10：六类方案比较与明确推荐

规范前提是减少不必要负担、保护表达与退出、保留服务和照护连续性，并使成本留在有责任与资源的位置。所有方案共用 2024-08-25 基线，关联 O1—O3；受影响者为原员工、交接承担者、离职者、照护依赖者及未进入试点者。保护底板为不报复、不强迫披露私人资料、不削弱必要支持、不把减负转为同事或家庭无偿补位。只要底板不满足，不以平均收益通过方案。

| 类别与具体方案 | 路径与分配后果 | 信息价值、可逆与锁定 | 成本与最坏可接受结果 |
| --- | --- | --- | --- |
| A 维持现状：继续原排班、既有管理与公关回应 | 可维持短期交付，P1/P2 仍在；成本主要落在员工和家庭 | 新信息低，旧承接持续耗费资源并可能锁定 | 原排班与公关预算持续投入；不可接受持续超载或压制申诉 |
| B 主动行动：立即全体减载、增加补位并改申诉职责 | 若执行可截断 P1 并减弱 P2；公司承担资源成本 | 改变多项条件，归因较难；人员和职责重排可部分回滚 | 需要新增预算与人员，不能重复承诺同一补位；最坏只容许短时、可补救的交付下降 |
| C 延迟行动：延后重大重组两周，保留必要保护并补齐材料 | 保留选择，但延迟本身增加负荷与退出机会 | 信息价值取决于能否取得排班和真实机会资料；期限明确 | 调查和临时保护成本；若等待造成不可逆损害则不再可接受 |
| D 试探行动：自愿、可退出的两周工时与申诉试点 | 以实际减载和执行记录区分公关与有效改变；公司提供独立补位 | 能区分组织桥接；范围和回滚可核实，不把参与者当校准耗材 | 限定补位与处理资源；最坏为无改善但不增加原负担且可停止 |
| E 退出或转移：允许成员自愿转岗并提供可验证接收 | 降低部分人的退出成本，可能加重留下者交接；接收方须有能力 | 转移可显示替代通道，个人决定不保证可逆 | 公司与接收方承担接续，照护与弱势位置另保；不得接受无承接断裂 |
| F 不行动：当前不启动结构动作，只保持已有必要保护与观察 | 不新增重组，其他成员、资源和时钟继续变化；不等于维持原全部干预 | 仅观察可减少越权，无法主动区分某些机制 | 保持观察与既有责任；持续伤害或法定义务不能因“不行动”被忽略 |

| 方案 | 执行者、权限状态与资源前提 | 停止、回滚与补救 |
| --- | --- | --- |
| A | 原责任团队；本例未给真实执行授权，既有角色名不代证 | 负荷或保护越线即复核；恢复到可承受排班并补偿受影响工时 |
| B | 有明确预算与岗位权限的主体，加受影响者程序；资源和权限均待核 | 若补位不到位或外包成本增加则停扩；保留旧接口，恢复职责并补救误配 |
| C | 有权决定等待与临时保护的主体；限定两周且明确补证负责人 | 伤害窗口早于两周则停止等待；转保护性措施并承担延迟损失 |
| D | 经具体授权的试点负责人、独立申诉接口与自愿参与者；独立补位必须先到位 | 参与者退出、隐私泄露、负担转嫁或无实质减载即停；恢复原岗位选择并补救暴露和损失 |
| E | 员工自主决定、原方与接收方各自有权的责任者；真实岗位和保护已运行 | 接收承诺失效则暂停；可回滚时保留原接口，不可回滚风险事前说明并安排接续补救 |
| F | 原有责任主体维持保护与观察，不获得新的结构干预权 | 到期、持续伤害、来源新证据或退出受阻时重新开启比较；不履责造成损害仍需补救 |

当前分析推荐为 D：在独立补位、真实退出与具体授权得到核实后，以两周试点区分关键组织桥接，并把 E 作为自愿者可选的保护性接续。二者不能重复占用同一补位；联合容量不足时缩小试点而不是把缺口交给留下者。B 的资源与权限尚不明确，A 无法处理已知负担，C 只能有限等待，F 不能回避持续伤害。

最强反对意见是试点拖延全体改善且可能选择性照顾容易成功的位置。回应是公布覆盖边界、保护未参与者、事前冻结停止和扩展条件；若不能做到，撤回 D 的推荐，转向有权主体可承担的普遍保护。上述为供审议的分析推荐，不是执行指令；现实采用仍需 N、PF、J、O 和 C12。教学案例不执行这些动作。
