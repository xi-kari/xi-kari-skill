# 一至三阶推演协议

三阶不是把“短期/中期/长期”换三个标题，而是连续状态转移：后一阶必须由前一阶的真实写回、资源变化、反馈或制度化条件生成。推演是条件模型，不是现实事实或确定预言。

## 阶次定义

### 一阶：直接状态后果

记录事件或动作对当前对象、关系、资源、信息、能力、风险或受影响位置的直接改变。必须写明发生窗口、载体、触达字段和最小证据。没有通道或执行证据时，一阶只保留为条件情景。

### 二阶：行动与生成条件变化

追踪一阶结果怎样改变行动者的选择空间、资源分配、反馈回路、策略、信任/预期、替代路径和下一事件的生成条件。二阶不是“影响扩大”，而是可观察的中介状态变化；要写谁承担成本、谁获得信息、哪些通道被堵塞或开启。

### 三阶：制度化、锁定、逆转与跨圈层溢出

只有二阶已经形成可重复写回、角色/规则/资源的稳定承载，或存在明确的跨圈层桥接时，才进入三阶。三阶可以走向制度化、自我复制、路径锁定、逆转、分裂、退出/转移或跨圈层溢出；并非必然升级，也不代表价值更高。

## 节点合同

每个阶次的每个节点都填写：

| 字段 | 要求 |
| --- | --- |
| `input_state` | 进入本节点前已冻结的状态 |
| `state_delta` | 本节点新增或失去的状态项，不能只写情绪性结果 |
| `carrier` | 承载变化的行动者、资源、信息、角色、规则或桥 |
| `scale_or_circle` | 发生层次、圈层和跨层边界 |
| `clock` | 即时、互动、组织、制度或长期时钟及滞后 |
| `conditions` | 必须成立的事实、权限、容量和环境条件 |
| `evidence` | 现实来源、用户材料、v8.2 锚点或明确的条件假设 |
| `countermechanism` | 能阻断、反转或解释同一结果的竞争机制 |
| `failure_condition` | 不成立、停止或降档的可观察条件 |
| `early_signal` | 最早可观察的支持信号和反向信号 |

`evidence` 必须说明身份；v8.2 锚点只能支持结构约束，不能单独证明现实发生。

## 路径规则

1. 先声明基线状态和事件截止点，再列一阶节点。
2. 二阶只能从已成立的一阶节点出发；若一阶为 `not_supported` 或关键条件缺失，二阶只能写为另一个条件分支。
3. 三阶必须引用二阶的状态增量和写回证据，并说明制度化/锁定/逆转/溢出是哪条桥产生的。
4. 每条路径至少保留一条竞争路径；若某一阶被反向机制击穿，终止该路径并保留停止原因。
5. 同一事件不能未经说明同时更新所有尺度；检查容量、过滤、延迟、恢复和边界损耗。
6. 结论使用条件语气：若条件集合 `C` 在窗口 `T` 内保持，则状态转移 `ΔS` 的可能性上升；出现失败信号 `F` 时停止、降档或切换。

## 不适用情形

纯定义、翻译、算术、代码、静态事实和没有真实状态变化的问题，输出“三阶推演不适用”，解释缺少哪种动态载体。不能为了形式完整制造制度化或跨圈层后果。

## 终止与回写

推演结束不是写满三层，而是达到：路径终点、明确停止条件、不可判断区、可观察回写信号和下一次复核窗口。现实新证据出现时只更新被触达的节点；不要把旧情景自动升级为新事实。
