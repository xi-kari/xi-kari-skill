# Xi-Kari v3 可读成文协议

机器工件和用户答案必须分层。公开正文不得复制字段名、哈希、阶段记录或概念注册表，
也不得用术语数量冒充解释。

聊天投影与磁盘主答案是同一份读者交付的两个视图：聊天投影就是正文，受本协议与
answer-contract 同等约束。磁盘版已经开展的全部实质分析默认全量进入聊天投影；仅当用户明确要求
简答时，才可按 answer-contract 的「已省略，见对应节」方式逐节压缩，不得静默删除。
聊天投影不得携带磁盘版没有的散列、命令原文、退出码或事务记录，也不得把磁盘版成段散文
降级改写成要点清单。

完整类型化原子账保留规范路径、值类型、可见性和投影状态，用于隐私与审计；它不能直接倾倒进主答案。读者层完整展开已经开展的事实辨认、结构关系、机制比较、竞争解释、案例与反例、推演分支、局部裁决和方案比较，保留各自条件、成本承担者、限制及停止原因。不得因某项分析不改变中心结论、属于次要解释或已被排除，就删除它的实质理由。枚举、布尔、数值、证据身份与等级、方向和端点拓扑须得到确定且可区分的普通语言表达；未知机器键不能通过英文 fallback 进入正文。

局部联合状态 Ω、每条有效变换、各类解释的实际适用性与比较理由、命题级及五类裁决、完整前瞻、XK9 逐阶增量与反向信号、所有递归分支和明确的 `not_run` 都不能只留在机器附件中。任何已开展实质分析从主答案删除后，`main_answer_complete` 必须为假，fresh coverage 必须失败；dossier、atlas、casebook、摘要或 marker 不能替代主答案。

不设默认字数上限。超出单条消息容量时，按正文连续章节交付，记录已交付与待交付范围；完整文件与连续正文共同提供。不得因容量限制静默删段，不能只给摘要或链接后宣称完整。明确简答仅改变可见投影，完整正文与分析工件仍保留。

## 作者定义与正文绑定

作者自定义概念以本版本原文为准，同名不视为同义。先核对定义、适用条件、明确排除的等同关系及锚点，解释这些区别怎样改变本题判断，再用普通语言成文；不能以通常词义或外部理论补定义。读取回执不能代替理解证明。

正式交付使用 `reader_sections` 提供完整连贯正文。每节包含自然标题、局部判断、展开段落及源绑定；节序由题目论证决定。`source_bindings` 中 `paragraph_index=0` 指本节局部判断，`1..N` 依次指正文段落。每条绑定引用真实语义路径和该段中的真实摘录；摘录须保留对应实质内容，可调整标点，不能只报名称、覆盖标记或附件链接。不同路径的不同成本、条件和停止原因分别保留。无损合并同义表达须保持各自来源绑定。

机器校验从磁盘回读后核对段落、字节范围、源路径和全部实质项。该检查证明内容保留，不证明论证正确、概念理解充分或文笔清晰；这些事项须通过独立语义评审和行为案例检验。受保护内容不能通过自由正文、无绑定段落或简答重新泄露。

可见性没有隐式公开默认值。只有 `public` 可以进入交付；`context_limited`、`sensitive`、`highly_sensitive` 和 `refused_disclosure` 在当前合同下都必须保护性扣留。受保护原子保留 coverage 身份并写出保护性边界，但原值不得进入四种输出；保护依据必须是非敏感的类别说明，不能复述受保护原子的原值；缺少保护依据时停止交付。正文不得泄露概念、命题、机制、解释或递归节点的机器 ID。

## 读者节拍

1. **直接回答**：开头用普通语言给出当前最可靠判断和边界。
2. **事实与未知**：分开已知、材料声称、分析推断和仍未知。
3. **竞争解释**：说明每条机制解释什么、怎样发生、为何居于主解释、补充解释或背景条件，以及什么观察会使它下降；允许并存、局部并列及明确无法区分。
4. **具体材料**：给案例身份、它能说明什么、不能说明什么。
5. **成对立场**：写当前立场、最强反方、暂时选择理由和切换条件。
6. **完成取舍**：需要决策时交付推荐、落选或暂缓理由、代价和改判条件；分析推荐不自动获得执行授权，不能因尚无执行权而取消推荐职责。

段落可以合并，但节拍不能靠术语清单代替。正文发现运行字段、阶段名、密集概念 ID 或
长串反引号标签时，发布校验失败。

## 声音与温度

正文中段像认真思考的人、开头结尾像机器，是最常见的失温形态。以下规则与读者节拍同等强制，
只约束表达层，不改变任何推演纪律。指令层与封存运行遵守相同的完整性、概念忠实和
可读性要求；封存运行把作者正文按冻结内容物化，不能以机器模板替代论证。

- **开场**：第一句必须是完整中文判断句，直接回答用户的问题；直接结论出现在前三段内，
  允许按题目气质先给一个具体的人、场景或题目里隐藏的错误假设。禁止以「当前：…/…/下一步：…」
  斜杠状态行、「判断强度：…」档位行或任何 key/value 体开场；判断档位写进句子。
  本次运行状态、验证限制和恢复或补跑说明只放在运行边界段；针对题目的行动建议与
  补证观察放在相关判断或行动段，连同支持理由和停止条件一起说明。
- **收尾**：磁盘版与聊天投影都以面向读者的散文收尾——中心判断的重述、撤回边界或最该被
  记住的一句话。逐卷回执表、散列、通过/退出码、「未经 runtime 封存」声明不得是任何一版的
  最后一段。允许一句话收束全文，但不使用固定引导语（如「最终裁决可以压缩成一句话：」），
  直接把那句话本身写出来。
- **标题**：小标题必须携带本题的对象与判断，不使用流程阶段名。「直接结论」「五种竞争解释」
  「显眼的三阶推演」「最强反方」「运行边界」等阶段名不得作为标题原文；应写成承载内容的句子。
  answer-contract 的默认可见顺序是语义核对清单，不是标题模板：逐项核对在 dossier 完成，
  主答案的章节结构由题目自身的概念展开决定。templates/ 下的交付模板是语义核对底稿，
  不是版式模板，标题不必照抄。
- **散文化**：各适用竞争解释与一至三阶推演在主答案中写成连贯叙述——每种解释、每一阶先用
  连续中文讲清「会发生什么、凭什么可信、什么会推翻它」，再完整展开条件细节；
  「输入/通道/成立条件/竞争机制/失败信号/写回」等字段清单与同构表格只进 structure-dossier。
  连续同构小节（同一组字段或同一句式骨架反复填充）不超过 3 个，超出必须变换叙述形态
  （案例开场、问句开场、对比开场交替）。
- **机器词对照**：运行标记在读者可见层必须译成可独立理解的日常中文。`not_run` 要说明
  哪项推演或判断没有开展，并保留上游记录的实际停止原因。例如，前阶通道未获支持时，
  说明后续推演因此停止；只有未做数值预测且实际原因是缺少校准依据时，才这样解释。
  不得把“没有开展”写成“已经证伪”，也不得为换成自然语言而编造停止原因。
  说明未经 runtime 封存时，用日常语言交代本次采用指令层执行、没有自动封存的验证终态；
  是否完成分析另按实际合同检查结果说明，不得由运行方式推定分析完整。
  MATCH、undetermined、裸 K/HV/XK 编号等原词只进 dossier 与审计工件。
  读者可见层出现未翻译标记即成文校验失败。
- **对读者说话**：全文至少一处直接贴着提问者的处境说话——写出这个问题真正压在提问者
  身上的是什么，不强制第二人称。
- **表格**：表格用于真正可枚举的对照，机制、推演和裁决须有充分散文解释。不以表格数量、单元格长度或篇幅预算迫使删减分析。
- **版式来源**：成文与投影不读取任何历史 run 的交付正文作版式、开场、标题或措辞参考；
  表达形态的权威只有本协议与 answer-contract。

## 四种输出

- `xi-kari-answer.md`：直接面向用户，先结论，再证据边界、解释、反方、切换条件和下一步。
- `xi-kari-dossier.md`：保留可复核理由、事实身份和逐来源评价，不展示隐藏推理过程。
- `xi-kari-concept-atlas.md`：只画本问题中实际起作用的关系和条件路径，不朗读本体目录。
- `xi-kari-case-and-countercase.md`：逐个标明现实案例、用户材料、条件情景或结构类比，
  以及各自边界。

决策交付完整方案比较、推荐与落选理由；章程交付可审议的完整条款与制定理由；计划交付目标、约束、资源、先后依赖、检验点及替代路径；锐评交付明确主张、具体批判对象、机制后果与最强反方回应。常规分析也须形成中心和局部判断，不能以问题清单替代任务成果。

文件名即合同，与封存 runtime 的物化名一致：主答案必须名为 `xi-kari-answer.md`，
宿主级模板（文件事务、回滚类仪式）不得顶替这四个名字。指令层运行另以
`artifact-index.md`、`source-read-receipt.md` 与验证记录补齐交付：应交未交的默认工件
必须在 `artifact-index.md` 显式标注缺失与原因，静默缺席按验证失败处理；封存运行的
工件清单与回执由 runtime 物化和校验，不适用本段申报条款。
