## 4.15　组合条件与证据路线

根实例与附加条件的关系可以压缩为下列条件树：

G1-instance + 对象/变量桥 + G2-instance
  └─ 指定组织依赖的通道候选
      ├─ + 返回通道与阻断反事实
      │    └─ 有效反馈
      │         ├─ + 当前更新载体 + 多轮调用与任务比较（§4.5）
      │         │    └─ 载体传递型反馈介导学习候选
      │         └─ + G3-instance + 可保留更新 + 重复轮次
      │              └─ 历史增量型反馈介导学习候选
      └─ + G4a/G4b + D3/E5 映射
           └─ 闭合失败或对象/干预转换候选

G2-instance + 同型需求/容量映射
  └─ 瞬时过载候选
       ├─ + 当前载体 + 跨窗累积/恢复与因果比较（§4.5）
       │    └─ 载体传递型累积损伤或迟恢复候选
       └─ + G3-instance + 历史载体
            └─ 当前状态之外的历史增量型累积损伤或迟恢复候选

D1 + V + D + R + 下一轮 + 重复轮次 + 漂变竞争
  └─ 变异—差异保留—再生产模式
       ├─ + G2-instance → 指定保留/再生产机制
       └─ + G3-instance → 跨轮历史路径候选

只列G实例名称不构成机制的充分条件；相应附加条件、方法门、桥接证据和适用边界也须成立。条件完整时，按具体合同登记有限结果；条件不全时，指出缺口及它阻断的结论，不撤销已有独立依据。即使 G1—G4 的某组实例全部通过，也不推出 S0—S6 阶段、方向、价值、责任、选择或授权；这些结论分别需要自己的分类、规范和程序合同。
