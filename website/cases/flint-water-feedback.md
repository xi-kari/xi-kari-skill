# 弗林特饮水投诉：收到、回信和结案，各说明了什么

居民的投诉到了，机构也回了信。这能说明投诉改变了什么吗？美国环保署监察长办公室在2018年和2022年两次审计环保署对弗林特饮水危机的应对与整改，留下了一组可以逐项对照的记录。

## 投诉到了之后

2014年4月，密歇根州弗林特市的供水系统改从弗林特河取水。处理河水的工艺里没有防止含铅部件腐蚀的方法，铅开始渗入饮水；居民随后陆续反映水质问题。[1，第1页]

监察长2018年的报告统计：从2014年5月到2016年1月环保署发出紧急行政命令，环保署第五区（辖区包括密歇根州）的工作人员收到87件有关弗林特饮水的居民投诉，其中30件提到铅。第五区官员用格式信回复，建议居民去找州环境部门或弗林特供水系统的工作人员；有6件的回复晚了一年以上，另有11件查不到回复记录。第五区没有归档整理和回应投诉的系统，也没有把投诉或来电的数量当作供水出问题的指标，因此无法评估事态的严重程度。[2，第23页；1，第3页、附录A第21—22页]

第五区工作人员对审计人员说，居民对水的投诉与含铅量通常关联很小，甚至没有关联。监察长不同意，认为这样的投诉量本应引起警觉。[2，第23—24页]

## 四年后的复查：两个入口，两种结果

2018年的报告提出九项建议，第8项要求环保署建立一个系统来追踪居民投诉、评估投诉所涉及的风险并推动解决。环保署后来出具证明，称九项整改都已完成；监察长2022年复核后不同意其中三项（第1、6、8项），认为不该在审计跟踪系统里把它们关闭。[1，第3—4页]

就第8项，监察长分开检查了环保署接收公众线索的两个入口：

- **安全饮用水热线**，由水务办公室管理。2019年制定的处理规程要求追踪经热线提出的关切、评估风险，并确定和记录每条线索的处理结果。监察长认定这回应了建议。[1，第15页]
- **“举报违法”系统**（Report a Violation，简称RAV），由执法与合规保障办公室管理，2006年启用，接收各类环境线索，饮水线索也可能从这里进来。协调员能查到线索转给了谁，操作人员能审阅和转交线索、生成报告、开启或关闭案件，后来还能上传照片和视频；但系统没有评估线索风险、追踪处理结果的功能。[1，第14—16页]

监察长的判断来自对规程文本、操作程序和系统功能的核查，以及对工作人员的访谈；报告没有给出任何一条线索的实际处理结果。[1，第5—6、15页]

## 机构的异议，和后来的结果

监察长在报告草稿里建议给RAV加上对每条线索的风险评估和结果追踪。执法与合规保障办公室不同意：饮水线索已有热线规程处理，再改造RAV是重复投入；RAV每年有14,000条线索（热线为5,000条），没有资源逐条处理；多数线索转给了州，要各州回报结果负担不小，环保署有没有权这样要求也不清楚。监察长把建议收窄为只针对环保署自己留下处理的线索；报告发布时，这项建议列为“未解决”。[1，第16—17页、附录B第24页]

两个月后，该办公室接受了收窄后的建议，计划在2023年4月30日前完成，监察长把它改记为“已解决”。[3][4] 在这套审计用语里，“已解决”指双方就整改方案达成一致，整改本身仍待完成。[1，第17页] 本页所据的材料到此为止：没有记录这项计划后来是否落实，也不代表这些系统今天的状态。

## 用“有效反馈”读这些记录

《Xikari-条件结构与转化论》§3.3的定义是：

> 先前状态或输出经可追踪通道返回，并使后续状态、转移概率、时序或约束相对无返回情形发生可检测差异，称为有效反馈。

原文接着列出四个要追踪的位置：先前状态或输出、返回通道、接收位置、被改变的后续字段；信号被接收、回执被生成、档案被保存，只证明到达或留痕。（[原文§3.3](/theory/part-03#section-3-3)）按这个读法，报告里的各项记录说明的东西并不一样：

| 报告记了什么 | 由此可以说 | 还不能说 |
| --- | --- | --- |
| 第五区收到87件投诉，以格式信回复，11件查不到回复记录 | 投诉到达，多数留有回复记录 | 投诉改变了第五区对供水风险的判断 |
| 第五区没有把投诉量用作指标 | 投诉到了，却没有接到风险评估这一步 | 每一件投诉都没有引起任何后续变化 |
| 环保署关闭了第1、6、8项建议，监察长认为整改并不完全 | “已关闭”是整改一方在跟踪系统里的登记 | 建议关闭了，所指的缺陷就已消除 |
| 热线规程要求评估风险、记录处理结果 | 规则确实改了，监察长认可它回应了建议 | 每条线索都已按规程处理，或居民的饮水因此更安全 |
| RAV能转交线索、开启或关闭案件，但不评估风险、不追踪结果 | 系统有转交和案件管理功能 | 案件关闭了，问题就已解决；或者承接线索的人都没有处理 |

中间一列是借原文概念所作的解读，不是报告的结论。§3.3还说明，这个定义不保证反馈真实、及时或有益：返回造成了改变，与改变是否改善了居民的处境，是两项判断。

## 规程改了，算不算学会了

热线规程是一处有记录的规则更新。原文§6.3讲的“反馈介导学习”还要往后看几步：更新被保留下来，在重复轮次中实际调用，并使预定任务的结果相对预先声明的基线出现可复核的差异。（[原文§6.3](/theory/part-06#section-6-3)）审计只核对到规程存在并得到认可，后面几步没有材料。照原文的说法，可以同时写明“做法已改变”和“后续净效果尚未确定”。

## 这个案例能说明到哪里

两份报告是事后审计，不是为检验某条返回通道而预先设计的研究。原文§6.2对“有效反馈”机制的正式支持，要求返回通道经预先登记的检验识别（原文称G2-instance），时间顺序和被改变的字段在看到结果前登记，并与无返回或通道阻断的情形比较。（[原文§6.2](/theory/part-06#section-6-2)）本案没有这些材料，所以不是这一机制的正式检验。这并不削弱审计本身：按[§2.1.1](/theory/part-02#section-2-1-1)，既有材料依其实际的研究设计支持相应的结论，不因没有转成正式实例而失去原来有依据的内容。

## 读完后，试着回答

1. 一件投诉收到了格式回信。凭这一点能说它改变了什么？
2. 一项建议被“关闭”，另一项被记为“已解决”。这两个状态各说明了什么？
3. 热线规程得到认可，能不能替RAV作答？
4. 假设某件投诉让办公室把一次检查提前了，居民家中的铅暴露却没有及时消除。这算不算有效反馈？（为练习设的情形，报告没有记载这样的事。）

参考回答：

1. 只能说投诉到达并得到回复。要说“改变”，得指出被改变的后续字段，比如谁承接、作了什么风险判断、采取了什么动作，并有与“没有这件投诉”相比较的依据。
2. “关闭”是整改一方在跟踪系统里的登记，监察长复核后认为有三项不该关闭；“已解决”表示双方对整改方案达成一致。方案是否执行、缺陷是否消除，要另看材料。
3. 不能。两个入口的管理部门、接收范围和功能都不同；结论要写明是哪个入口、截至哪一年、哪一项功能。
4. 如果有依据表明检查提前确实由这件投诉引起，按§3.3的定义就算：返回使后续的时序出现了可检测的差异。目标有没有实现，是另一项判断。
