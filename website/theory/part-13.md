# 第十三部分　判断程序与工具 {#part-title-13}

本部分讲的是，怎样把前面十二个部分所定义的对象、命题、尺度、机制、行动者、多圈层联合状态和动态推演的要求，转换成可以观察、可以质疑、可以复核、可以撤回的有限判断。它不增加关于世界的事实，也不把表格填得完整当作事实成立。进入工具流程之前，必须已经按结构对象的七个要素界定了候选对象（§3.1），并写明它在九个尺度轴上的位置（§5.2）。对象、边界、尺度、时间窗、同一性判据或用途一旦改变，已有的判断不得原样搬过来沿用。

工具流程分为两级：七闸（§13.3）是唯一的主流程，五闸十三步（§13.4）是诊断时的展开层。七闸回答一个判断能不能进入下一层。五闸十三步用在复杂的案例里，把需要提交的材料展开；它不另外给出与七闸相竞争的“通过”结论，也不产生第二套流程结果。

最重要的一条边界是：工具这一层不产生授权。流程、证据和强判断八件套（§13.5）全部完成，得到的也只是描述、候选机制、比较判断、强判断候选或行动要求。现实行动仍须另外经过规范选择记录（§14.7）、结论规则“规范桥接”所要求的十项组件（§4.14.1）、同一条有效的逐项授权和四步操作程序（§14.6）；工具的输出不能代替其中任何一项。

下面的流程所管的，是按本框架的结构形成的判断，以及这些判断的移交。阅读、原文校对，或低影响的问题澄清，可以采用与任务相称的简明记录；不能因为没有把工具流程全部走完，就宣布已有的领域事实不存在。进入正式的诊断、前瞻或高影响用途时，则必须满足相应的全部条件，不能靠给输出换一个名称来降低责任。

</div>

## 13.1　四次转换 {#section-13-1}

从结构变量到行动要求，中间有四次转换。四次转换不是把理论词换成现实里的标签，而是一次比一次增加记录责任。任何一步没有通过，依赖这一步的输出就停在这一步之前，不能靠后一步在格式上的完整来补救；其他独立的判断，各按自己的依据和用途分别审查。

| 转换 | 必须得到什么 | 没有通过时停在哪里 |
| --- | --- | --- |
| 结构变量到可观察信号 | 信号记录，其中对象、尺度、观察位置、时间窗、测量方法和缺失状态都明确 | 概念映射或材料缺口 |
| 信号到证据强度 | 证据记录，其中来源、观察、比较条件、覆盖、反例、替代解释和不确定性分开 | 未分级的材料或待检验的假设 |
| 证据强度到判断等级 | 一个判断，它对命题有明确的界定，并带有适用边界、反向条件、证伪条件和撤回条件 | 候选解释或观察意见 |
| 判断等级到行动要求与上限 | 一份清单，写明受影响位置、保护底板、禁止的动作、停止、申诉、恢复原状，以及规范前提、逐项授权、操作程序和结论规则“规范桥接”（§4.14.1）这几样里还缺哪些 | 描述、补证或不行动的要求 |

四次转换各防一种错误。第一次，结构变量到可观察信号，防止把结构叙事当成观察到的事实。第二次，信号到证据强度，防止把出处、材料或表态直接当成证据。第三次，证据强度到判断等级，防止把相关、类比或单一的机制故事升级为结论。第四次，判断等级到行动要求与上限，防止从事实判断直接跳到处置。四次转换全部通过，也不改变授权的状态。

任何一次转换没有通过，依赖它的后续转换只能记为“未执行”，它们所支持的命题、比较判断、强判断候选和行动要求也要停止或降低。出自同一个缺口的下游结论，不得靠改名、拆分或另开分支来恢复原来的上限。后面的“未执行”只是把这条失败的链条保留下来；强判断八件套即使齐全，也补不回这个断口。不依赖失败环节、有独立依据、用途又满足自身要求的判断，可以保留原有的地位。如果缺口触及全局性的来源身份、共同的事实前提、对象边界，或整项任务合法使用的条件，那么所有依赖它的输出一并停止或降档。高影响采用所要求的检查没有通过时，同一个判断不得只靠改称普通意见而保留原来的用途。

## 13.2　十一个基本结构概念与十一项人类变量的使用方式 {#section-13-2}

第七部分的十一项人类变量（§7.3）用于人类结构化世界，第三部分的十一个基本结构概念（§3.5）是通用的。工具这一层可以在同一个案例里并列使用二者，但不把编号相同、数量相同或所问的问题相似解释为一一等价。

使用时至少写明：用的是哪一个基本结构概念或哪一项人类变量，有效对象，在九个尺度轴上的位置，所选的支持路线，这一个案的证据，替代解释，缺失状态，判断上限和行动上限。六项人类领域条款（§7.1）里属于经验假设的三项，即“意义与协调”“权力、中介与反身性”和“历史留痕载体”，只能各自经过一次具体检验（§4.2）进入指定的路线。四类经验问题只能经过在结果出现之前已经预注册的正式检验（§4.1）来支持经验主张。概念和变量的详表（人类变量的详表见附录A）可以提出问题，却不能因为各项都填满了就证明对象事实。

## 13.3　七闸：唯一主流程 {#section-13-3}

七闸对每一个具体的命题、按它的依赖顺序逐闸进行。某一闸没有通过，依赖它的后续各闸只能记为“未执行”，相应的判断和行动要求停止或降档。后面的“未执行”不能把未通过的那一闸已经压低的上限再抬高；也不能一边承认对象或证据没有过闸，一边让相关的后续程序自称通过。不依赖失败环节的判断，仍须有它自己独立的证据和用途审查，不得拿另一个命题的通过掩盖这个命题的失败。全局性的来源身份、共同的事实前提、对象边界或任务合法使用的条件一旦失效，所有依赖它们的输出一起停止。对象、所依据的证据、受影响位置或用途发生实质变化时，从最早受到影响的那一闸重新做起。

| 闸门 | 核心问题 | 未通过时的输出上限 |
| --- | --- | --- |
| 有效对象闸 | 对象、边界、九个尺度轴上的位置、时间窗与同一性判据是否支持这一次判断？ | 重新界定对象、尺度记为“未知”，或对对象转换进行复核 |
| 证据追踪闸 | 来源、材料、观察、证据、反例、案例与判断是否分开，并且可以回溯？ | 材料整理、候选问题或待检验的假设 |
| 受影响位置闸 | 哪些直接、间接、二阶、跨域与跨期的位置会改变处境？ | 补充影响核算；暂停强判断和高影响用途 |
| 权力与反报复闸 | 低权力位置能否安全地补证、反驳、拒绝、停止和申诉？ | 不得因沉默作不利的推断；降低发布与判断的档位 |
| 中介与反身性闸 | 指标、平台、AI、公开评价或诊断行为，是否改变了证据和对象？ | 高反身性尚未收束；改写成有条件的状态转移 |
| 强判断程序闸 | 按用途与可预见的影响触发了强判断的命题，是否完整提交了强判断八件套？公开传播须提高审查，但不单独使全部分析都升为强判断。 | 相关的强判断与高影响用途停止；独立成立、用途合规的比较判断分别审查 |
| 行动上限闸 | 最多只能提出什么要求，哪些动作禁止，何时停止、申诉和恢复原状？ | 描述、证据缺口、不行动或继续审议 |

七闸全部通过，不表示结论为真，只表示各闸所要求的记录没有缺口。经验命题仍然由它自身的界定和具体检验的证据来判定；规范目标仍然需要明示的规范前提；现实行动仍然需要规范选择、结论规则“规范桥接”（§4.14.1）、逐项授权和操作程序（§14.6）。尤其是“行动上限闸”，它只能记下外部的规范层与授权层是否已经具备；工具流程不能自己把结果写成“已授权”。

“强判断程序闸”有一条专门的适用规则。普通的“轻量描述”和“标准判断”两档输出（§13.6）可以把这一闸记为“不适用”，但必须写明这一次为什么不触发强判断程序；这样记并不阻断“行动上限闸”。一旦把这一闸记为“通过”，同一份记录里就必须附有强判断八件套（§13.5）完整的、逐项通过的结果。只写“已检查”几个字，或者理由空着，都不能代替这八项结果。

“受影响位置闸”的识别范围按§14.4.1确定：那一节要求全部列出的位置，必须全部列出；其余的位置，须说明追踪到了哪里、为什么停下。没有方案比较的解释任务和诊断任务，以继续追踪还能不能改变判断的结论或档位、用途范围或保护安排为准。

## 13.4　五闸十三步：诊断展开层 {#section-13-4}

对象复杂、责任重、反身性高，或者七闸（§13.3）需要展开取证时，就走五闸十三步。五闸是展开过程里的局部检查，不产生第二套主流程结果。

| 展开闸 | 必须展开的材料 | 对应的主闸 |
| --- | --- | --- |
| 对象闸 | 对象、边界、尺度、时间窗 | 有效对象闸 |
| 证据闸 | 信号成本、来源、权重、复核 | 证据追踪闸 |
| 尺度闸 | 九个尺度轴上的位置、各尺度之内的对象与证据、尺度变化 | 有效对象闸、证据追踪闸 |
| 责任闸 | 对权利和资源的影响、反向条件、修复窗口、申诉与复核 | 受影响位置闸、权力与反报复闸、强判断程序闸 |
| 观测闸 | 观察之前的基线、观察之中的反应、发布之后的反应、递归的封顶 | 中介与反身性闸 |

十三步按照从现实问题到写回的顺序，连成一条可以核查的工作链：

| 步骤 | 最小产物 |
| --- | --- |
| 问题入口 | 不用框架术语表述的现实问题、请求者和用途 |
| 对象与边界 | 有效对象、子系统、上级环境和外部通道 |
| 信号分层 | 事实、行为、资源、反馈、叙事、感受、推测和噪声分栏 |
| 观测参与记录 | 被观察者是否知情、观察者的权力、发布的影响和候选反应 |
| 主导约束 | 候选约束、所选约束、选择的证据和竞争约束 |
| 状态与窗口 | 对象适用时，指明对应七种状态原型（§8.3）中的哪一种、在该状态内的位置、并行的子系统和反向条件；不适用时说明原因，保留本领域自己的状态与窗口 |
| 核心结构扫描 | 锚点、承接层、传导链、边界和反馈写回 |
| 关键保护变量 | 受保护的变量、受损路径、资源、冗余，以及修复路径或回流路径 |
| 承接与偿付 | 成本承担者、回流获得者、停止权、长期透支与损害转移 |
| 隐患与边界类型 | 维护债、快慢错配、指标替代、摘要失真和对象转换候选 |
| 机制候选 | 材料允许、并且足以改变判断的竞争机制，各自所需的证据、削弱它的证据和淘汰规则；没有合理的竞争解释时，说明检索范围与失败条件，不为凑数虚构机制 |
| 分支预判 | 触发、早期信号、反向条件、修复窗口和最低行动要求 |
| 输出与写回 | 用现实语言写成的输出、触发修改的条件、记录范围、复核、撤回和恢复原状 |

其中几步各有界限。“状态与窗口”一步用到七种状态原型时，只能用于适用的人类意向性集体，不适用的对象不得硬套；也不能把七种状态原型写成成熟度或命运。“关键保护变量”一步发现了重要的保护变量，只能由此提出保护需求。“承接与偿付”一步发现了承接或透支，不能由此产生牺牲的义务或完整的责任。“机制候选”一步提出的机制候选，不得越过因果主张的条件（§2.4）。“分支预判”一步给出的分支不是确定的未来。“输出与写回”一步如果没有复核和撤回，就不得把判断写进组织记录、资格、分配或公共记忆。

## 13.5　强判断八件套 {#section-13-5}

一个判断是不是强判断，按它的用途和可以预见的影响来界定，不按语气、篇幅或表达得有多自信来界定。打算用于、或可以合理预见会被用于处置、资格、权利、资源分配，或对具体主体的声誉与公共记忆产生实质影响的判断，以及被嵌入自动化、组织化、制度化决定的判断，都进入强判断程序。中间的评分、建议或材料筛选，如果通过后面的环节影响到这些决定，同样要核查它的实际用途。

公开传播是提高审查要求的一个因素，应当结合被评价的对象、事实指控、可识别性、传播范围和后果来判断；它本身不足以使所有的分析输出都升级为强判断。普通的论证评价、机制解释或规范意见，在不触及上述用途与影响的时候，可以按与任务相称的证据要求和复核要求提出明确的结论。自称是评论、研究或草案，不能使实际已经达到强判断条件的输出得到豁免。

只有按“强判断候选”这一档（§13.6）处理、七闸（§13.3）全部通过、并且下列八项逐项通过的判断，才可以记为强判断候选；它仍然不产生现实行动的授权。

| 组件 | 必须回答什么 |
| --- | --- |
| 反向条件 | 出现什么情况会削弱、反转或撤回这个判断？ |
| 修复窗口 | 窗口在哪里，根据是什么，何时失效？ |
| 证据要求 | 支持的证据、缺失的证据和反向的证据分别是什么？ |
| 申诉入口 | 谁可以进入，谁负责，时限多长，能不能改变结果？ |
| 反报复保护 | 哪些行为受保护，怎样监测，怎样独立报告和补救？ |
| 证据补充权 | 怎样补证，怎样纠正已有的记录，并使下游随之更正？ |
| 外部复核触发 | 何时触发，谁来独立复核，复核者能不能看到材料、能不能停止结果？ |
| 恢复原状与写回 | 回到哪个状态，谁来修复，以哪一版记录为准，怎样使各处一致？ |

八项之中任何一项缺失，这个强判断就过不了“强判断程序闸”（§13.3）：它不得成为强判断候选，也不得保留原来的高影响用途，只能在与它的材料和实际用途相称的范围内，记为内部假设、开放断言或候选机制。属于“标准判断”一档的比较判断，如果不依赖所缺的那一项、有独立依据、又不触发强判断用途，可以保留。共同前提失效，仍然阻断所有依赖它的判断，不得靠改名或拆分来规避。申诉入口如果不能改变记录或行动，就不算有效的申诉。名义上来自外部，不等于独立。发表声明、道歉或发布新的一版，不等于实际的恢复原状和修复。

</div>

## 13.6　诊断档位 {#section-13-6}

诊断分三个档位，简称“轻量描述”“标准判断”和“强判断候选”。

| 档位 | 适用 | 输出上限 |
| --- | --- | --- |
| 轻量描述与试探问题 | 低复杂、低影响、可逆，并且信息有限 | 描述、问题和下一步观察 |
| 标准可复核判断 | 需要结构比较，但不进入高责任的处置 | 有边界的比较判断或机制候选 |
| 高责任强判断候选 | 有实质高影响的判断，或嵌入自动化、组织化、制度化决定的判断；公开传播按对象、事实指控、可识别性和后果审查 | 七闸与强判断八件套通过之后的强判断候选 |

档位升高，不表示“更接近真理”，只表示记录责任增加。证据覆盖下降、对象发生转换、反身性失控、申诉或反报复保护失效时，必须降级。情况紧急，也不能删去对象、保护或停止条件；等待的代价很高时，只能在相应的授权之外，另行提出范围最窄、可以撤回、可以监测的行动要求。

</div>

## 13.7　六项正式工具 {#section-13-7}

正式工具有六项，各有作用，也各有边界。

| 工具 | 作用与边界 |
| --- | --- |
| 来源—证据台账 | 把来源、材料、观察、证据、反例、覆盖和不确定性分开；不证明命题 |
| 开放断言记录 | 留下一个可以质疑、可以证伪、可以撤回的临时判断，作为靶点；不用于高责任的处置 |
| 命题验证表 | 对命题的类型、证据、反证、证伪条件、影响和上限逐项写明 |
| 前瞻登记 | 事先写定预测、窗口、触发、早期信号、反向信号和修改目标 |
| 反例与尺度压力测试 | 用边界案例、对抗性的解释和尺度变化找出失败的位置，并收缩范围 |
| AI 输出边界 | 强制写明来源、缺失的材料、人类责任人、不确定性、禁止的用途，以及复核与撤回 |

来源—证据台账不能把“有来源”写成“得到支持”。开放断言不能代替命题验证。预测失败了，必须写回到相关的命题上。内部的压力测试只是一场风洞试验，不是外部的经验支持。各项工具可以互相引用对方的记录，但不得绕成一圈、互相作证。

自动核对适合做这样几件事：核对只能在固定选项里取值的项目，核对引用能不能对应到真实材料，核对各处的版本和状态是否一致，核对计算能不能重算出来。它不能代替材料的鉴别、受影响者的证言、因果识别或价值选择。可以机械完成的工作应当交给程序，让读者能够审查真正的判断理由；完整的过程记录和清楚的正文可以分开保存，并且能够互相找到。

</div>

## 13.8　AI 使用边界 {#section-13-8}

AI 可以做的事：整理材料，检查记录中的各项，比较不同的版本，提出候选问题，列出替代解释，发现格式上的矛盾。在证据和规范前提允许的时候，AI 也应当比较机制，形成可以反驳的判断，推荐方案，并起草完整的制度、计划和评论。

AI 不得做的事：虚构来源；把训练中留下的记忆当作当前的证据；替当事人表示同意；把沉默解释为同意；代替决策主体或授权机关；隐藏不确定性；独立作出高风险的现实决定。

AI 的输出必须说明：用了哪些材料；缺什么；哪些内容是观察，哪些是推断，哪些是类比；谁承担最终的判断责任；允许怎样使用；何时复核和撤回。涉及身份暴露、报复风险或正当的不透明时，为保护而作的省略，必须能够同“没有证据”区分开来。

使用 AI 的责任，还应当按实际的分工落到各个角色上：材料提供者，目标与权限的决定者，系统维护者，执行者，复核者。承担技术步骤的设施和程序，不会仅仅因为输出了建议或执行了指令，就成为能够承担道德责任或法律责任的主体；依法具有特定责任能力的组织，则根据它的制度身份和具体事项分别判断。自动化程度提高，也不把全部责任压给最后点击的那个人。复核者必须有足够的材料、时间和能力，并且有真正能够生效的停止权限；组织还须为这些条件提供资源。

</div>

## 13.9　流程记录与失败的含义 {#section-13-9}

每走一次工具流程，都要留下一份流程记录。这份记录有哪些项目是固定的，使用者不能自行增添。它写明：对象和尺度的记录；所用的诊断档位（§13.6）；四次转换（§13.1）各自的结果；七闸（§13.3）各自的结果；是否走了五闸十三步（§13.4）；是否触发了强判断八件套（§13.5）；证据；替代解释；不确定性；输出的类别；判断上限和行动上限；向规范层的移交；申诉；恢复原状；状态。

行动上限只有三档：仅描述、仅诊断、仅提出要求。每一档可以出现哪些类别的输出是固定的；无论哪一档，都既不能授权，也不能执行。使用者不能在自由行文里自称“已经授权”，也不能自行扩大允许的类别。所谓行动要求，只是向外部的选择程序和授权程序提出所需要的条件，不是可以执行的命令。

向规范层移交时，须指明可以核查的外部记录，即规范选择记录（§14.7）、结论规则“规范桥接”（§4.14.1）的检查记录和授权记录；这些记录尚不具备的，要明白说出尚不具备。指明时须写清对象、动作、范围、时间，以及实际凭什么核验。含糊的标签、自称已经通过，或同一份记录绕回来引用自己，都不能证明权限。引用采用什么具体格式，由实际采用的工具和做法确定；这不改变一条边界：工具不得自己签发授权。

各种结果要保持可以区分。“通过”表示这一项所要求的记录过了关；“未通过”表示已经做了，但没有过关；“未执行”表示因为前面的闸没有通过，或受范围所限，而没有做。未知、不适用、不可观察和为保护而不公开，仍然是四种不同的缺失状态（§2.9）。“未通过”不能改写成“不适用”；为保护而隐去的内容，不能改写成“不存在”。

流程记录本身永远不产生授权的效力。即使外部的规范选择、“规范桥接”的检查、逐项授权和操作程序都已经有记录可以指明，流程记录也只是核对它们、向它们移交，不能自己造出授权。凡是经过复核的输出，都必须保留可达的申诉途径，以及实际的撤回、纠正途径；不能撤回的工具结论，不得进入高影响而又难以逆转的用途。

## 13.10　多圈层推演九闸 {#section-13-10}

七闸（§13.3）是解释与诊断的唯一主流程。任务明确要求动态推演、条件前瞻或有限选择时，在七闸的基础上展开九闸。九闸不得绕过七闸已经规定的对象、证据、受影响位置、权力、反身性、强判断程序和行动上限。

| 闸 | 核心检查 | 未通过时的输出 |
| --- | --- | --- |
| 事实定格 | 事件类型、来源、时间、证据截止和争议 | 事实问题清单 |
| 联合对象 | 行动者、圈层、关系、成员与同一性判据 | 候选分组，或退回单一焦点 |
| 双通道与时钟 | 与任务相关的物质条件和体验—意义条件、时钟、未知；无关的项目说明理由后记为“不适用” | 保留状态快照；暂停依赖所缺条件的传播，独立的路径分别审查 |
| 机制传播 | 通道、阈值、时延、反馈和级联 | 候选机制与区分观察 |
| 路径分叉 | 条件、父子节点、早期信号与反向信号 | 并行路径，不强制排序 |
| 前瞻登记 | 目标、期限、简单基线、校准和回写 | 仅作情景推演 |
| 规范选择 | 规范前提、保护底板、受影响者、方案与不行动 | 被缺失所阻断的推荐暂停；保留独立成立的评价、明示前提的条件建议和补证需求，不产生执行权限 |
| 授权与执行 | 逐项授权、操作程序、责任、停止、恢复原状和补救 | 向外部移交，不执行 |
| 结果回写 | 结果、同基线的比较、偏差、降级和退役 | 保留失败的记录，另立新的一版 |

工具可以在“联合对象”一闸提出圈层候选，在“路径分叉”一闸提出变量候选，但任何候选都始终只是候选。“前瞻登记”一闸没有通过时，输出不能使用“将会”“预计命中”一类的前瞻语气。“规范选择”或“授权与执行”一闸没有通过时，输出不能给出可以执行的指令。“结果回写”一闸不允许覆盖原来那一次的记录。

## 13.11　AI 在动态运行中的边界 {#section-13-11}

AI可以做的事：整理材料；核对可以定位的原文；发现记录中缺了哪些项；提出并比较竞争路径；检查各项界定和约定是否一致；计算事先登记的指标；并在明示的规范前提下，形成有依据的局部判断、建议和完整的文本。

AI不能做的事：仅凭自己生成的内容、自己的陈述或内部流程，认证现实中的事件；诊断人格；替当事人披露信息；凭自己的分类，决定对他人有约束力的圈层边界；把模拟当作事实；替别人确定有争议的价值前提；签发授权。

外部材料是否支持某一项具体事实，要按材料的身份、方法、反例和拟定的用途分别判断；忠实于原文，也不自动证明原文所说的现实为真。对AI自动提出的变量，系统必须记明它只是模型提出的候选，并写明最小检验和禁止的用途；没有相应的外部证据之前，不得升级。

</div>

### 13.11.1 AI材料核对与工具行动链 {#section-13-11-1}

核对生成的答案时，要分开检查：出处是否存在；引用的信息是否正确；原文那一段是否支持这句话；这句话所说的世界事实是否有足够的依据。给定的来源没有提到，不等于这句话一定错误；忠实地转述一个错误的来源，也不等于已经查明事实。对于没有公开网页可查的地方知识、口述和保护性材料，应当保留合适的核验途径和公开范围，不能直接当作不存在。

检索增强可以改善资料的取得和任务表现，一致性检测或不确定性检测也可能发现某一类错误；它们的作用仍然受检索的覆盖、共同的来源和错误的类型限制。稳定重复的错误可以显得一致；多个模型复述同一份失实的材料，也不构成多份独立的证据。形式检查器能够确认明示前提之下的推导，却不能替这些前提在现实中成立作证。

自动化的行动，应当把建议、工具请求、应用执行、外部状态和后果分别记录。模型写出“已停止”，不证明执行器收到了停止指令；界面显示“已删除”，不证明下游的副本已经消失；人改过了建议，也不证明这一改动赶在不可逆的动作之前生效。用于实际保护和纠错的权限，必须在相应的系统里可以行使。

### 13.11.2　任务终点与可核验的执行链 {#section-13-11-2}

一串工具操作核验到哪里为止，由用户的请求或制度规定的任务来确定。只要求生成草案时，草案正确保存、可以打开、内容满足要求，就可以构成这一次交付。要求改变外部记录时，工具返回“成功”还不够，还须由相应外部对象的状态来证实。要求实际补救时，又须核对资源、权利或服务确实到达。较窄的终点真的完成了，不必等到生活中的全部后果都出现才予以承认；较宽的终点，也不能用界面返回的一张成功回执来代替。

| 环节 | 最小核验对象 | 典型断点 |
| --- | --- | --- |
| 建议形成 | 目标、材料、打算改动的对象和允许的范围 | 把生成的文本当作已被采用 |
| 工具请求 | 具体动作、参数、对象当前是哪一版，以及权限 | 正确的建议发给了错误的对象 |
| 应用执行 | 请求是被接收、被执行还是被拒绝，重复的请求怎样处理 | 请求送达了，却在排队、已经失败或被重复执行 |
| 外部状态 | 目标对象和依赖它的对象是否发生了预期的变化 | 本地的标记变了，实际执行时读的仍是旧状态 |
| 任务后果 | 指定的受益终点或保护终点，以及残余的问题 | 更正的记录已经生效，错过的机会却没有恢复 |

多个工具同时操作时，应当先区分三种情形：可以独立读取，可以独立修改，共同写入同一个对象。修改共享的状态，要保留先后顺序，写明这次修改以对象的哪一版为前提，或者定下冲突怎样处理。作出不可逆的动作之前，要重新核验权限和停止条件是否仍然有效。请求超时表示结果未知，不能直接当作没有执行而重复动作；先凭请求的标识或对象的状态核对，再决定是否重试。这里规定的是执行上的责任，不要求所有的应用采用同一种日志格式。

停止也有它自己的完成条件：发出停止，执行器确认，在途的动作终止，已经发生的后果得到补救，这几步要分别记录。只确认了前两步时，要准确说明相应的范围。如果安全撤收需要在独立职责之下做有限的动作，这些动作按它们自身的依据继续进行，不能因为主任务停止而放弃必要的接续。修复失败时，保留失败的对象和现实中的后果，禁止用一份新的、正常的输出覆盖它们。
