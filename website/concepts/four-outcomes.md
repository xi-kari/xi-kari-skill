# 成功一次，为什么仍要分别问维持、恢复与复制

四种结果各有条件；已有成效和新阶段失败可以同时成立。

安排建立了、现在运转良好、故障后恢复了、换一个地方也做成了，分别是形成、维持、恢复和复制。v2的[§6.10.1](../theory/part-06#section-6-10-1)要求逐项判断。

| 结果 | 继续检查什么 |
| --- | --- |
| 形成 | 启动条件及从原状态过渡的路径 |
| 维持 | 持续补给、替换与校正 |
| 恢复 | 受扰后仍可调用的载体、余量、外援与时间 |
| 复制 | 新对象、地点或规模自己的人员、设备、时间和纠错条件 |

原处成功，对新地点只提供候选。复制或扩大失败时，至少比较四条解释：原方案无效；未按事前内容实施；缺少事前声明的使能条件；规模变化改变了处理或对象。它们需要区分性材料，不是四个可任选的免责理由。

教学情景：试点时有培训和权限，扩展时没有落实。若这些要求在结果前已声明，可以检查实施缺口；若失败后才追加“还必须由创始人每天在场”，它只能作为下一轮候选。结果后取得的记录仍可用于核实事前声明的条件，关键不在取证日期本身。

[GitLab恢复案例](../cases/gitlab-recovery)可以帮助读者区分功能恢复与未来恢复能力。案例原有事实和截止日期保持不变，它不因此成为本节全部机制的检验。需要支持的真实恢复也不用靠撤掉支持来证明。
