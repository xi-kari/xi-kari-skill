# Part 3 Universal Structural Grammar {#part-title-3}

This Part provides a shared descriptive interface for discussing the broadly conceived empirical structural world. It is not a set of assertions that “all things are isomorphic,” but a set of interfaces that can each be declared, tested, withdrawn, and converted across scales. The definition layer D0–D3 specifies how to state objects and states clearly; U01–U11 specifies which structural positions need to be distinguished in explanation. Neither definitions nor primitives automatically become empirical facts by being written into a contract[^tn-contract-03]. The 11 primitives are not claimed to be a logically independent, unique, or complete classification of the world. A task may use a sufficient subset, or add domain variables after stating the reasons. Empirical support still comes from specific materials, G-instance, and the corresponding evidence procedures.

## 3.1 D0 Structural Object {#section-3-1}

Proposition: A candidate structural object is denoted S*=&lt;B,X,R,I,T,SP,K&gt;; the null model N0 is frozen only in a specific test instance.

Definition: D0 declares only a candidate object S*=&lt;B,X,R,I,T,SP,K&gt;. B is the boundary. X comprises the state variables. R specifies relations or transition constraints. I is the interface. T is the time window. SP is the scale profile. K is the identity criterion. This declaration makes the object available for discussion; by itself it neither provides grounds for object facts nor proves a grouping gain; N0 belongs to the comparison contract of a specific G-instance.

The candidate object is written as:

S*=&lt;B,X,R,I,T,SP,K&gt;

B is the boundary, specifying which states and relations are included in the current object and which remain outside it.

X comprises registered state variables, not a synonym for “all actual states of the object.”

R specifies relations or state-transition constraints; endpoints, direction, time, and conditions of application must be stated.

I is the interface through which the object has inputs, outputs, filtering, transmission, or conversion with its exterior.

T is the time window used for observation, prediction, intervention, or feedback.

SP is the nine-axis scale profile. It records the object's positions in aggregation, space, time, organization, causation, observational resolution, influence, network topology, and jurisdiction.

K is the identity criterion, specifying which changes still allow the object to be recorded as the same object.

D0 declares only the candidate object for this analysis. The same object can serve different tasks; each task must separately specify the target being asked about, horizon, environment, admissible operations, error, and evidential requirements. The seven object fields must not be taken to imply sufficiency for answering every question. N0 is not entered into the object vector; it is specified within a particular comparative claim. Complete object fields do not establish a grouping gain; naming, clustering, drawing a boundary, and narrative coherence cannot replace G1 evidence. Existing records, observations, or other reliable materials can support facts concerning specified people, organizations, events, and relations, with sources and identity conditions stated. These facts do not disappear merely because G1 has not yet been tested, nor do they automatically establish that the grouping has a predictive gain, a unified subject, or a common will.

## 3.2 D1 Basic State Terms {#section-3-2}

Proposition: Change, operation, persistence, evolution, dissolution, and repair are each used according to pre-declared detectable criteria; evolution does not imply a path, direction, or value; repair must satisfy K or F, while its value and authorization undergo separate N/O review.

Definition: Change is a detectable difference in registered variables between two observation positions, without implying its cause, whether the change will last, or its direction. Operation is a state transition in X while B, R, I, SP, and K still hold under the current contract. Persistence is the current K continuing to hold within a specified time window. Evolution is a detectable change over time in the boundary, variable set, relations, interfaces, scale position, or identity conditions of an object contract, exceeding a declared fluctuation window; the definition itself does not include durable traces, path dependence, selection, direction, or value judgments. Dissolution means that the K declared in the original contract no longer holds. Repair is the formation of a new state satisfying a pre-declared target identity criterion K or functional criterion F; whether repair should occur, what its target should be, and who should carry it out must undergo separate review in the N and O layers.

D1 does not define “structure,” nor does it judge whether a D0 candidate grouping brings a gain; the latter is tested by a pre-registered G1-instance relative to a complexity-matched N0, within its SP/T/K and extrapolation unit (§4.3), and object facts have separate grounds (§3.1). The applicability of state terms such as change, operation, or persistence cannot in turn serve as proof of a grouping gain, nor can it replace independent grounds for the object's existence. Persistence describes only the continuation of the current K within a specified window; it does not mean health, justification, progress, or that continuation is warranted.

Evolution registers only detectable changes in object-contract fields over time that exceed a predetermined fluctuation window; it does not imply durable traces, path dependence, historical determination, a selection mechanism, direction, maturity, progress, decline, or a value judgment. Whether historical conditional increments exist requires separate testing under G3; whether variation–differential retention–reproduction exists requires separately passing C8/CM-SELECTION. An evolution record can hold while G3 or a selection mechanism still does not hold.

Dissolution means that the specified K no longer holds. Dissolution may mean the object's termination, its conversion, or the need for reclassification; it does not automatically amount to failure. Repair is the formation of a new state satisfying a pre-declared target identity criterion K* or functional criterion F*. It can retain old components, or change boundaries, relations, interfaces, and carriers; it does not require a return to the historical state. Whether repair should occur, which K*/F* should be its target, who decides, and who carries it out must each undergo review in the N and O layers. The definition of “repair” cannot authorize these matters on its own.

## 3.3 D2 Effective Feedback {#section-3-3}

Proposition: A prior state or output constitutes effective feedback only when it returns through a channel and changes a subsequent state, transition probability, or constraint.

Definition: A prior state or output returning through a traceable channel and producing a detectable difference in subsequent states, transition probabilities, temporal sequence, or constraints relative to the absence of that return is called effective feedback.

Effective feedback contains at least four traceable positions: the prior state or output, the return channel, the receiving position, and the subsequent fields that are changed. Reception of a signal, generation of a receipt, recording of an expression, or preservation of an archive establishes only arrival or a trace. Feedback is registered as effective only when subsequent states, transition probabilities, temporal sequence, or constraints show a detectable difference relative to the absence of return or to a blocked channel. D2 does not guarantee that feedback is accurate, timely, or beneficial, still less that it produces learning.

The effects of feedback, its stability, and improvement relative to a target must be kept separate. A return that has changed subsequent states can coexist with oscillation, amplification, or deviation from the target. Fixed rules can also produce feedback; retraining parameters is not a necessary condition. A claim of deviation correction must separately state the deviation from the target, gain, execution delay, operating range, and destabilization criteria. A claim of improvement must also evaluate transient peaks, cost, and distribution. Stability criteria for a specified linear model constrain only that model. They must not be generalized, merely on the strength of the term “negative feedback,” into a claim that real-world processes necessarily stabilize themselves.

## 3.4 D3 Scale Transformation {#section-3-4}

Proposition: A cross-scale judgment must declare M(SP0→SP1) and record what is retained, changed, and lost, the operator, error, and applicable range.

Definition: A scale transformation M(SP0→SP1) records the source and target scale profiles, retained variables, changed variables, lost variables, the conversion operator, error, and applicable range. Each sufficiency judgment must also specify the target query or task family, horizon, environment, and admissible operations. Static answers, dynamic progression, responses to intervention, and feasible action are judged separately.

A scale transformation is written as:

M(SP0→SP1)=&lt;保留变量, 改变变量, 丢失变量, 转换算子, 误差, 适用区间&gt;[^tn-fields-03]

Using the same word at different scales does not constitute a scale transformation. An aggregated object is not simply an enlarged local object, nor can aggregate statistics be assigned back to every local unit. Each M must specify the source and target scales, whether the object's K is retained, how relations or units are converted, what information is lost, and when the error exceeds the limits of applicability. Without bridging evidence, only parallel descriptions of the two scales may be given; successful transfer must not be claimed.

At least three questions must be distinguished for the same mapping: whether it suffices to answer the current static query, whether it can advance to the next state on its own, and whether it still suffices to evaluate admissible interventions. There is no automatic progression among the three. A total can answer a question about the total exactly while omitting local overload. Adding the maximum can recover a particular static answer while still omitting the positional identity needed for targeted operations. The success of a mapping must therefore always be specified with its target, horizon, environment, and admissible actions, not merely with a note that “information is retained.”

### 3.4.1 Representational Recasting and Discursive Recasting {#section-3-4-1}

Representational recasting rewrites a sourced state, information, or model expression, through a named converter, bridging party, or rule, into a new representation directed toward a target scale, circle[^tn-circle-03], task, or vocabulary system. When the payload is primarily language, institutional texts, or explanation, it is called discursive recasting. The new representation must retain its parent record and source lineage.

Recasting differs from scale transformation, transformation of circle relations, network propagation, compression, and lateral analogical transfer. These operations may participate in a recasting, but cannot replace the recasting contract. Whether recasting actually changes understanding or action on the target side still requires materials concerning the specified channel. Whether the collapsed differences still provide conditional increments, and whether different orderings fail to commute, are still tested under the existing contracts for scale closure.

A recasting must register at least: the source formulation and context; the target circle and task; the converter or rule and its version; retained elements; permitted changes; collapsed differences; omissions; added explanations; ambiguities; error; the parent record; the path back to the source record; review on the target side; the validity period; and conditions for failure and withdrawal. Without independent review on the target side, the recasting may only be registered as awaiting testing.

## 3.5 The 11 Universal Structural Primitives {#section-3-5}

### 3.5.1 U01 Candidate Object Interface {#section-3-5-1}

U01 registers only the D0 candidate object S*=&lt;B,X,R,I,T,SP,K&gt; and its traceability across scales. N0 is frozen in a specific G-instance; completing U01 does not guarantee in advance that G1 holds.

The function of U01 is to turn an object of intended study into a traceable input: the object-instance ID and the seven D0 fields must be complete, with a root-instance contract then established when applying for formal root-instance support. It permits soft boundaries, short-duration objects, forms with multiple centers, and distributed forms, but does not presuppose that the groupings in these forms bring a gain. U01 is not applicable to purely metaphysical objects for which the declaration of empirical fields is refused. Completing U01 permits only the registration of candidate objects and the generation of questions awaiting testing; it does not generate value, responsibility, choice, or authorization to act.

### 3.5.2 U02 Boundaries and Interfaces {#section-3-5-2}

Boundaries distinguish the inside of an object from its outside; interfaces record exchanges and constraints across the boundary. Boundaries can be permeable, movable, nested, or overlapping; interfaces can filter, delay, convert, or block processes across the boundary. Spatial proximity does not automatically constitute a shared boundary. The existence of a boundary does not imply that the object is closed; still less does the existence of an interface imply that any one party holds control rights. Across scales, the distinction between inside and outside and the traceability of channels should be retained, while allowing boundaries and interfaces to be reorganized. This primitive is not applicable to objects for which no distinction between inside and outside can be declared.

### 3.5.3 U03 States and Observables {#section-3-5-3}

States are described through declared variables and observables, with measurement positions and errors retained. A state is the object's registered configuration at a given T and resolution; an observable is a record formed from a state through a measurement channel. Measurable quantities are not the same as the entire state; not having been observed is not the same as not existing; and a record may also include contributions from the measurement process itself. Changes of scale can alter resolution and observables, but variable definitions, measurement positions, and errors must be retained through the transfer.

### 3.5.4 U04 Components, Carriers, and Substrates {#section-3-5-4}

Structural realization must distinguish components, carriers that carry causal transitions, and substrates that provide the conditions for realization. A component is a constituent unit of the current object; a carrier is a material, informational, or relational position through which a specified state transition actually occurs; a substrate provides the background conditions that make this realization possible. A given component is not necessarily the key carrier, and the object may retain K after the component is replaced. Identifying a carrier specifies only a position of realization; it cannot give the carrier intent, responsibility, or an obligation to continue carrying. This primitive is not applicable to purely definitional objects that make no claim to empirical realization.

### 3.5.5 U05 Relations and Constraints {#section-3-5-5}

A relation is registered as a structural constraint only when it changes what states or transitions are feasible. Relations describe repeatable dependencies between endpoints; constraints narrow the set of feasible states or transitions. Correlation, adjacency, and co-occurrence cannot by themselves be upgraded to causal constraints; a causal upgrade also requires temporal order and a specified channel, together with intervention or a counterfactual. The existence of a constraint does not establish that it is justified, either. Scale transformation may change effective relations, so the endpoints, direction, and applicable window of a relation must remain traceable.

### 3.5.6 U06 Flow, Channels, and Transmission {#section-3-5-6}

For systems in which transitions across components or boundaries are claimed, flow specifies the object, direction, rate, and distribution of resources, signals, or effects; channels specify the carrying paths; and transmission specifies how inputs change downstream states. Capacity, delay, reliability, controllability, and loss are candidate attributes for measurement channel by channel and dimension by dimension; unmeasured dimensions remain unknown. U06 provides descriptive positions, not proof that any particular channel actually exists; channel effects still require a G2-instance. The source, target, and channel must remain traceable through scale transformation, and a channel must not automatically be deemed a responsible party.

### 3.5.7 U07 Feedback and State Updating {#section-3-5-7}

A prior state or output constitutes effective feedback only when it returns through a channel and changes subsequent states, probabilities, or constraints. Feedback is a return relation; state updating is the subsequent change caused by a return or other input. The two need to be registered separately. Feedback can be reinforcing, inhibiting, delayed, distorted, or blocked. Effective feedback is not the same as learning, nor is it the same as repair: for the carrier-learning branch of C3, current updates, subsequent invocation, and task results are checked under §4.5; the historical-increment branch `C3-learning/CM-LEARNING-history` additionally requires updates that can be retained, repeated rounds, and G3's historical conditional increments (see §6.3); repair additionally requires K*/F* and N/O review. U07 is not applicable to a one-way process with no return channel.

### 3.5.8 U08 Conditions and Environment {#section-3-5-8}

The environment and conditions enter explanation only when they change an object's states or transitions through detectable interfaces. A condition is a local prerequisite for a mechanism to hold in the current instance; the environment is the set of variables left outside the current boundary that may affect the object through interfaces. The environment is not a personified overall cause, nor does it determine every outcome. Changes of scale redraw the object–environment boundary, so the relevant environmental variables and interfaces through which effects occur must be declared again. For a model that is explicitly closed and has no external channel, this primitive may be marked not applicable.

### 3.5.9 U09 Load, Capacity, and Recovery Margin {#section-3-5-9}

In nonequilibrium systems with sustained flux, maintenance requirements, or recovery requirements, load must be described together with finite capacity and recovery margin. Load is demand of the same type at a given position and within a given window; capacity is the range of what can be taken up in the same type or through an explicit conversion mapping; recovery margin is the room still available after a disturbance for replenishment, reorganization, or a return to target K/F. Units, distributions, windows, and bottleneck positions must be declared for all three. An instantaneous shortfall does not automatically amount to cumulative damage, nor does overload create an obligation to continue carrying. An object with neither sustained nonequilibrium nor maintenance requirements may be marked not applicable.

### 3.5.10 U10 Trace, Memory, and Paths {#section-3-5-10}

A trace is a durable record that a prior change leaves in a state, relation, boundary, interface, transition constraint, or environment. A trace counts as structural memory only when it enters subsequent transitions. Historical-increment path differences are registered under G3 only when a historical term changes future paths, probabilities, or conversion costs after controlling for the currently registered state. General historical effects transmitted by measured current carriers are tested separately under §4.5. Retaining a trace is not the same as G3 holding, nor is a path difference the same as fate or irreparability. Trace carriers and durability thresholds can change with scale; U10 is not applicable to static classifications with no temporal extension.

### 3.5.11 U11 Phase, Transition, and Dissolution {#section-3-5-11}

A phase is a conditional range of operation under the same K, distinguished by pre-registered variables and criteria; a transition is a detectable change between ranges beyond noise and sensitivity to binning; dissolution means only that the original K no longer holds. The basic phase pattern does not require path dependence; a causal claim about a specified trigger separately requires G2. Sustained effects or delayed recovery transmitted through current carriers require separate evidence under §4.5; G3 is additionally required only when a historical conditional increment beyond the current representation is claimed. A phase is not a maturity ranking of S0–S6, nor a stage that every object must pass through. If K has already ceased to hold before a transition, the classification should be changed to object conversion or dissolution.

## 3.6 Combining Primitives and Purpose-Relative Closure {#section-3-6}

U01–U03 answer “what is currently treated as a candidate object, and how is it seen”; U04–U06 answer “what realizes the structure, and through what is change transmitted”; U07–U10 answer “how a return updates states, how conditions act on an object, how load is distributed, and how history leaves effects”; U11 answers “when it is still the same range of operation, and when there is transition, conversion, or dissolution.”

These primitives serve as interfaces for one another, not as proofs of one another. Every missing field must be marked unknown, not applicable, unobservable, or withheld for protection, with an account of how that state affects the ceiling on conclusions. The familiarity of natural language must not be used to fill in missing contract fields, nor may the existence of a primitive be directly upgraded to a stage, value, responsibility, choice, or authorization.
