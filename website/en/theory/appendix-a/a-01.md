# A.1 HV01 Structural Domain (Full Interface Card) {#section-a-1}

A. Identity, Proposition, and Scope

| Field | What to Record |
| --- | --- |
| Interface ID (`id`) | HV01 |
| Qualified ID (`qualified_id`) | `human_variable:HV01` |
| Name (`name`) | Structural Domain |
| Claim type (`claim_type`) | H |
| Contract role (`contract_role`) | `human_variable_interface` |
| Proposition (`proposition`) | D0 declares only a candidate human object. Register a limited effective structural domain within the instance’s scope only if a pre-registered G1-instance shows that the candidate grouping achieves an out-of-sample or extrapolation gain above the threshold on the preselected outcome relative to a matched N0. |
| Scope (`scope`) | Relationships, teams, organizations, institutions, and public issues |
| Conditions for suspension (`pause_condition`) | The object, boundary, scale, time window, or basis for treating it as the same object is insufficient for the selected route. When formal G1 support is sought, the corresponding null model or instance contract is incomplete |

| Protocol dependencies (`protocol_requires`) | 1. E1<br>2. EVIDENCE<br>3. SOURCE |
| Qualification/specialization (`specializes`) | None (empty set) |
| References to applicable objects (`applies_to`) | None (empty set) |
| Conditional support routes (`conditional_support_routes`) | 1. route&#95;id=HV01-R0-candidate-object;<br>claim&#95;level=candidate&#95;description;<br>when=The D0 object contract is complete, but there is not yet an eligible G1-instance with result&#95;state=supported;<br>additional&#95;inferential&#95;requires=None (empty set);<br>additional&#95;protocol&#95;requires=None (empty set);<br>allowed&#95;conclusion=Register a candidate human object, the set of materials, boundary disputes, and the need for further G1 evidence;<br>result&#95;ceiling=Candidate object description only. Do not draw conclusions about the object’s ultimate nature, a unified will, or authorization. |
| Permitted inferences (`allowed_inference`) | 1. R0 may register a candidate object, boundary disputes, and limited descriptive references<br>2. Register only the limited effective structural domain supported by the gain, and the strength of support for the grouping gain, within the G1-instance’s pre-registered object, scale, window, outcome, and extrapolation unit |
| Prohibited leaps (`prohibited_leap`) | 1. Inferring an objective community from naming it. 2. Inferring a common will from shared circumstances |

C. Nine-Axis Scale and Object Contract

| Field | What to Record |
| --- | --- |
| Nine-axis scale profile (`scale_profile`) | SP=&lt;A,X,T,O,C,R,I,N,J&gt;. A=Aggregation level covers relational or event units, the candidate member population, distributions inside and outside the boundary, and grouping rules. X=Spatial extent covers common locations, organizational boundaries, digital platforms, and external environments across domains. T=Time span covers the identification window, cycles of membership change, and boundary history. O=Organizational level covers roles, teams, organizations, institutions, and governance ecologies. C=Causal level covers originating events, interaction mechanisms, meso-level relational structures, and institutional and systemic conditions. R=Resolution covers original interactions, event sequences, individual member cases, boundary distributions, metrics, and summaries. Record compression loss as well. I=Scope of influence covers direct members, people excluded, people indirectly affected, second-order spillovers, and positions across domains and generations. N=Network topology scope covers membership relations, boundary connections, isolated points, and bridging across domains. J=Scope of jurisdiction and authorization requires separate authorization records for naming the object, adopting the boundary, and subsequent action. For an inapplicable axis, record the reason for `not_applicable` |
| Effective object (`effective_object`) | A candidate object declared by D0. Register it as a limited effective structural domain within the instance’s scope only if the pre-registered G1-instance passes the threshold test relative to a matched N0 |
| Scale invariants (`scale_invariants`) | 1. Object contract. 2. Participating and affected positions |
| Required additions for scale elevation (`required_scale_additions`) | 1. Units and population<br>2. Representativeness<br>3. J axis<br>4. Positions with low visibility |
| What changes with scale (`changing_semantics`) | 1. Effective membership, relationships, and what counts as the same object can change with scale |
| Inapplicable objects (`non_applicable_objects`) | 1. Nonhuman systems without intent, institutions, or interfaces for responsibility |
| Prohibited elevations (`forbidden_elevation`) | 1. Treating a local group as directly representative of all affected people |

D. State, Evidence, and Variable Flows

| Field | What to Record |
| --- | --- |
| State set (`state`) | 1. Candidate. 2. Identifiable. 3. Boundary disputed. 4. Does not hold |
| Observables (`observables`) | 1. Differences in relationship density and constraints inside and outside the boundary<br>2. Records of members entering, exiting, or being excluded<br>3. Repeated co-occurrence of common problems, resource channels, or institutional rules<br>4. Whether the grouping gain remains stable after changing the grouping rule |
| Evidence requirements (`evidence`) | 1. D0 candidate object and records used to determine whether it remains the same object<br>2. The G1-instance pre-registration and matched N0<br>3. Training results and out-of-sample or extrapolation results<br>4. Comparison of gains for the candidate and competing groupings |
| Input dependencies and interface content (`input_dependencies`) | 1. D0 provides only candidate object fields and does not establish the structure<br>2. Pre-registered G1-instance, matched N0, threshold, model class, and sample or extrapolation unit<br>3. Observation positions, competing groupings, and the E1 protocol |
| Output effects and variable flows (`output_effects`) | 1. R0 supplies the other variables with a candidate object reference, boundary, time window, and uncertainty. R1 additionally supplies the limited effective scope supported by G1<br>2. Preserve grounds for both the object’s existence and domain facts separately from grouping gains |
| Time window and lag (`time_window_and_lag`) | Register the identification window, boundary changes, and lags in membership changes |
| Uncertainty (`uncertainty`) | Record boundary disputes, absent members, and observation coverage |
| Local exclusion zone (`local_exclusion_zone`) | The aggregate must not represent positions where people cannot express themselves safely or that were not sampled |
| Affected positions (`affected_positions`) | 1. Members. 2. People excluded. 3. Cost bearers outside the boundary |

E. Uptake, Responsibility, Normative Status, Ceilings, and Correction

| Field | What to Record |
| --- | --- |
| Uptake carriers (`carrier`) | 1. Relationship network. 2. Organizational boundary. 3. Institutional records |
| Responsible parties (`responsible_subject`) | 1. The analyst who proposes the structural domain judgment<br>2. The decision maker who uses the judgment |
| Normative status (`normative_status`) | A descriptive H-World interface. It confers no normative justification |
| Judgment ceiling (`judgment_ceiling`) | A limited effective structural domain at the level of explanation may be registered only if the G1-instance passes, and only for the pre-registered object, scale, window, outcome, and extrapolation unit. Otherwise no support from a grouping gain is registered, while the candidate object reference and object facts with separate grounds are retained as usual |
| Action ceiling (`action_ceiling`) | This variable produces only descriptions of candidate structural domains, boundary disputes, and needs for more evidence. It does not authorize inclusion, exclusion, or action. Any real-world adjustment separately requires C12, explicit N premises at runtime, J authorization, and O procedures |
| Counterexamples (`counterexamples`) | 1. People repeatedly present in the same place lack stable relationships or common constraints<br>2. A group defined by the analyst disappears as soon as the grouping rule changes |
| Appeal (`appeal`) | Under `appeal_and_rollback_rule`, members and people at affected positions can challenge the boundary, representativeness, and the object’s identity criterion through a safe, accessible channel with anti-retaliation protection. This triggers review independent of the original naming or decision chain |
| Rollback (`rollback`) | Under `appeal_and_rollback_rule`, once rollback is authorized, the designated responsible party must within the stated deadline actually revoke the structural domain registration, remove its effect on the scope of downstream objects, and return it to a candidate grouping. Object facts with separate grounds are not revoked along with it. Preserve versions and verification of completion |
