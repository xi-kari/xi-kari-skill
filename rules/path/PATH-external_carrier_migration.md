# 向可承接系统迁移

派生使用卡。读取者：M2 状态判断、M5 推演、M6 条件前瞻与反方审查者；调用前读完 anchors 所列完整原文小节。

## 适用对象

- 用于修复受阻时人员、能力、资源、关系或证据转移的可行性检查；先核接收能力与不能退出者。〔派生，待确认〕

## 触发观察

- 核查原文判据「无接收能力、浪漫化离开或把伤害私有化，不构成安全迁移。」。〔原文 §8.4〕

## 生成的路径

- 比较有保护的实际迁移、部分载体转移、迁移失败和原地保护；每个载体分别核实去向与权限。〔派生，待确认〕

## 时钟与时延

- 比较伤害窗口与查明、授权、资源筹集、转移及接收起效总时延；宣布通道不等于来得及。〔派生，待确认〕

## 早期信号

- 接收方实际提供岗位、存储、资金或保护接口，转移者可试验访问且停止与回滚渠道明确。〔派生，待确认〕

## 反向信号

- 接收承诺无资源、路途或数据转移引入更高风险、弱势位置无法退出时否决安全迁移表述。〔派生，待确认〕

## 竞争解释

- functional_transfer 聚焦功能，休眠可能保留原位置，X0 另有全面责任条件；不能以任一标签代替保护检查。〔派生，待确认〕

## 不能推出的结论

- 不能要求个体自行逃离来承担组织义务，不能将迁移计划写成已完成的安全。〔派生，待确认〕
