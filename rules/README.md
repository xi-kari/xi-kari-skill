# 派生规则库

读取者：M2、M3、M5、M6 的使用者与反方审查者。38 张卡将原文合同变成检索和比较步骤，不是定义来源，也不构成对象证据。原文为唯一理论权威；版本、完整小节和卡片短引共同用于核对，不能以读卡替代读锚点原文。

每张卡由 JSON 兼容 YAML 头部和八个固定正文段组成：适用对象、触发观察、生成的路径、时钟与时延、早期信号、反向信号、竞争解释、不能推出的结论。`index.json` 的 `rules` 项逐字段对应卡头，`file` 给出仓库相对路径。

- `〔原文 §x〕` 只标精确短引；引号中的文字可在所列完整小节定位。
- `〔派生，待确认〕` 是将原文合同用于检索和观察的操作建议，不称理论定义或作者经验。
- 全部卡当前为 `draft`。作者完成具体审定后，只有其明确覆盖的条目才能标 `〔作者确认〕`，状态改变须有真实依据；`retired` 表示退出使用。
- 卡头 `theory_sha256` 与原文 manifest 绑定；原文变更按锚点差异复核，不因散列变化一律废弃，也不自动沿用。

## 使用顺序

依 §6.14，先按对象域和已观察变化检索，保留状态未知；S0—S6 只用于人类有意图集体，X0 是生命周期路径。读取入选卡的完整锚点小节，逐项核对使能条件与对象证据，再把 `competes_with` 所列卡一并拉入比较。竞争卡不必全部适用，不适用须说明对象、条件或证据原因；不得只呈现主路径。

`draft` 卡可作为实验中的检索和推演辅助。使用时说明“按派生规则”，在答案中列出实际使用的 draft 卡及其未知；卡名、模型一致和本地检查通过均不提升理论或经验支持。结果只支持候选时，保留候选，不为形成清楚结论补造使能条件。
